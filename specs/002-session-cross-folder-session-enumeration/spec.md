# Feature Specification: セッション列挙 (R-2)

**Feature Branch**: `002-session-cross-folder-session-enumeration`

**Created**: 2026-09-16

**Status**: frontmatter の `status:` を正とする

**Input**: User description: "[session] 登録フォルダを横断して Claude Code のセッション一覧を取得する。WSL ディストロ内の config ディレクトリを Windows 側から列挙できること。読み取り専用で、起動は行わない。"

## 本 feature の位置づけ

R-2 は M1「読める」の 2 番目の feature であり、**`session` domain の最初の feature** である。
R-1 の US-1〜US-3 の出力 — `RuntimeDescriptor`、実行中確認済みの値、登録済み作業フォルダ、
パス API と接頭辞照合、単一 capability の IPC — を入力として受け取る
([docs/roadmap.md](../../docs/roadmap.md) の「R-2 の依存は R-1 の全体ではない」)。

**本 feature は読み取り専用である。** セッションを起動せず、改名せず、削除せず、
config ディレクトリに書き込まない。起動は X-1、transcript の描画は R-3 が担う。

`session` charter の Journey 1「過去セッションを横断して探す」に対応する。
Closta の出発点にある課題「並行して走らせたセッションの所在が分からない」に
最初に答える feature であるため、**登録していないフォルダのセッションも落とさない**。

**本 spec は「何を満たすか」を定める。** 列挙を行う実行単位の形、config ディレクトリの探索手順、
キャッシュの実装手段といった実装方式は [plan.md](plan.md) / [tasks.md](tasks.md) とコードで決める。

## User Scenarios & Testing _(mandatory)_

### User Story 1 - 登録フォルダを横断してセッションを一覧する (Priority: P1)

セッション一覧を開くと、登録済みの作業フォルダごとに、そのフォルダで過去に走った
Claude Code のセッションが並ぶ。Windows 側のフォルダと WSL ディストロ内のフォルダが
**同じ画面に並び**、所在の違いはラベルで分かる。

**Why this priority**: `session` charter の Journey 1 そのものであり、charter KPI
「列挙の網羅」の測定対象。R-3 (transcript 表示) / R-4 (Tier A tool 表示) の入力であり、
M1「読める」の完了判定がここを通る。

**Independent Test**: 実データを持つ開発ホスト (WSL ディストロ内に数百のセッション履歴) で
一覧を開き、同じ config ディレクトリを対象に SDK を直接呼んで得た識別子集合と突き合わせる。
セッションの起動を伴わずに検証できる。

**Acceptance Scenarios**:

1. **Given** 所在 `windows` の登録フォルダにセッション履歴がある、**When** 一覧を開く、
   **Then** そのフォルダの配下にセッションが並び、各行に要約・最終更新時刻・識別子が示される
2. **Given** 所在 `wsl:<D>` (実行中) の登録フォルダに履歴がある、**When** 一覧を開く、
   **Then** **ディストロを起動せずに** Windows 側から列挙され、同じ画面に並ぶ
3. **Given** 同じパスのフォルダが 2 つのディストロに存在し、両方を登録している、**When** 一覧を開く、
   **Then** 所在ごとに別のグループとして現れ、セッションが混ざらない
4. **Given** 所在 `windows` の登録フォルダを、あるディストロから `/mnt/c/...` として使ったセッションがある、
   **When** 一覧を開く、**Then** そのセッションは**当該登録フォルダの配下に現れ**、
   **越境である旨が示される** (所在が違うことだけを理由に未登録扱いにしない)
5. **Given** ホスト側の履歴に、作業ディレクトリが **UNC 形式 (`\\wsl.localhost\<D>\...`) で
   記録されたセッション**がある、**When** 一覧を開く、
   **Then** ディストロ `<D>` の登録フォルダの配下に現れる (UNC 形式は所在を特定できる)
6. **Given** ホスト側の履歴に、作業ディレクトリが **POSIX 形式で記録されたセッション**がある、
   **When** 一覧を開く、**Then** **所在を推測せず「所在不明」として示される** —
   同じ `/home/y/p` が複数のディストロに存在しうるため、どれかに帰属させてはならない
7. **Given** 所在の変換材料 (`PathMapping`) がまだ取得できていない、**When** 一覧を開く、
   **Then** その所在のセッションは**「対応づけ保留」として示され**、未登録と区別される
8. **Given** UNC 形式の作業ディレクトリが指すディストロが検出済みの集合に無い、**When** 一覧を開く、
   **Then** 「未検出の所在」として示され、**所在不明と区別される**
9. **Given** セッションが 0 件の登録フォルダ、**When** 一覧を開く、
   **Then** 「このフォルダにはまだ履歴がない」ことと次の操作への導線が示され、空白の行にならない
10. **Given** 一覧を開いたあと、アプリ外の `claude` で新しいセッションが作られた、
    **When** 利用者が再取得を実行する、**Then** 新しいセッションが現れ、削除されたものは消える
11. **Given** 同じ起動中に一度取得済み、**When** 再度一覧を開く、**Then** 再走査されず即座に表示される
12. **Given** 要約が空 / タイトル未設定のセッション、**When** 表示する、
    **Then** 最初のプロンプト、それも無ければ識別子と時刻が代替として示され、**空欄にならない**
13. **Given** 要約・フォルダ名に日本語・絵文字・非 ASCII を含む、**When** 表示する、
    **Then** 文字化けや切れなく表示される
14. **Given** git worktree 由来のセッションと SDK / daemon 由来 (programmatic) のセッションが混ざる、
    **When** 一覧を開く、**Then** それぞれが**区別可能に**示される (黙って同じものとして数えない)
15. **Given** 取得から時間が経った一覧、**When** 表示する、**Then** **取得時刻が示される**
    (正本はアプリ外にあり、いつの状態かが分からなければ判断できない)

### User Story 2 - 未登録フォルダのセッションを見つける (Priority: P1)

config ディレクトリには、登録していないフォルダで走ったセッションも残っている。
一覧はそれらを **作業ディレクトリごとにまとめた「未登録フォルダ」**として示し、
その場で作業フォルダとして登録する導線を添える。

**Why this priority**: 「並行して走らせたセッションの所在が分からない」という課題に
直接答える部分である。登録済みフォルダだけを出すと、**登録していないフォルダのセッションは
アプリから見て存在しないことになる** — 探す手段がないから登録できず、登録していないから
見つからない、という循環に落ちる。

**Independent Test**: 登録フォルダ 1 件と、未登録の作業ディレクトリ 2 件分のセッションを持つ
config ディレクトリをスタブで与え、3 グループに分かれることと総数が保たれることを確認する。

**Acceptance Scenarios**:

1. **Given** 登録フォルダに対応しないセッション群、**When** 一覧を開く、
   **Then** 作業ディレクトリごとにまとめられ、**「未登録」であることが示される**
2. **Given** 未登録グループ、**When** 登録の導線を選ぶ、**Then** その作業ディレクトリと所在が
   初期値として R-1 の登録操作に渡る。**アプリが黙って登録しない**
3. **Given** 未登録グループの作業ディレクトリ、**When** 一覧を表示する、
   **Then** **実在確認は行われない** (任意パスの存在を問い合わせる経路を作らない)。
   実在の判定は登録操作の側で行われる
4. **Given** 作業ディレクトリが記録されていないセッション、および所在を特定できないセッション、
   **When** 一覧を開く、**Then** いずれも「作業フォルダ不明」として別のグループに現れ、
   **捨てられない**。**両者は理由が区別して示される** (記録がない / 所在が分からない)
5. **Given** 未登録グループが多数 (数十〜数百) ある、**When** 一覧を開く、
   **Then** 既定では畳まれており、登録フォルダの一覧が押し流されない
6. **Given** 未登録の作業ディレクトリが登録された、**When** 再取得する、
   **Then** そのグループが登録フォルダのグループへ移る

### User Story 3 - 列挙できない所在を理由つきに知る (Priority: P1)

停止中のディストロ、WSL サービスの停止、config ディレクトリの不在、権限不足 —
列挙が成立しない所在について、**失敗は所在ごとに閉じ**、理由と次の操作が示される。

**Why this priority**: 停止中ディストロ内のセッションは **R-2 では原理的に列挙できない**
(`session` charter の KPI に明記。R-1 が「検出のためにディストロを起動しない」と決めたためである)。
黙って 0 件にすると「セッションが消えた」に見え、正本がアプリ外にあること (Principle X) と
合わせて利用者の信頼を直接損なう。**列挙できないことを列挙する**必要がある。

**Independent Test**: プロセス起動レイヤとファイルアクセスレイヤを差し替え、
停止中 / WSL 不在 / config 不在 / 権限拒否 / 途中停止 の各条件を与えて、
成功した所在の結果が失われないことを確認する。

**Acceptance Scenarios**:

1. **Given** 所在ディストロが停止中、**When** 一覧を開く、
   **Then** その所在は「停止中のため未列挙」と示され、起動と再検出の導線が添えられる。
   **アプリはディストロを起動しない**
2. **Given** 停止中の所在の識別子で列挙を直接要求する、**When** 受け付ける、**Then** 拒否される
3. **Given** WSL が利用できないホスト、**When** 一覧を開く、
   **Then** Windows 側の列挙だけが成功し、例外が発生せず、WSL が使えない旨が示される
4. **Given** ディストロ内に config ディレクトリが存在しない (そのディストロで Claude Code を使っていない)、
   **When** 一覧を開く、**Then** 「この所在には履歴がない」と示され、**失敗と区別される**
5. **Given** 読み取り権限がない / パス長が上限を超える、**When** 列挙する、
   **Then** 所在ごとの失敗として理由つきに示され、他の所在の一覧は失われない
6. **Given** 列挙中に所在ディストロが停止した、**When** 結果を受け取る、
   **Then** 部分結果と失敗理由の**双方**が示される
7. **Given** 複数の所在のうち 1 つが失敗した、**When** 一覧を表示する、
   **Then** 成功した所在の一覧が**そのまま表示される** (全体を失敗にしない)
8. **Given** すべての所在が未列挙、**When** 一覧を開く、
   **Then** 空白の画面にせず、所在ごとの理由と次の操作が示される

### User Story 4 - 件数が多くても目的のセッションに辿れる (Priority: P2)

実データでは 1 つの config ディレクトリに数百のセッションが残る。一覧は最終更新の新しい順に並び、
所在とフォルダで絞り込め、全件の取得完了を待たずに先頭から読める。

**Why this priority**: 網羅性 (US-1 / US-2) を満たしたうえで**使えるかどうか**を決める。
ただし網羅性が満たされていなければ絞り込みは意味を持たないため P2 とする。

**Independent Test**: 多件数のスタブ (700 件規模) を与え、先頭の描画と追加取得、
並べ替えと絞り込みを確認する。実機を要しない。

**Acceptance Scenarios**:

1. **Given** 数百件のセッション、**When** 一覧を開く、
   **Then** 先頭の一定件数が先に描画され、**全件の取得完了を待たされない**
2. **Given** 先頭が描画された状態、**When** 続きを要求する、**Then** 追加分が取得されて連結される
3. **Given** 一覧、**When** 並び順を確認する、**Then** 既定は最終更新の新しい順である
4. **Given** 一覧、**When** 所在またはフォルダで絞り込む、**Then** 該当のみが残る
5. **Given** 絞り込み結果が 0 件、**When** 表示する、**Then** 空状態と絞り込み解除の導線が示される
6. **Given** 追加取得の途中で所在が失敗した、**When** 表示する、
   **Then** 取得済みの分は保たれ、失敗が理由つきに示される

### Edge Cases

- 停止中ディストロ / WSL サービス停止 / WSL 未インストール — 所在ごとの未列挙として扱う
- ディストロ内に config ディレクトリが無い / `projects` が無い / 空 — 失敗ではなく「履歴なし」
- ディストロ内に config ディレクトリの候補が**複数ある** (複数ユーザ、`root` のみ) —
  どれか 1 つを勝手に選ばない
- **ホーム配下に `.claude` を持たないユーザが混ざる** (実測: `linuxbrew`)
- **読み取り権限のないホームが候補に含まれる** (実測: `/root` は UNC 経由で Access denied)
- **1 つの config ディレクトリに 3 形式の作業ディレクトリが混在する**
  (実測: ホスト側 43 件のうち Windows 形式 30 / POSIX 形式 6 / UNC 形式 7)
- UNC 形式の作業ディレクトリが**未検出・改名後のディストロ**を指す
- worktree の作業ディレクトリが登録フォルダ配下の `.claude/worktrees/<name>` にある (実測で存在)
- config ディレクトリ配下に壊れた JSONL / 0 バイトのファイル / `.jsonl` 以外が混ざる
- 1 つのセッションファイルが数十 MB ある — 一覧のために全文を読まない
- UNC 経由のパスが Windows の長さ制限を超える / 読み取り権限がない
- 列挙中にディストロが停止する / ファイルが削除される / 追記される
- セッションの作業ディレクトリが**当該ディストロの Windows マウント配下**にある
  (`/mnt/c/...`) — 所在 `windows` の登録フォルダに対応づき、**越境**として扱う
- 作業ディレクトリが記録されていない / 相対パス / 既に削除されている
- 所在が同じで**互いに前方一致する**登録フォルダが複数ある — 最長一致に対応づける
- 同一の識別子 (UUID) が 2 つの config ディレクトリに現れる (履歴のコピー)
- 要約が空 / 極端に長い / 改行や制御文字を含む
- 最終更新時刻が未来 / 0 / 欠落している
- ディストロ名が変わった・削除された — 登録フォルダの所在が解決できない (R-1 と同じ)
- 一覧を開いたままアプリ外の `claude` がセッションを追加・削除する
- 変換材料 (`PathMapping`) が未取得のまま一覧を開く — 起動直後と再検出中に必ず通る状態であり、
  例外経路として扱わない
- 空状態 — セッション 0 件 / 登録フォルダ 0 件 / 全所在が未列挙。いずれも導線を示す

## Requirements _(mandatory)_

### Functional Requirements

**番号は追加順、並びは主題順である。** design-gate round 1 の指摘で
FR-049 〜 FR-051 と SC-015 / SC-016 を追加したが、**既存番号を振り直していない** —
振り直すと data-model / contracts / tasks / quickstart の参照がすべて古くなる。
したがって group 内で番号が昇順にならない箇所がある。**重複は無い。**

#### 列挙の経路と正本

- **FR-001**: セッションの列挙は **Agent SDK の公式 API** を通して行わなければならない。
  JSONL の自前パースを行ってはならない (Principle IV /
  [AD-002](../../docs/decisions/0002-use-agent-sdk-not-cli.md) /
  [AD-007](../../docs/decisions/0007-session-source-of-truth-is-claude-code.md))
- **FR-002**: セッションの正本は Claude Code 側とし、アプリが保持するものは
  キャッシュ / インデックスとして扱わなければならない。矛盾したときは再取得結果を正とする (Principle X)
- **FR-003**: 本 feature は**読み取り専用**でなければならない。セッションの起動・再開・分岐・
  改名・タグ付け・削除、および config ディレクトリへの書き込みを行ってはならない
- **FR-004**: 列挙は**登録フォルダの有無によらず、対象 config ディレクトリ配下の全セッション**を
  対象としなければならない。登録フォルダに紐づかないセッションを落としてはならない
- **FR-005**: 列挙の I/O とパースは **main process の外**で行い、UI の応答を止めてはならない
  (Principle IX。数百ファイルの読み取りとパースは stream の逐次パースと同じ性質を持つ)
- **FR-006**: システムは WSL 内のセッション列挙および config ディレクトリ探索に
  **`wsl.exe` を使ってはならない**。WSL 内のファイル読み取りは UNC 経路で行う
  ([AD-015](../../docs/decisions/0015-wsl-access-strategy.md) §1 / §2。
  1 回あたり約 1.5 秒の固定費がかかり、所在ごと・セッションごとに呼ぶと実用にならない)
- **FR-007**: システムは**列挙のためにディストロを起動してはならない**。停止中の所在は
  「未列挙」として理由つきに提示する (R-1 の FR-007 / SC-005 と同じ拘束)
- **FR-008**: ディストロ内のファイルアクセス**および当該所在を対象とする列挙プロセスの起動**は、
  **実行中確認済みの値に対してのみ**発行しなければならない。値と対象が同じディストロを
  指すことを検証する (R-1 の `VerifiedRunning` の契約)。
  **ゲートは config ディレクトリの探索・列挙プロセスの起動・追加取得の
  すべての入口に掛ける** — 1 つでも外れると SC-002 が成立しない

#### 対象 config ディレクトリの解決

- **FR-009**: 列挙対象の config ディレクトリは**所在ごとの既定**とする。
  Windows 側はホストユーザの既定、WSL 側は当該ディストロのユーザの既定である。
  **複数 config ディレクトリの登録は本 feature に含まない** (`provider` domain / X-3)
- **FR-010**: WSL 側の config ディレクトリの探索に、**ディストロ内でのコマンド実行を要してはならない**。
  探索は UNC 経路のディレクトリ列挙で完結させる (FR-006 の帰結)
- **FR-011**: 1 つの所在に候補が複数見つかった場合、システムは**見つかったすべてを対象とし**、
  どの候補から得られたセッションかを保持しなければならない。1 つを暗黙に選んではならない
- **FR-012**: 対象 config ディレクトリが存在しない所在は、**失敗ではなく「履歴なし」**として
  扱わなければならない
- **FR-013**: システムは config ディレクトリおよびその配下を**作成・変更してはならない**
  (Principle VI / FR-003)
- **FR-014**: システムは**同一プロセス内で環境変数を書き換えて対象 config ディレクトリを
  切り替える方式を採ってはならない**。並行列挙でレースを起こす
  ([AD-021](../../docs/decisions/0021-session-store-and-enumeration.md) §3)
- **FR-015**: 対象 config ディレクトリの集合は**所在ごとに分けて保持**しなければならない。
  X-3 で Provider ごとの config ディレクトリが加わったときに、**集合を差し替えるだけで済む形**とする

#### 作業ディレクトリの名前空間の判定

- **FR-016**: セッションの作業ディレクトリの名前空間を、**由来 config ディレクトリの所在から
  推定してはならない**。値の形から分類し、**ホスト名前空間 / UNC 形式 (ディストロを特定できる) /
  POSIX 形式 (ディストロを特定できない) / 不在** の 4 通りで扱わなければならない。
  **1 つの config ディレクトリに 3 形式が同時に現れる**ことが実測で確認されている
  ([research.md](research.md) R-02)
- **FR-017**: UNC 形式の作業ディレクトリは、**埋め込まれたディストロ名で所在を特定**し、
  当該ディストロの名前空間のパスに変換して扱わなければならない。
  該当ディストロが検出済みの集合に無い場合は「**未検出の所在**」として提示する
- **FR-018**: POSIX 形式でディストロを特定できない作業ディレクトリについて、
  システムは**所在を推測してはならない** (AD-025)。ただし**由来 config ディレクトリの所在が
  `wsl:<D>` である場合は、その所在のもの**として扱う。
  ホスト側 config ディレクトリに現れた POSIX 形式は「**所在不明**」として提示する

#### 登録フォルダとの対応づけ

- **FR-019**: セッションは**作業ディレクトリと所在の組**で作業フォルダに対応づけなければならない。
  パス文字列だけで対応づけてはならない
  ([AD-025](../../docs/decisions/0025-workspace-folder-carries-location.md))
- **FR-020**: 対応づけは、登録フォルダのパスを**セッションの所在の名前空間に変換したうえで**
  照合しなければならない。**所在が異なることだけを理由に未登録扱いにしてはならない** —
  ディストロから Windows 側のフォルダを使ったセッション (`/mnt/c/...`) が未登録に落ちる
- **FR-021**: 変換と照合は `domain` が公開するパス API と接頭辞照合を経由しなければならない
  (Principle I)
- **FR-022**: 変換材料 (`PathMapping`) が無い所在について、システムは対応づけを
  **「保留」として提示し**、未登録と区別しなければならない
  (R-1 の 3 値の到達可能性と同じ分け方。2 値に潰さない)
- **FR-023**: 越境と判定された対応づけについて、システムは**越境である旨を保持**しなければならない
  ([AD-016](../../docs/decisions/0016-cross-filesystem-performance-cliff.md) / R-1 の FR-030)
- **FR-024**: 所在が同じで互いに前方一致する登録フォルダが複数あるとき、
  **最長一致**の登録フォルダに対応づけなければならない。
  ドライブレターの大小と末尾セパレータの有無で結果が変わってはならない
- **FR-025**: 登録フォルダに対応しないセッションは、**作業ディレクトリごとにまとめた
  「未登録フォルダ」**として提示しなければならない
- **FR-026**: 未登録フォルダについて、システムは**登録の導線**を提供し、作業ディレクトリと所在を
  初期値として R-1 の登録操作に渡さなければならない。**アプリが自動で登録してはならない**
- **FR-027**: 未登録の作業ディレクトリについて、システムは**実在確認を行ってはならない**
  (任意パスの存在を問い合わせる経路を作らない。R-1 の同種の判断を踏襲する)
- **FR-028**: 作業ディレクトリが**不在のセッションと所在不明のセッション**は
  「作業フォルダ不明」として保持し、一覧から落としてはならない。
  **両者は理由を区別して保持する**
- **FR-029**: システムは git worktree 由来のセッションと programmatic (SDK / daemon) 由来の
  セッションを**区別可能に**提示しなければならない。区別せずに数えてはならない
  (AD-021 の Consequences。SDK 側の既定はいずれも「含む」であり、
  実測では 269 件のうち 40 件が programmatic 由来だった)
- **FR-052**: 列挙対象が**複数の候補 (ユーザ) にまたがる場合、システムは各セッションの
  由来候補を一覧上で常時識別できるようにしなければならない** (FR-011 の帰結)。
  1 つのディストロ内の全ユーザ分を 1 画面に集約するため、
  **どのユーザの履歴を見ているかが分からない状態を作ってはならない**
- **FR-051**: **登録フォルダは、対応するセッションが 0 件であっても一覧に現れなければならない。**
  グループの生成源は (**登録フォルダ一覧** ∪ セッションから導出したグループ) である。
  セッション集合だけから導出すると、登録した直後の履歴が無いフォルダが画面から消え、
  利用者には「登録が失敗した」と区別がつかない

#### 失敗・空状態・鮮度

- **FR-030**: 列挙の失敗は**所在ごとに閉じ**、成功した所在の結果を失わせてはならない
- **FR-031**: 失敗は理由を**参照キー**として保持しなければならない。訳出は `ui` が行う。
  少なくとも 停止中 / WSL 利用不可 / config 不在 / 権限拒否 / パス長超過 / 途中停止 / その他
  を区別する
- **FR-032**: 空状態 (**登録フォルダ単位のセッション 0 件** / セッション 0 件 / 登録フォルダ 0 件 /
  全所在が未列挙 / 絞り込み結果 0 件 の **5 条件**) は空白の画面にせず、
  次の操作への導線を示さなければならない
- **FR-033**: 一覧はキャッシュし、**再取得は利用者の明示操作に限らなければならない**。
  自動ポーリングとファイル監視を行ってはならない (AD-015 §3 と同じ方針)
- **FR-034**: システムはキャッシュの**取得時刻を提示**しなければならない。
  正本はアプリ外にあり、アプリの知らないうちに変わりうる (Principle X)
- **FR-035**: 再取得の結果はキャッシュを**置き換え**なければならない。
  マージして消えたセッションを残してはならない (R-1 の検出キャッシュと同じ扱い)
- **FR-036**: 列挙結果を**ディスクに永続化してはならない**。プロセス寿命のキャッシュに限る。
  会話全文を含みうるデータの保持期限と削除経路は未定義であり (AD-007 の blocking gap)、
  本 feature で持ち込まない

#### 件数と並び

- **FR-037**: 一覧は**先頭から段階的に**提示し、全件の取得完了を待たせてはならない
- **FR-038**: システムは件数上限に達したときの**追加取得**の手段を持たなければならない
- **FR-039**: 並び順の既定は**最終更新の新しい順**とする
- **FR-040**: システムは**所在とフォルダによる絞り込み**を提供しなければならない

#### IPC と境界

- **FR-041**: 列挙結果は**データのみのプロトコル**で renderer に渡さなければならない。
  SDK のオブジェクト・コールバック・`AbortSignal` を IPC に載せてはならない
  ([AD-023](../../docs/decisions/0023-application-architecture.md) のセキュリティ要件)
- **FR-042**: **UNC 形式のパスを IPC 境界に出してはならない**。パスは所在の名前空間で表す (AD-025)。
  UNC 形式で記録されていた作業ディレクトリも、変換してから境界を越えさせる (FR-017)。
  **表示用の生値としても UNC 形式の文字列を境界に出してはならない** —
  「表示専用だから」という理由で例外を作ると、規則が文面上だけのものになる。
  変換できない値は**形の分類 (参照キー) と、所在を伴わない安全な表示用文字列**で表す
- **FR-043**: 新設する IPC メソッドは preload の**単一 capability** に追加し、
  送信元とペイロードを**すべて未信頼として検証**しなければならない
  (R-1 の FR-039 / SC-018 と同じ拘束)
- **FR-044**: 一覧の payload は **列挙 API が返すメタデータ項目に限る**。
  メッセージ列・tool 出力などの transcript 本文を**取得も転送もしてはならない**。
  ただし `summary` / `firstPrompt` / `customTitle` は **SDK の定義上「会話由来の逐語文字列」を
  含みうる** (`firstPrompt` は "First meaningful user prompt in the session.")。
  これらを「要約だから安全」と扱ってはならない — FR-049 の正規化と長さ上限の対象とする
- **FR-049**: システムは列挙結果の**会話由来文字列** (`summary` / `firstPrompt` / `customTitle` /
  `gitBranch` / `tag` / 作業ディレクトリの生値) に対し、IPC 境界を越える前に
  **バイト長上限での切り詰め**と**制御文字 (C0 / C1 / 双方向制御文字) の除去**を行い、
  **切り詰め・除去が起きたことを payload 上で示さなければならない**。
  数値 (`lastModified` / `createdAt` / `fileSize`) は**有限の安全整数**であることを検証し、
  満たさない値は「不明」として扱う (**行は落とさない**)。
  config ディレクトリの内容は**アプリ外のプロセスが書いた未信頼入力**である
- **FR-050**: 列挙プロセスに与える環境変数は**明示した許可リストのみ**とし、
  親プロセスの環境を**継承してはならない** (Principle V。
  X-3 で Provider の資格情報が入ったときに流れ込む経路を最初から作らない)
- **FR-045**: 列挙を行う実行単位は **Electron API とネイティブモジュールに依存してはならない**
  (Principle VII / [AD-010](../../docs/decisions/0010-supervisor-runs-standalone.md))

#### 用語と表示

- **FR-046**: UI のラベル・メッセージは**日本語を第一言語**とし、内部識別子をそのまま
  提示してはならない (R-1 の FR-047 を踏襲)
- **FR-047**: セッション行は**要約が空のときも識別可能**でなければならない。
  最初のプロンプト → 識別子と時刻 の順に代替を用いる
- **FR-048**: 本 feature で導入・変更する用語を [docs/glossary.md](../../docs/glossary.md) に
  反映しなければならない (Principle XIV)

### Key Entities

- **SessionSummary (セッション要約行)**: 識別子・要約・最終更新時刻・作成時刻・作業ディレクトリ・
  git ブランチ・タグ・由来 (対話 / programmatic / worktree)・由来 config ディレクトリ。
  **transcript の本文を含まない**
- **CwdOrigin (作業ディレクトリの出自)**: 作業ディレクトリの値から判定した名前空間と所在。
  **ホスト / `wsl:<D>` (UNC 形式から特定) / `wsl:<D>` (由来 config の所在から継承) /
  所在不明 / 不在** を区別する。**由来 config ディレクトリの所在と一致するとは限らない**
- **EnumerationTarget (列挙対象)**: 所在と、その所在における config ディレクトリのパス
  (所在の名前空間で表す)。X-3 で Provider 由来のものが加わる
- **SessionGroup**: セッションのまとまり。**4 種**ある —
  登録フォルダ / 対応づけ保留 / 未登録の作業ディレクトリ / 作業フォルダ不明。
  保留と未登録を同じものにしない
- **FolderMatch (対応づけの結果)**: セッションと登録フォルダの対応。
  一致した登録フォルダ・越境か否か・変換の可否
- **EnumerationOutcome (所在ごとの成否)**: 所在・成功か失敗か・理由キー・取得時刻・件数・
  打ち切りの有無
- **SessionIndex**: 全所在の `EnumerationOutcome` と `SessionGroup` を束ねたキャッシュ。
  **プロセス寿命**であり永続化しない

## Success Criteria _(mandatory)_

- **SC-001**: 実行中の所在について、対象 config ディレクトリ配下のセッションを**取りこぼさない**。
  一覧の識別子集合が、同じ config ディレクトリを対象に SDK を直接呼んで得た集合と**一致**する。
  数百件規模の実データを含む (`session` charter KPI「列挙の網羅」。計測経路: Vitest + quickstart)
- **SC-002**: 列挙・config ディレクトリ探索・対応づけのいずれにおいても、
  **アプリが停止中のディストロに対して起動を伴う操作を発行することが 0 件**である。
  計測経路: **プロセス起動レイヤとファイルアクセスレイヤを差し替えた Vitest** で、
  `running` でない所在に対する UNC アクセスの発行・列挙プロセスの起動が **0 回**であることを
  assert する (**発行側の行為で定義する** — 確認から操作までの窓は消せないため。R-1 の SC-005 と同じ)。
  `wsl -l -v` の前後比較は**補助的な回帰確認**として quickstart で行い、主たる判定根拠にしない —
  停止中ディストロへの UNC アクセスが起動を引き起こすかを測っていない以上
  ([research.md](research.md) R-08)、実行状態が不変でも発行 0 件は導けない
- **SC-003**: 列挙と config ディレクトリ探索のために `wsl.exe` を起動した回数が **0 件**。
  計測経路: プロセス起動レイヤを差し替えた Vitest + 検証スクリプトでの呼び出し形の走査
- **SC-004**: **読み取り専用であること**が示される。列挙の前後で対象 config ディレクトリ配下の
  ファイル一覧・更新時刻・内容ハッシュが**変化しない**。
  **[contracts/session-enumeration.md](contracts/session-enumeration.md) C-4 の 2 つの表
  (副作用禁止 / R-2 で呼んではならない読み取り API) の各行**について、呼び出し形が **0 件**。
  **API 名を SC 側で部分列挙しない** — 列挙すると表に足された行が拘束を外れる (SC-010 と同じ理由)。
  計測経路: 前後比較 + 検証スクリプトでの呼び出し形の走査
- **SC-005**: 作業ディレクトリの出自判定と対応づけが**全パターンで正しい**。
  **ホスト形式 / UNC 形式 (ディストロ特定) / UNC 形式で未検出のディストロ /
  POSIX 形式 (由来 config が `wsl:<D>`) / POSIX 形式 (由来 config がホスト → 所在不明) /
  不在** の 6 出自と、**所在が同じ直接一致 / 越境経路での一致 (`/mnt/c/...` ↔ 所在 `windows`) /
  前方一致する登録フォルダの共存 (最長一致) / 小文字ドライブレターと末尾セパレータ /
  同じパスが 2 ディストロにある / 変換材料が無い所在 (保留) / 未登録** を含む。
  計測経路: 出自判定関数と対応づけ関数のユニットテスト (表の全セルを網羅する)
- **SC-006**: セッションが**1 件も落ちない**。対象 config ディレクトリから得た総数と、
  4 種のグループの件数の合計が**一致**する。計測経路: Vitest
- **SC-007**: 所在ごとの失敗が封じ込められる。1 つの所在が失敗しても他の所在の一覧が
  **欠落 0 件**で表示され、例外が **0 件**である。停止中 / WSL 不在 / config 不在 /
  権限拒否 / パス長超過 / 途中停止 の各条件を含む
  (計測経路: ファイルアクセスとプロセス起動を差し替えた Vitest + renderer 単体テスト)
- **SC-008**: 一覧の**先頭 50 件の描画が 2 秒以内**、**1 所在あたり 700 件規模の全件取得完了が
  10 秒以内**、**キャッシュヒット時の再表示が 100 ミリ秒以内**である。
  計測経路: 開発ビルドが出力する計測ログの値で判定する (R-1 の SC-004 と同じ方式)
- **SC-009**: 日本語・絵文字・非 ASCII を含む要約・フォルダ名・ディストロ名が
  文字化けや切れなく **UI 上でそのまま表示される**。要約が空・改行・制御文字を含む場合も
  行が識別可能である (計測経路: Vitest のフィクスチャ + quickstart)
- **SC-010**: **IPC の未信頼入力検証表の各行**について、不正入力が拒否されることが示される。
  行を 3 つだけ列挙する形にしない — 列挙すると同じ構造の残りが拘束を外れる。
  計測経路: preload をスタブせず main 側ハンドラを直接呼ぶユニットテスト。
  最低でも 送信元不一致 / 未検出 descriptor の所在 / 停止中の所在 /
  未登録の作業ディレクトリを登録済み識別子として渡す / UNC 値を所在のパスとして渡す /
  既知でないセッション識別子 を含む
- **SC-011**: 一覧の payload が **列挙 API のメタデータ項目だけ**で構成される。
  `getSessionMessages` / `getSubagentMessages` / `listSubagents` / `getSessionInfo` の
  呼び出しが **0 件**であり、**`SessionSummaryDTO` と `SessionGroupDTO` の各 variant** の
  フィールド集合が**許可リストと完全一致**する (項目が増えたら落ちる形にする)。
  **表示用の生値を運ぶフィールドは `cwdDisplay` の 1 種類に限り、UNC 接頭辞を含まない**。
  計測経路: 呼び出し形の走査 + DTO のスキーマ検証
- **SC-015**: **会話由来文字列の正規化が効いている** (FR-049)。
  制御文字・双方向制御文字を含む値、バイト長上限を超える値、`NaN` / `Infinity` / 負の時刻を
  与えたとき、payload 側で除去・切り詰め・「不明」への変換が行われ、**行が落ちない**。
  計測経路: 正規化関数のユニットテスト (境界値を全数) + DTO のサイズ上限検査
- **SC-016**: 列挙プロセスに渡す環境変数のキー集合が**許可リストと完全一致**する (FR-050)。
  許可リスト外のキーが **0 件**。計測経路: `env` を組み立てる純粋関数のユニットテスト
  (**プロセスを実際に起こさずに測れる形に分離する**)
- **SC-012**: 再取得でキャッシュが**置き換わる**。アプリ外で作られたセッションが現れ、
  削除されたセッションが消え、**取得時刻が更新される** (計測経路: Vitest + quickstart)
- **SC-013**: 空状態がいずれも導線つきで描画される。**登録フォルダ単位のセッション 0 件** /
  セッション 0 件 / 登録フォルダ 0 件 / 全所在が未列挙 / 絞り込み結果 0 件 の **5 条件**すべてで、
  空白の画面が **0 件**である。
  加えて**登録フォルダ 3 件 / セッション 0 件のとき `folder` グループが 3 件現れる** (FR-051)
  (計測経路: グループ化関数のユニットテスト + renderer 単体テスト)
- **SC-014**: 列挙結果が**ディスクに書かれない**。アプリの設定ディレクトリに
  セッション由来のデータが残る件数が **0 件** (計測経路: 前後のファイル一覧の比較)

## Assumptions

`[USER]` は起案時に人間が確定したもの、`[ASSUMED]` は本 spec で自動採用したもの。

- **[USER]** 登録フォルダに紐づかないセッションも**全件列挙**し、「未登録フォルダ」として示す
- **[USER]** 列挙対象の config ディレクトリは**所在ごとの既定のみ**。
  複数 config ディレクトリの登録は X-3 に残す
- **[USER]** 本 feature は**一覧とメタデータまで**。transcript 本文の取得は R-3 で追加する
- **[USER]** セッション一覧は **assistant-ui の thread-list 系 element を土台**にする
  ([AD-025](../../docs/decisions/0025-workspace-folder-carries-location.md) の申し送り / Principle XIII)。
  4 種のグループと所在ごとの失敗行は element のモデルに無いため、
  primitive を直接組んで表す (element の grouping / search は使わない)
- **[USER]** **E2E / CI 基盤は本 feature に含めない。M4 完了後に再検討する。**
  `session` charter KPI の「計測経路: E2E」と
  [AD-024](../../docs/decisions/0024-constitution-verification-paths.md) #18 の
  「(A) / (B) は R-2 の E2E 基盤に相乗りする」は R-2 を名指しているが、
  **本 feature では満たさない**。SC-001 は Vitest + quickstart で測る。
  R-2 は読み取り専用であり composer の送信経路を開けないため、AD-024 (A) の発動条件
  (`isDisabled: true` を外す変更) にも該当しない
- **[ASSUMED]** WSL 側の既定 config ディレクトリは各ユーザのホーム配下の `.claude` とし、
  ホームの所在は UNC 経路の浅いディレクトリ列挙で求める (AD-015 の実測で 22 ミリ秒)
- **[USER]** 複数ユーザ分が見つかった場合は**すべて対象とし、由来を保持する** (FR-011)。
  **露出面の評価** (design-gate round 1 の security 指摘に対する人間判断):
  本 feature は 1 つのディストロ内の全ユーザの会話要約・逐語プロンプト・作業ディレクトリ・
  git ブランチを読み取り、1 つの一覧に集約する。**権限境界は越えていない** —
  UNC 経由で読めるファイルは Windows 利用者が既に読めるものであり、
  実測でも `/root` は Access denied で弾かれた。したがって権限昇格ではない。
  ただし **OS の ACL が許すだけで、アプリが能動的に他人の会話を収集・集約・表示する**形になり、
  ホスト側を「ホストユーザ 1 名分」に絞っているのと**非対称**である。
  この非対称を受け入れる理由は、**WSL 側は既定ユーザを特定する手段が無い**ことである
  (R-1 は保持しておらず、`wsl.exe` は FR-006 で禁止。Windows レジストリの `DefaultUid` か
  UNC 経由の `/etc/wsl.conf` を読む工程が追加で必要になる)。
  **代償として FR-052 で由来ユーザの常時表示を要求し、
  I-1 (ミラー) へ「他ユーザ由来のセッションはミラー対象外」を申し送る** —
  FR-036 により本 feature ではディスクに残らないため、実害は表示に留まる
- **[ASSUMED]** 列挙結果はプロセス寿命のキャッシュに限り、ディスクに永続化しない。
  AD-007 の未解決事項 (ミラーの保持期限・削除経路) を本 feature に持ち込まない
- **[ASSUMED]** 自動更新 (ポーリング / ファイル監視) は行わない。再取得は利用者の明示操作に限る
- **[ASSUMED]** worktree 由来と programmatic 由来は**取得したうえで区別する**。
  SDK の既定 (いずれも含む) に合わせて取り、落とすかどうかは表示側の絞り込みで扱う
- **[ASSUMED]** 未登録の作業ディレクトリの実在確認は行わない (R-1 の同種の判断を踏襲)
- **[ASSUMED]** 同一プロセス内での環境変数の書き換えによる切り替えは採らない (AD-021 §3)。
  具体的な実行単位の形は plan で決める
- **[ASSUMED]** SDK が計算する transcript ディレクトリ名 (`encoded-cwd`) を
  **アプリ側で再現しない**。作業ディレクトリはセッションのメタデータから読む
- **[ASSUMED]** POSIX 形式の作業ディレクトリは、由来 config ディレクトリの所在が `wsl:<D>` なら
  その所在のものとして扱う。**ホスト側 config ディレクトリに現れた POSIX 形式は所在不明**とする。
  同じ `/home/y/p` が複数のディストロに存在しうるため、いずれかに帰属させると誤対応が生まれる
- **[ASSUMED]** 実測値 (ホスト 43 件 / ディストロ 269 件 / JSONL 844 件 / 最大 25 MB /
  programmatic 由来 40 件) は開発ホスト 1 台のものであり、一般性は未確認
- **[ASSUMED]** SC-008 の予算は開発ホスト 1 台の実測に基づく。他ホストでの一般性は未確認
  (AD-015 の Open Question と同じ留保)
- **[ASSUMED]** SC-008 の**全件取得の予算は 700 件規模で測れていない**。
  開発ホストの最大所在は 277 件であり (UNC 経由で 7,282 ms)、
  1 件あたり約 23.6 ms の外挿では **700 件で約 17 秒**となって予算を超える。
  **実測値が予算内であることと SC-008 を満たすことは別である** —
  700 件規模の config ディレクトリを用意して測るまで、この予算は未検証のままとする
  (実測は `quickstart-results.md` の「SH-074」節)
- **[ASSUMED]** 本 feature の UI は R-1 の 3 画面に「セッション一覧」を 1 画面加える形とする
- **[ASSUMED]** セッションの識別子 (UUID) は表示に使ってよいが、要約の代替としてのみ用いる
- **[ASSUMED]** Windows 側の既定 config ディレクトリはホストユーザ 1 名分とする

## Out of Scope

- セッションの**起動**・応答のストリーミング・中断 → `session` (X-1)
- **transcript 本文の取得と描画** → R-3 (`ui`)。本 feature は一覧とメタデータまで
- Tier A tool の表示 → R-4 (`ui`)
- セッションの改名・タグ付け・削除・分岐 (`forkSession`) → 本 feature は読み取り専用。X-1 以降
- **Provider の登録と複数 config ディレクトリ**、認証方式・環境変数の導出 → `provider` (X-3)。
  本 feature は所在ごとの既定 1 系統に限る
- 実行中セッションの状態管理 (idle / running / awaiting_permission / error) と監視ビュー →
  `session` (O-1)。本 feature は**過去セッションの静的な一覧**である
- `sessionStore` ミラーと SQLite、コンテナ内セッションの列挙 → `isolation` (I-1)
- **停止中ディストロ内のセッションの列挙** → **非目標**。R-1 の SC-005 と
  `session` charter KPI により原理的に成立しない
- transcript ミラーの保持期限・削除経路 (AD-007 の blocking gap) → 本 feature は永続化しないため
  発生しない。I-1 で決める
- Thread 検索と observability → `ui` (O-3)
- 仮想スクロール等の大規模件数向け描画最適化 → 必要になった時点で O-1 / O-3
- **E2E 基盤 (CI で Electron を起動する仕組み) とスクリーンショット比較** → **M4 完了後**に再検討
  (`[USER]` 確定)。charter KPI と AD-024 #18 の R-2 名指しは本 feature では満たさない
- セッションの選択に応じた transcript の読み込み → R-3。
  本 feature は**選択状態の配線まで**を持ち、読み込みは行わない
- ディストロ内の `claude` 実行パスの解決 → X-1
- 越境時の実測ベンチマークと閾値判定 → R-1 と同じく持たない
