# Quickstart: 起動設定の残りの軸 (024)

**Date**: 2026-10-29 (`/cl-plan`) | **Spec**: [spec.md](./spec.md) (SC-009 / 「合否の扱い」)

実機での確認の手順。結果は `quickstart-results.md` に V-n ごとに書く。行えなかった V-n は「未実施」と書いてマージし、roadmap の X-6 の行に未確認の項目として残す (spec の「合否の扱い」)。実機で通らなかったときは利用者に返す。

## V-0 準備

- 本番ビルド (`docs/discovery.md` の "Build / Test / Lint" 表のパッケージの行) を起動する
- WSL のランタイムに WSL のフォルダを 2 つ (`app` / `lib`)、Win32 のランタイムに Windows のフォルダを 2 つ (`app-win` / `lib-win`) 登録する。どちらかのフォルダ名に日本語と空白を含める (例 `共通 lib`)
- 各 `lib` に `NOTE.md` を置き、1 行の合言葉を書く

## V-1 追加ディレクトリ (WSL / Win32)

1. 作業フォルダ `app`、追加ディレクトリ `lib` で起動する (`default`)
2. 「lib の NOTE.md の合言葉を教えて」と頼む。合言葉が返ることを確かめ、読み取りに承認カードが出たかを記録する (research R-14。出ても起動は成り立つ)
3. 「lib に TODO.md を作って」と頼む。書き込みは承認カードを経ることを確かめる (spec US-1 AC2。権限モードの規則のまま)
4. 概要のタブに「追加ディレクトリ: lib」が出ることを確かめる
5. Win32 でも `app-win` / `lib-win` で 1〜4 を行う。日本語と空白を含むパスで読めることを確かめる (`--add-dir` の argv の経路。research R-01)
6. WSL のランタイムで Windows のフォルダを追加ディレクトリに選び、越境の警告が出ることを確かめる (US-1 AC4)
7. WSL のフォルダを追加ディレクトリに選んでからランタイムを Win32 にし、項目が外れて通知が出ることを確かめる (US-1 AC3)

## V-2 ターン数の上限 (WSL / Win32)

1. ターン数の上限 1 で起動し、「README を読んで要約して」と頼む
2. O-4 の理由「ターン数の上限に達したため止まりました。」が出て止まることを確かめる (SC-009)
3. 続けて次のプロンプトを送ったときの振る舞い (続くか・同じ理由で止まるか) を記録する (spec Edge Cases。research R-14)

## V-3 起動のときの名前 (WSL / Win32)

1. 名前「ログインの API 修正」で起動する。最初のプロンプトの前から稼働中の行と中央のヘッダに名前が出ることを確かめる
2. 1 ターン話して終了し、過去の区画に同じ名前が文字化けせずに出ることを確かめる (023 RK-06 に当たれば利用者に返す)
3. 稼働中の行から「再開」を開き、名前の軸が出ないことを確かめる (US-4 AC4)
4. 名前を付けた起動を会話の id の前に失敗させ (例: Provider の鍵を外す)、「やり直す」で名前が戻ることを確かめる (US-4 AC6)

## V-4 費用の上限

1. 費用の上限 0.01 で起動し、1 ターン話す
2. O-4 の理由「費用の上限に達したため止まりました。」が出るか、1 ターン目では止まらずに次で止まるかを記録する (費用は結果の後に判定される)

## V-5 プリセットと再開

1. 追加ディレクトリ `lib`・費用の上限 5・名前を入れてプリセットに保存し、ダイアログを閉じて開き直して適用する。追加ディレクトリと上限は戻り、名前は空であることを確かめる (US-4 AC1)
2. `lib` の登録を解除してから同じプリセットを適用し、項目が外れて通知が出ることを確かめる (US-4 AC2)
3. 本 feature の前のビルドで保存した `presets.json` (版 1) を置いてアプリを起動し、プリセットが読めることを確かめる (US-4 AC3)
4. V-2 で止まったセッションを稼働中の行から再開し、ターン数の上限の初期値が 1 であること、引き上げて続けられることを確かめる (US-4 AC4)。再開の前のターンを上限に数えるかを記録する (research R-14)

## V-6 記録しないこと

1. V-1〜V-5 の後に `launch-usage.json` を開き、起動元の 2 つの回数のほかのキーが無いことを確かめる (FR-014)
2. main のログに名前と追加ディレクトリのパスが出ていないことを確かめる (FR-007)
