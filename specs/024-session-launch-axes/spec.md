# Feature Specification: 起動設定の残りの軸 — 追加ディレクトリ・上限・セッション名 (X-6 の 2 本目)

**Feature Branch**: `024-session-launch-axes`

**Created**: 2026-10-29 (夜間の自走で起案。人間の判断が要る点は推奨案で仮採用した — 下の「判断の一覧」)

**Status**: frontmatter の `status:` を正とする

**Input**: roadmap「M2 の後続」の X-6 の行 (範囲と義務の正本)。X-6 の行のうち 023 で扱わなかった項目の 1 つ目 — `SessionLaunchConfig` の残りの軸 (追加ディレクトリ / 上限 / セッション名) を、起動の画面とプリセットで選べるようにする (U-1)。依存の X-5 と、023 (X-6 の 1 本目)・X-9 (021) は main にマージ済み。

## Summary

起動ダイアログで選べる軸を 6 から 9 に増やす。今は作業フォルダの外のディレクトリを Claude に見せる手段が無く、暴走したセッションを止める上限も無く、名前は起動の後に付け直すしかない (023)。

- **追加ディレクトリ**: 登録済みの作業フォルダから選び、作業フォルダのほかに Claude が扱えるディレクトリとして渡す (SDK の `additionalDirectories`)。パスは入力させない (U-2)
- **上限**: ターン数 (`maxTurns`) と費用 (`maxBudgetUsd`) の上限を任意で付ける。達したときの表示は O-4 のものを使う (U-4 / U-5)
- **セッション名**: 起動のときに名前を付ける (SDK の `title`)。名前は 023 の改名と同じ欄に出る (U-6)
- **プリセットと再開**: プリセットは追加ディレクトリと上限を持ち、名前は持たない (U-7)。X-9 の再開では新しい軸を選び直せる軸として扱う (U-8)

## 本 feature の位置づけ

- **session の feature で、domain (起動設定の形と依存解決)・main (検証・起動ゲート・registry・プリセットの store)・agents (query の options)・renderer (起動ダイアログ・プリセット・概要のタブ) に触れる** (targets は both)。`QUERY_OPTION_KEYS` を 12 から 16 に増やす (AD-064)
- **権限モードは安全 3 値のまま。** 追加ディレクトリは扱える範囲を広げるが、権限モード・承認の経路 (`canUseTool`)・tool の集合を変えない。書き込みは今どおり権限モードと承認で決まる (追加ディレクトリの skill が `allowed-tools` で省く承認を除く。U-11)
- **パスを renderer で組み立てない。** 追加ディレクトリはフォルダの id で選ぶので、AD-041 (h) が X-6 に預けた「パスの入力を renderer に足す」(`tests/rule-fixtures/expected.mjs` の `ui-path-concat`) は生じない (U-2)
- **Principle X のまま。** 名前の正本は Claude Code の transcript (custom-title)。Closta は起動の名前を registry (メモリ) に持つだけで、永続化しない

## User Scenarios & Testing

### User Story 1 - 作業フォルダの外のディレクトリを Claude に扱わせて起動できる (Priority: P1)

利用者はアプリのリポジトリを作業フォルダにし、隣の共通ライブラリのリポジトリ (登録済み) を追加ディレクトリに選んで起動する。Claude は両方のファイルを読める。

**Why this priority**: 複数リポジトリにまたがる作業は日常にあり、今は作業フォルダを親ディレクトリに広げるしかない (扱える範囲が必要以上に広がる)。

**Independent Test**: 2 つの登録フォルダを持つ WSL のランタイムで、片方を作業フォルダ、もう片方を追加ディレクトリにして起動し、もう片方のファイルを読ませる。ランタイムを Win32 に切り替えると WSL のフォルダの追加ディレクトリが外れて通知されることを確かめる。

**Acceptance Scenarios**:

1. **Given** 起動ダイアログで作業フォルダとランタイムを選んだ、**When** 「追加ディレクトリ」の「フォルダを追加」を押す、**Then** 選択肢は登録済みのフォルダから作業フォルダ自身と選択済みを除いたもので、パスの入力欄は無い
2. **Given** 追加ディレクトリを 1 つ以上選んだ、**When** 起動する、**Then** そのフォルダのランタイムのパスが `additionalDirectories` に載り、Claude はそこのファイルを扱える (書き込みは今どおり権限モードと承認で決まる)
3. **Given** WSL のフォルダを追加ディレクトリに選んだ、**When** ランタイムを別のディストロか Win32 に切り替える、**Then** その項目は外れ、理由が軸の reset の通知に出る。起動は止まらない
4. **Given** WSL のランタイムで Windows のフォルダを追加ディレクトリに選んだ、**When** ダイアログを見る、**Then** 作業フォルダと同じ越境の警告が出る
5. **Given** 追加ディレクトリが 10 個、**When** さらに足そうとする、**Then** 「フォルダを追加」は押せない
6. **Given** renderer から未登録の folder id・作業フォルダ自身・重複・11 個以上を送った (改ざん)、**When** main が受ける、**Then** 起動は拒否され、`query()` は呼ばれない

---

### User Story 2 - ターン数と費用の上限を付けて起動できる (Priority: P1)

利用者は試しの作業を「費用 2 USD まで」「ターン 30 まで」と上限を付けて起動し、思わぬ長いループで費用が膨らまないようにする。

**Why this priority**: 10 本を並べて回すと 1 本ずつは見ていられない。上限は止める手段を起動の前に持たせる。

**Independent Test**: ターン数の上限を 1 にして起動し、tool を使う依頼を送って、上限で止まり O-4 の理由 (「ターン数の上限に達したため止まりました。」) が出ることを確かめる。

**Acceptance Scenarios**:

1. **Given** 起動ダイアログ、**When** 上限の軸を見る、**Then** 「ターン数の上限」と「費用の上限 (USD)」があり、既定はどちらも「上限なし」
2. **Given** 上限を付けて起動した、**When** 上限に達する、**Then** O-4 の理由の表示が出る (U-5)
3. **Given** 上限を付けずに起動した、**When** query の options を見る、**Then** `maxTurns` / `maxBudgetUsd` のキーは載っていない
4. **Given** ターン数に 0・小数・1001、費用に 0・負・1000.01・小数 3 桁を入れた、**When** 起動しようとする、**Then** 起動は押せず、範囲の文言が出る
5. **Given** renderer から範囲外・NaN・Infinity・文字列の上限を送った (改ざん)、**When** main と agents が受ける、**Then** どちらかで拒否され、`query()` は呼ばれない
6. **Given** 上限 (と名前) を付けた起動が拒否された・失敗した、または「やり直す」を押した、**When** 起動ダイアログが前回の起動設定 (`lastConfig`) から開き直る、**Then** 「ターン数の上限」「費用の上限 (USD)」の入力欄には前回の値が入っており (黙って「上限なし」に戻らない)、名前の入力欄にも前回の名前が入る (data-model §9.2.1)

### User Story 3 - 起動のときにセッションに名前を付けられる (Priority: P2)

利用者は起動ダイアログで「ログインの API 修正」と名前を入れて起動し、最初のプロンプトを送る前から稼働中の行で見分ける。

**Why this priority**: 023 の改名は会話の id が決まって応答を待っている間しか使えない。起動の前に決めた名前を最初から出す。

**Independent Test**: 名前を入れて起動し、稼働中の行と中央のヘッダに名前が出ることと、セッションを終えた後に過去の区画に同じ名前が出ることを確かめる。

**Acceptance Scenarios**:

1. **Given** 起動ダイアログで名前を入れた、**When** 起動に成功する、**Then** 稼働中の行と中央のヘッダにその名前が出る
2. **Given** 上で起動したセッションで 1 ターン話した、**When** 終了して過去の区画を見る、**Then** 行に同じ名前が出る
3. **Given** 名前を空のまま起動した、**When** 稼働中の行を見る、**Then** 今どおり (自動の題) で、`title` のキーは載っていない
4. **Given** 名前が 100 文字を超える・改行を含む、**When** 起動しようとする、**Then** 起動は押せず、023 と同じ制限の文言が出る
5. **Given** 起動のときに名前を付けたセッション、**When** 023 の「名前を変更」で変える、**Then** 新しい名前が出る

### User Story 4 - プリセットと再開で新しい軸を引き継げる (Priority: P2)

利用者は「共通ライブラリ付き・費用 5 USD まで」をプリセットにして毎日使う。止まったセッションを X-9 で再開するとき、上限を引き上げて続ける。

**Why this priority**: 新しい軸を起動のたびに選び直すと、プリセットの再利用 (O-3 の KPI) が下がる。再開で上限を変えられないと、上限で止まったセッションを続けられない。

**Independent Test**: 追加ディレクトリと上限を持つプリセットを保存して適用し、値が戻ることと名前が戻らないことを確かめる。稼働中の行から再開し、上限の初期値が元の値で、名前の軸が出ないことを確かめる。

**Acceptance Scenarios**:

1. **Given** 追加ディレクトリ・上限・名前を選んだダイアログ、**When** プリセットに保存して後で適用する、**Then** 追加ディレクトリと上限は戻り、名前は空のまま
2. **Given** 追加ディレクトリを含むプリセット、**When** そのフォルダの登録を解除してから適用する、**Then** その項目は外れ、通知が出る (US-1 AC3 と同じ)
3. **Given** 版 1 の `presets.json` (本 spec の前に保存した)、**When** アプリを起動する、**Then** プリセットは読め、新しい軸は既定 (追加ディレクトリなし・上限なし)
4. **Given** 上限を付けて起動した稼働中の行、**When** 「再開」を開く、**Then** 追加ディレクトリと上限の初期値は元の起動設定の値で、選び直せる。名前の軸は出ない
5. **Given** 過去の区画の行、**When** 「再開」を開く、**Then** 追加ディレクトリと上限は既定で、選び直せる
6. **Given** 名前を付けて起動し、会話の id の前に失敗した行、**When** 「やり直す」を押す、**Then** 名前を含めて元の起動設定が初期値になる

### Edge Cases

- 追加ディレクトリと作業フォルダが入れ子 (片方がもう片方の下) — 許す (Claude Code の扱いに任せる)。同じフォルダの id の重複だけを拒否する
- プリセットを適用したら作業フォルダが追加ディレクトリの 1 つと同じになった — その項目を外し、通知する
- 起動の後に追加ディレクトリのフォルダの登録を解除した — 動いているセッションは変わらない (起動の値のまま)。概要のタブは起動の値を出す
- 費用の上限は Claude Code の計算した費用 (`total_cost_usd`) で判定される。Provider によっては定価での概算で、請求と一致しない (O-4 の費用の表示と同じ注意)
- 再開のセッションの費用の上限が、再開の前の費用を含むか — SDK の扱いに任せる (Assumptions)。概要のタブには起動の値を出すだけ
- 上限で止まった後に利用者が次のプロンプトを送った — 今の結果の分類と状態の遷移のまま (U-5)。quickstart で振る舞いを記録する
- 日本語・空白を含む追加ディレクトリのパスが WSL の起動の引数 (`--add-dir`) を通る — 割れないことを quickstart で確かめる (Assumptions)。名前は起動の引数を通らない (stdin の初期化の要求で届く。plan「設計後の見直し」1)
- Closta の外で同じ会話の名前を変えた — 023 の Edge Cases のまま (last-wins)

## Requirements

### Functional Requirements

#### 追加ディレクトリ (US-1)

- **FR-001**: 起動ダイアログに「追加ディレクトリ」の軸を足し、登録済みのフォルダから 0〜10 個を選べなければならない (作業フォルダ自身と重複は選べない)。renderer は folder id だけを持ち・送り、パスの値を組み立てない・入力させない (U-2)
- **FR-002**: 依存解決 (`resolveLaunchAxes`) は、追加ディレクトリの各項目に作業フォルダと同じ「フォルダ ↔ ランタイム」の判定を通し、通らない項目・登録が解除された項目・作業フォルダと同じになった項目を外して軸の reset として通知しなければならない。起動は止めない。越境する項目には作業フォルダと同じ警告 (AD-016) を出す (U-3)
- **FR-003**: main は起動ゲートで FR-002 を再評価し、外れる項目が 1 つでもあれば起動を `invalid-config` で拒否しなければならない (main は黙って外さない。renderer は FR-002 で既に外しているので、ここに来るのは改ざんか、ダイアログの後の登録解除・ランタイムの変化)。全件が通れば、各 folder id を選択ランタイム (`RuntimeDescriptor`。WSL は自分の PathMapping を持つ) に対する `resolveFolderRuntime` で選択ランタイムのパスに変換して agents に渡す。変換できない項目 (到達できない・変換の材料が無い・名前空間が違う) があれば同じく `invalid-config` で拒否する。agents は件数・ランタイムの種類 (WSL / Win32) に合う絶対パスの形・制御文字なしを再検査し、外れれば throw する。0 件なら `additionalDirectories` のキーを載せない

#### 上限 (US-2)

- **FR-004**: 起動ダイアログに「ターン数の上限」(1〜1000 の整数) と「費用の上限 (USD)」(0.01〜1000、小数 2 桁まで) を足さなければならない。どちらも既定は「上限なし」で、そのときは `maxTurns` / `maxBudgetUsd` のキーを載せない (U-4)
- **FR-005**: 上限の値は、main の検証 (形) と agents の `buildQueryOptions` の assert の 2 段で範囲を確かめ、範囲外・有限でない数・数でない値を拒否しなければならない
- **FR-006**: 上限に達したときの表示は O-4 の失敗の理由 (`max-turns` / `max-budget`) を使い、結果の分類と状態の遷移を変えてはならない (U-5)

#### セッション名 (US-3)

- **FR-007**: 起動ダイアログに「セッション名」の任意の軸を足し、023 FR-009 と同じ制限で検証しなければならない (main と agents の 2 段)。空なら名前なしで `title` のキーを載せない。値があれば `title` で渡す。名前をログに出さない
- **FR-008**: 起動に成功したら、main は registry の行の名前 (023 FR-012 の欄) を起動の名前で初めから持ち、稼働中の行と中央のヘッダに出さなければならない。以後の 023 の改名はこの値を上書きする

#### プリセット (US-4)

- **FR-009**: プリセットは追加ディレクトリ (folder id) と上限を保存し、適用は依存解決 (FR-002) に通さなければならない (X-4 FR-011 の「適用は起動しない」のまま)
- **FR-010**: プリセットはセッション名を保存してはならない。適用しても名前の入力を変えない (U-7)
- **FR-011**: `presets.json` の版を 2 に上げ、版 1 のプリセットを新しい軸の既定 (追加ディレクトリなし・上限なし) として読まなければならない。書き出しは版 2。IPC (`checkPreset`) と永続層 (`preset-record`) は同じ述語を使う (write/read 対称)。将来版の扱いは今の store の規則のまま (U-7)

#### 再開・表示・記録

- **FR-012**: X-9 の再開の形のダイアログでは、追加ディレクトリと上限を選び直せる軸として出し、初期値を稼働中の行からは元の起動設定の値、過去の行からは既定にしなければならない (021 FR-006 / FR-007 を新しい軸に広げる)。セッション名の軸は出さず、`title` を渡さない。「やり直す」(021 FR-009) は名前を含めて元の起動設定を初期値にする (U-8)
- **FR-013**: 右のペインの「概要」のタブに、起動時の追加ディレクトリ (フォルダの表示名) と上限 (無ければ「上限なし」) を出さなければならない。値は起動の値で、実行中に変わらない
- **FR-014**: 新しい軸を `launch-usage.json` に記録してはならない (U-9)。023 FR-014 (実行中の変更を書き戻さない) を継ぐ
- **FR-015**: AD-041 (g) の読み替え・`QUERY_OPTION_KEYS` に 4 キーを足すこと (12 → 16)・`SessionLaunchConfig` の形を広げることは ADR (AD-064) に書き、`session-core.test.ts` の pin テスト・`LAUNCH_CONFIG_KEYS` と `isValidLaunchConfig`・`resume.ts` の「6 軸」の記述を同じ PR で直さなければならない
- **FR-016**: `tests/rule-fixtures/expected.mjs` の `ui-path-concat` の `howToClose` に 024 の確認の結果 (追加ディレクトリはフォルダの id で選び、パスの入力を足さない) を書かなければならない。`nextFeature` の付け替え先は plan で決める
- **FR-017**: session charter の Related Specs / Related ADRs、glossary の SessionLaunchConfig (「前 6 軸」と「X-6 が扱う」の記述)・Launch axis (軸の数)・Resume / Resume dialog (選び直せる軸)・LaunchInput (`options` の中身) と Concurrency limit / 023 の名前の項の Counterexamples、charter の Key concepts のプリセット (型は `PresetLaunchConfig`) を直し (一覧の正本は data-model §10)、完了の PR で roadmap の X-6 の行に 024 の結論を書かなければならない (Principle XII / XIV)

### Key Entities

- **起動設定 (`SessionLaunchConfig`) の新しい軸**: 追加ディレクトリ (folder id の並び。0〜10)・ターン数の上限 (整数か null)・費用の上限 (数か null)・セッション名 (文字列か null)。名前を `SessionLaunchConfig` に入れるか、起動の要求の別の欄にするか (プリセットに入らない値をどう分けるか) は plan で決める
- **プリセット (版 2)**: 版 1 の 6 軸に追加ディレクトリと上限を足したもの。名前を含まない
- **稼働中の行の registry**: 023 の名前の欄を、起動の名前で初期化する。メモリにだけ持つ

## Assumptions

- `additionalDirectories` は WSL のランタイムではディストロの POSIX のパス、Win32 のランタイムでは Windows のパスで効く (作業フォルダと同じ変換で足りる)。実機で quickstart で確かめる
- `--add-dir` のディレクトリから Claude Code が読み込むのは `.claude/skills/` (と、環境変数で有効にしたときの CLAUDE.md) で、`.claude/settings.json` の hooks・permissions は読み込まれない (Claude Code の文書。research R-02)。登録フォルダの設定として受け入れる (U-10)。読み込まれるものは quickstart V-1 で実機に記録する
- `maxTurns` / `maxBudgetUsd` はストリーミング入力のセッション (Closta の起動の形) で効く。数え方 (プロンプトごとか、セッションを通してか・再開の前の費用を含むか) は SDK の扱いに任せ、quickstart で記録する。表示は「上限」とだけ言い、数え方を約束しない
- `title` は SDK が stdin の初期化の要求 (control request) で渡し、起動の引数を通らない (sdk.mjs。plan「設計後の見直し」1)。起動の引数を通るのは `--add-dir` / `--max-turns` / `--max-budget-usd` で、日本語・空白を含む追加ディレクトリのパスが WSL の起動 (`wsl.exe --exec`) と Win32 の直接の起動で割れないことを実機で quickstart で確かめる
- 上限に達した結果は既存の分類 (`error_max_turns` / `error_max_budget_usd`) で届く (sdk.d.ts の `SDKResultError`)

- `taskBudget`・`maxThinkingTokens`・実行中の上限の変更 (U-4)
- 登録していないディレクトリを追加ディレクトリにすること・パスの入力 (U-2)
- 退避ファイルの UI・`.bak` の重複抑止・claudePath の形の判定・settings store の是正・プロンプトキューの上限の通知・/clear の後の会話の id・Worker の異常終了の孤児の観測 — X-6 の後続の分割
