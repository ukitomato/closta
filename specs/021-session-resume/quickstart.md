# Quickstart: セッションの再開 (X-9)

**Spec**: [spec.md](./spec.md) | **Data model**: [data-model.md](./data-model.md)

実機の確かめの手順。結果は `quickstart-results.md` (`/cl-done` の前に作る) に V ごとに書く。合否の扱いは spec の「合否の扱い」が正本: **マージの条件は V-8 (自動の検証) だけ**。V-1 (SC-001)・V-2 (SC-007)・V-9 (SC-009) は**実機の確認の条件**で、行えるならローカルで行い、行えないときは `quickstart-results.md` に「未実施」と書いてマージし (2026-10-21 夜間の規則)、roadmap の X-9 の行に未確認の項目として残して利用者の実機に送る。

検証のコマンドは `docs/discovery.md` の "Build / Test / Lint" 表の agent 用の列 (`node` で直接呼ぶ形)。

## V-0 前提

- 本番ビルド (`docs/discovery.md` の build) で起動する
- WSL: 実行中のディストロ 1 つ・そこに登録した作業フォルダ・`claude` が見つかる
- Win32: `C:\dev\closta` を作業フォルダに登録・`Win32Runtime` の claude の状態が `found`
- 起動ダイアログで Provider なし (既定の config ディレクトリ) を選べる

## V-1 6 通りの再開 (SC-001・実機の確認の条件)

WSL と Win32 のそれぞれで、次の 3 通りを行う (計 6 通り)。各回、最初のターンで「合言葉は <ランダムな単語> です」と送り、再開した後に「合言葉は何でしたか」と送る。

| # | 止め方 | 再開の元 |
|---|---|---|
| a | 「終了」で終わらせ、過去の区画を再取得する | 過去の区画の行 → 中央の帯の「再開」 |
| b | 「終了」で終わらせる | 稼働中の区画の終了済みの行の「再開」 |
| c | 外から `claude` を止める (WSL: `wsl -d <D> -- pkill -f claude`、Win32: タスクマネージャーで `claude.exe` を終了) | 稼働中の区画の失敗した行の「再開」 |

各回で記録する:

1. 再開の形のダイアログで、フォルダ / ランタイム / Provider が表示だけで変えられないこと (US-3 AC1)。b / c ではモデル / effort / 権限モードの初期値が元の値であること (US-3 AC2)
2. 「再開する」で新しい行が起きて選ばれ、b / c では元の行が消えること (US-2 AC1)
3. 中央にそれまでの会話と「ここから再開」の区切りが出ること (US-4 AC1)
4. `claude` が合言葉を答えること (US-1 AC3)
5. config ディレクトリの `projects/<符号化した cwd>/` に新しい `.jsonl` が増えず、元の `<会話の id>.jsonl` に追記されたこと (更新時刻と行数)

## V-2 Win32 の記録と表示 (SC-007・実機の確認の条件。020 V-7 の引き継ぎ)

1. Win32 のセッションで tool を 1 回以上使うターン (例: 「README.md の 1 行目を読んで」) を行い、終了する
2. 過去の区画を再取得し、その会話が `C:\dev\closta` のフォルダの区画に出ることを確かめる (出なければ research R-14 / plan RK-06 として利用者に返す)
3. 過去ログで読めることを確かめる
4. そこから再開し、中央のそれまでの会話の tool の表示が過去ログと同じ (結果のある tool は結果つき、結果の無い tool は「結果不明」) であることを確かめる
5. それまでの会話の部分に承認・編集の操作が出ないことを確かめる (US-4 AC2)

## V-3 会話の id が同じであること (R-02)

V-1 の b のあと、main のログに `[session] conversation-id-changed` が出ていないことを確かめる (`resume` の `init` の `session_id` が要求の id と同じ)。出ていたら research R-02 の前提が崩れているので利用者に返す。

## V-4 会話が見つからない再開 (R-07)

1. 1 ターン話した WSL のセッションを終了する (稼働中の区画に終了済みの行が残る)
2. その会話の `.jsonl` を別の場所に移す
3. 行の「再開」から再開し、最初のプロンプトを送る
4. 行が失敗になり、理由が「再開できませんでした」であることを記録する (`process-crashed` のまま・失敗にならず「終了済み」なら data-model §6.4 の条件が実際の終わり方と合っていない)。`claude` がどの時点で終わったか (プロンプトの前か後か) も記録する
5. `.jsonl` を戻して同じ行の「再開」から再開でき、続きを話せることを確かめる

## V-5 同じ会話の 2 本目と上限 (U-5 / US-1 AC6)

1. 過去の行から再開し、最初のプロンプトを送る前に、同じ過去の行の「再開」をもう 1 回押す → 再開のダイアログで「再開する」を押すと、新しい行を起こさずに動いている行が選ばれること
2. 10 本を動かした状態で過去の行を再開し、`session-limit` で拒否され、元の行 (稼働中の行からのときは元の行) が残ること

## V-6 拒否の理由 (US-1 AC4 / US-3 AC5)

1. 登録していない作業ディレクトリの過去の行を選ぶ → 「再開」が押せず、理由と「作業フォルダとして登録」が出ること
2. 登録フォルダの下のディレクトリで動かした会話 (例: `src` で `claude` を起動した会話) の過去の行を選ぶ → `cwd-mismatch` の理由が出ること
2b. ホストの config ディレクトリにある UNC の cwd (`\\wsl$\…`) の過去の行 (該当する記録があるときだけ) を選ぶ → `location-mismatch` の理由が出ること (spec FR-005)
3. 稼働中の区画の終了済みの行の元の Provider を削除してから再開する → 起動ゲートの理由で拒否され、元の行が残ること

## V-7 記録する事項 (合否に数えない)

- `/clear` の後に終了して再開すると、`/clear` の前の会話が再開されるか (spec Edge Cases。X-6 の申し送り)
- 再開で SDK が過去のメッセージ (`SDKUserMessageReplay`) を stream に流すか (spec Assumptions)
- WSL の別のユーザのホームの過去の行を再開したときの終わり方 (research R-05 / plan RK-05。該当する環境があるときだけ)

## V-8 自動の検証 (SC-002〜SC-006 / SC-008・SC-007 / SC-009 の自動の部分。マージの条件)

`docs/discovery.md` の verify (typecheck・lint・test・Constitution 検証・rule fixtures) が通ること。

## V-9 昇格の権限モードで作った会話の再開 (SC-009・実機の確認の条件。research R-01)

1. WSL の端末で、登録した作業フォルダに入り、`claude --permission-mode acceptEdits` で 1 ターン話して終わる (ファイルの編集を伴わない問いでよい)
2. Closta で過去の区画を再取得し、その会話の行から、権限モード「default」を選んで再開する
3. 「README.md の末尾に 1 行足して」のようなファイルの編集を求め、承認のカードが出ること (編集が承認なしに行われないこと) を記録する。中央の権限モードの表示が `default` であることも記録する
4. 承認のカードで拒否し、ファイルが変わっていないことを確かめる
5. 行が最初のプロンプトの直後に `resume-failed` (「再開できませんでした」) で失敗したときは、再開の `init` が昇格のモードを報告して fail closed が効いたと記録し、research R-01 の 1 の前提 (SDK の引数のモードで起きる) が崩れているので利用者に返す。承認のカードが出ずに編集が行われたときは、前提と fail closed の両方が崩れているので利用者に返す (plan RK-10)
