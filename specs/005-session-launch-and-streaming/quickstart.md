# Quickstart (実機検証): 単一セッション起動とストリーミング (X-1)

実機依存の受け入れ確認。Vitest で測れないもの (逐次描画の体感 / 実際の中断・強制終了 /
JSONL 破損の観察) をここで人手確認し、結果を `quickstart-results.md` に記録する。
**実機操作は人間 deferred**。判定表の記録は done の必須。

前提: 実行中の WSL ディストロが 1 つ以上あり、その中で `claude` にログイン済み (既定 Provider)。
登録フォルダ (R-1) が 1 件以上ある。

| # | 手順 | 期待 (対応 SC) |
|---|---|---|
| V-1 | 登録フォルダ + 実行中の WSL ランタイムを選び、短いプロンプト (「1 から 3 まで数えて」) を送る | セッションが起動し、応答が**逐次**描画される (全完了を待たない)。SC-001 |
| V-2 | 応答中に tool 呼び出し・thinking を含むプロンプトを送る | tool は R-4 の Tier A 表示、thinking は Reasoning に流れる。日本語・絵文字が化けない。SC-001 / SC-008 |
| V-3 | tool 許可を要するプロンプト (ファイル編集等) を送る | 承認カードが出る → 「許可」で tool 実行 / 「拒否」で不実行。何の tool を何の入力で求めるか分かる。SC-004 |
| V-4 | `dontAsk` 相当 / deny ルールで聞かれず拒否される操作を起こす | 「聞かれずに拒否された」ことが対の経路で示される。SC-004 |
| V-5 | 長い応答の生成中に「中断」を押す。その後「強制終了」も試す | 中断で生成が止まり**途中出力が残る**。同一セッションで継続できる。強制終了は別ボタンで、
  警告 (保全・JSONL 非破損を保証しない) が出る。**JSONL が壊れるかを観察**して記録 (合否外)。SC-005 |
| V-6 | 停止中のディストロを選んで起動しようとする | 「停止中のため起動できない」と理由つきに示され、起動は発行されない。SC-002 / SC-010 |
| V-7 | `claude` が無いディストロで起動する | 「実行パスが解決できない」として起動失敗と区別して示される。SC-010 |
| V-8 | 生成中にウィンドウを閉じる / アプリを終了する | 実行単位 (utilityProcess) と**その孫の `wsl.exe`・WSL 内 `claude` が残らない** (タスクマネージャで孫プロセスまで確認)。SC-005 / SC-010 |
| V-9 | IME で日本語を入力し、変換確定の Enter を押す | 変換確定の Enter が**送信にならない** (SC-009)。全角混在のレイアウト目視は X-2 で確認 (本 feature 合否外) |
| V-10 | 数 MB の tool_result を含む応答を受ける | ウィンドウが固まらない (逐次描画が止まらない)。SC-003 |
| V-11 | **未ログイン / 認証切れのディストロ**で起動する | 「起動は成功したが Provider がエラー」が `provider-error` として理由つきに示され、黙って `done` にならない。再ログイン導線が出る。SC-010 (H-03) |
| V-12 | 生成中に次のプロンプトを送る → 中断する | running 中の送信が queue され、中断時に「何が残り何が消えたか」(`still_queued`/`cancelled`) が示せる。SC-005 (M-003) |

**計測ログ**: 起動〜初描画の時間を開発ビルドの計測ログに出し、`quickstart-results.md` に記録する
(合否外。AD-030 の起動費 ~2.7s を踏まえた体感の把握)。
