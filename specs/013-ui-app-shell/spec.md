# Feature Specification: アプリのシェルを目標レイアウトにする (O-7)

**Feature Branch**: `013-ui-app-shell`

**Created**: 2026-10-04 (夜間。利用者の提案「そろそろ正式な UI/UX にして、そこから改訂や追加開発していく」を受けて起案した。夜間に仮採用した判断は **2026-10-05 に利用者が推奨案どおり承認した** — 下の「判断」を参照)

**Status**: frontmatter の `status:` を正とする

**Input**: 利用者 (2026-10-04 夜): 「今のタブビューは全部廃止されて、ThreadList と Chat 画面の UI しかないアプリになるはず。そろそろ正式な UI/UX にして、そこから改訂や追加開発していくほうがよくない？」。素材は [AD-025](../../docs/decisions/0025-workspace-folder-carries-location.md) の「目標レイアウト (2026-09-15 に人間から提示)」。

## Summary

上部のタブ (ランタイム / 作業フォルダ / プロバイダ / セッション / 組み合わせ / セッション起動 / 会話) をやめ、Cursor の Agent View に近い **左のサイドバー (Thread list)・中央の Chat・右のペイン**の 3 面のアプリにする (利用者 2026-10-04: 「Cursor の AgentView のイメージが近い」)。

- **左のサイドバー**: 稼働中のセッション (O-1 の監視ビュー) と、過去のセッション (R-2 のフォルダごとの一覧) を縦に並べる。上に「新規起動」、下に「設定」を置く
- **中央**: 選んだセッションの会話。稼働中なら実行中の Chat (X-1 / X-5)、過去なら過去ログの transcript (R-3)。何も選んでいないときは空の状態で次の操作を示す
- **設定**: ランタイム / 作業フォルダ / プロバイダ / 組み合わせの 4 つの画面を、サイドバーの「設定」から開く設定のダイアログにまとめる
- **右のペイン** (AD-025 の Workspace / Panel): 表示中のセッションに付く情報をタブで切り替える面。本 feature は枠・タブを足す仕組み・畳み方と、「概要」のタブ (フォルダ・ランタイム・Provider・モデル・権限モード・ブランチ) だけを作る。M3 の後続 (O-4 の Context / Cost、O-5 の Server panel、O-6 の TodoList / Background task) と OPT-panel (Changes / Terminal / Files / Browser) はここにタブを足す

**なぜ今**: ui charter の Principle「見た目の判断を先送りしない」。AD-025 は「最初の UI 系 feature がシェルを組み替えることになる」と書いたが、担う feature が roadmap に登録されないまま M3 に来た。M3 の残り (O-3 の検索と palette、O-4 の Quota banner / Context display / Cost meter、O-5 の Server panel) は、どれも「どの面のどこに置くか」で中身が変わる。タブの画面の上に作ると、シェルを変えるときに作り直しになる。

## 本 feature の位置づけ

- **作り直さない。** 各画面の中身 (一覧の行・監視ビュー・起動ダイアログ・Chat・設定の 4 画面) は今のコンポーネントをそのまま使い、置き場所と遷移だけを変える。中身の持ち主 (runtime / session / provider の操作 UI) は変えない (ui charter の Out of scope)
- **シェル (面の配置と遷移) の持ち主は `ui` とする (U-2)。** 今の `App.tsx` は R-1 の FE-001 (アプリシェル) だが、R-1 の後に持ち主が決まっていない
- **M3 の順で O-3 の前に置く (U-1)。** O-3〜O-6 は本 feature の面の領域 (サイドバー・中央のヘッダ・中央の本体・右のペインのタブ) を参照して置き場所を書く

## User Scenarios & Testing

### User Story 1 - サイドバーでセッションを選び、中央で会話を読む・続ける (Priority: P1)

利用者は左のサイドバーで、稼働中のセッションか過去のセッションを選ぶ。中央にその会話が出る。稼働中なら入力して続けられ、過去なら読める。タブを行き来しない。

**Why this priority**: アプリの主な使い方そのものである。今は稼働中を見るには「セッション起動」タブ、過去を読むには「セッション」タブで選んでから「会話」タブに移る必要がある。

**Independent Test**: シェルの component テストで、サイドバーの 2 つの区画の行を選んだときの中央の面の切り替えと、選択の状態の保持を確かめる。E2E (偽の supervisor) の既存の起動の流れが新しいシェルで通る。

**Acceptance Scenarios**:

1. **Given** アプリを起動した、**When** 画面を見る、**Then** 上部のタブは無く、左にサイドバー (新規起動・稼働中 (0 件の文言)・過去のセッション・設定)、中央に空の状態、右に畳んだペインの帯がある (既定で畳む。data-model §2)
2. **Given** 稼働中のセッションがある、**When** サイドバーの稼働中の行を選ぶ、**Then** 中央に実行中の Chat が出て、入力できる。行の強調・経過時間・直近の活動 (O-1) はそのまま
3. **Given** 過去のセッションがある、**When** サイドバーの過去のセッションの行を選ぶ、**Then** 中央にその transcript が出る (読み取り専用)
4. **Given** 稼働中の会話を表示している、**When** 過去の行を選んでから稼働中の行に戻る、**Then** 稼働中の接続・transcript・下書き・キューは保たれる (X-5 FR-008)。スクロールは今と同じく下端に追従する (位置は保たない)
5. **Given** どの行も選んでいない、**When** 中央を見る、**Then** 空の状態が出て、「新規起動」と (フォルダが未登録なら)「設定 → 作業フォルダ」の操作がある
6. **Given** 稼働中のセッションが承認待ち・失敗になった、**When** 別の会話 (過去の会話を含む) を表示している、**Then** サイドバーの稼働中の区画の見出しに件数の印が出て、支援技術に読み上げられる (今の `SessionNavBadge` / `SessionAttentionAnnouncer` の役割を保つ。「見ている」の定義は data-model §1 の `watchedId`)
7. **Given** 過去の会話を表示している、**When** 稼働中の区画の承認待ちの件数のボタンを押す (O-1 FR-003)、**Then** 中央が承認待ちの稼働中のセッションに切り替わる
8. **Given** サイドバー、**When** 畳むボタンを押す、**Then** 帯 (新規起動・稼働中の件数の印・設定のアイコン) になり、もう一度押すと戻る

### User Story 2 - サイドバーから新しいセッションを起動する (Priority: P1)

利用者はサイドバーの「新規起動」から起動ダイアログを開き、起動すると、そのセッションが稼働中の区画に加わって中央に出る。

**Why this priority**: 今は「セッション起動」タブに移ってからダイアログを開く。シェルの入口を 1 つにする。

**Independent Test**: シェルの component テストと、既存の E2E (`launch-dialog.spec.ts` / `multi-session.spec.ts`) をナビゲーションの変更に合わせて流す。

**Acceptance Scenarios**:

1. **Given** どの面を表示していても、**When** サイドバーの「新規起動」を押す、**Then** 起動ダイアログ (X-4) が開く
2. **Given** 起動ダイアログで起動した、**When** 起動が受け付けられる、**Then** ダイアログが閉じ、そのセッションが稼働中の区画の行になり、中央に実行中の Chat が出る
3. **Given** 起動ダイアログを閉じた (起動しない)、**When** 中央を見る、**Then** 開く前の会話がそのまま出ている
4. **Given** 稼働中のセッションが起動の後に失敗した、**When** 失敗の告知の「閉じて起動し直す」を押す、**Then** 起動ダイアログが前回の設定と失敗の理由つきで開く (X-4 US-1 AC7 を保つ)
5. **Given** 起動中 (受け付けを待っている)、**When** ダイアログを見る、**Then** 起動中の表示が出て閉じられない。起動が拒否された (上限など)・起動に失敗したときは、ダイアログを閉じずに理由を出す (X-4 US-1 AC7 / AD-043)

---

### User Story 3 - 設定の画面をダイアログで開く (Priority: P1)

利用者はサイドバーの「設定」から、ランタイム・作業フォルダ・プロバイダ・組み合わせの画面と、テーマの切り替えを開く。閉じると元の会話に戻る。

**Why this priority**: タブを消すと、フォルダ・ランタイム・Provider の登録に届く入口はここだけになる。初回の起動 (フォルダが未登録) で使えないと、アプリが使えない。

**Independent Test**: 設定のダイアログの component テストで、4 項目の切り替え・閉じたときのフォーカスの戻り・画面をまたぐ受け渡し (一覧の「登録」→ 作業フォルダの登録の初期値) を確かめる。

**Acceptance Scenarios**:

1. **Given** サイドバー、**When** 「設定」を押す、**Then** 設定のダイアログが開き、左に 4 項目 (ランタイム・作業フォルダ・プロバイダ・組み合わせ) とテーマの切り替え、右に選んだ項目の画面がある
2. **Given** 設定のダイアログ、**When** Esc か閉じるボタン、**Then** 閉じて、開く前の会話と、開いた元の要素 (「設定」のボタンか「登録」のボタン) にフォーカスが戻る。中の画面は unmount され、閉じて開き直すと Provider の秘密の入力欄は空である
3. **Given** 過去のセッションの区画の「未登録」のグループで「登録」を押した (R-2 FE-051)、**When** 操作する、**Then** 設定のダイアログが「作業フォルダ」の項目で開き、登録の初期値が入っている
4. **Given** 設定のダイアログで作業フォルダを登録した、**When** 閉じる、**Then** サイドバーの過去のセッションの区画に、新しいフォルダのグループが反映される

### User Story 4 - 右のペインで表示中のセッションの概要を見る (Priority: P2)

利用者は会話を読みながら、右のペインを開いて、そのセッションがどの Provider・モデル・権限モードで動いているか、過去のセッションならどの所在・ブランチのものかを確かめる。ペインは既定で畳んであり、開ける。

**Why this priority**: 承認の判断 (権限モード) や費用の見当 (Provider・モデル) は会話の途中で要るが、今は起動ダイアログを閉じると見る場所が無い。右のペインの枠は後続 (O-4〜O-6) のタブの置き場にもなる。会話の表示 (US-1) が無いと意味が無いので P2 とする。

**Independent Test**: 右のペインの component テストで、タブの切り替え・畳み・表示中のセッションに合わせた概要の更新を確かめる。

**Acceptance Scenarios**:

1. **Given** 稼働中のセッションを表示している、**When** 右のペインを開いて「概要」を見る、**Then** data-model §5 の稼働中の項目が出る
2. **Given** 過去のセッションを表示している、**When** 「概要」を見る、**Then** data-model §5 の過去の項目が出る (登録フォルダの配下の行でもフォルダと所在が出る)。持っていない値は項目ごと出さない
3. **Given** どのセッションも選んでいない、**When** 右のペインを見る、**Then** 空の状態 (「セッションを選ぶと概要が出ます」)
4. **Given** 右のペイン、**When** 開く・畳むボタンを押す、**Then** 帯と開いた状態が切り替わる。再起動で既定 (畳んだ状態) に戻る
5. **Given** 概要の値 (ブランチ・フォルダなど) や中央のヘッダの題に HTML (`<img src=x onerror=...>`) や双方向制御文字が含まれる、**When** 表示する、**Then** DTO の時点で正規化済みの表示用の値をテキストとして描き、`img` 要素は 0

---

### Edge Cases

- ウィンドウの幅が狭い → 中央の最小の幅を割る前に、右のペイン → サイドバーの順に自動で畳む (利用者が開けば開く)。両方を畳んでも足りない幅では中央の最小の幅を割ってよい (横にスクロールさせない)。閾値の正本は data-model §2 [ASSUMED]
- アプリの起動の直後 → 過去のセッションの区画の初回の取得は、ランタイムの検出が終わってから行う (FR-016)。検出の前に列挙すると、WSL の所在のセッションが「未検出」として並び、取り直すまで残る (`useSessions.ts:71-77`)
- 稼働中のセッションが 10 本で、過去のセッションも多い → サイドバーの 2 つの区画はそれぞれ独立にスクロールし、稼働中の区画は最大の高さを持つ (過去の区画が見えなくならない)
- 表示中の稼働中のセッションが終了した → 中央は終了の告知 (X-5 の EndNotice) を出したまま残り、勝手に別の会話に移らない
- 表示中の過去のセッションが一覧の再取得で消えた → 今と同じく選択が外れた扱い (`useTranscript` の `hasSelection = false`) になり、中央は空の状態を出す
- 設定のダイアログを開いている間に、稼働中のセッションが承認待ちになった → 読み上げ (US-1 AC6) は行い、ダイアログは閉じない
- 設定のダイアログの中の画面がさらにダイアログを開く (削除の確認など) → 入れ子のダイアログのフォーカスは今の画面の振る舞いのまま。Esc は内側のダイアログから閉じる
- キーボードだけの操作 → サイドバー・中央・設定のボタンの順に Tab で移れ、ランドマーク (`nav` / `main` / `complementary`) で飛べる
- 稼働中と過去の両方の区画に選択が残っている → `focus` の側の行だけを選択中として強調する (data-model §1)

## Requirements

### Functional Requirements

#### シェル (US-1)

- **FR-001**: アプリは上部のタブのナビゲーションを持ってはならない。面は、左のサイドバー・中央・右のペインの 3 つにしなければならない。
  - 左は `nav` のランドマーク、中央は `main` のランドマーク、右は名前付きの `complementary` のランドマークにする。トップレベルの `nav` は 1 つ (区画の中で `nav` を入れ子にしない)
  - サイドバーの幅は固定の既定の幅を持ち、畳める (畳んだ状態は再起動で既定に戻る) [ASSUMED]
  - アプリの CSP と配信 (`src/main/app/protocol.ts`) を変えない。取り込む部品は本番の CSP (`style-src 'self'`。inline の `<style>` を足さない) の下で動くものに限る
- **FR-002**: サイドバーは、上から順に「新規起動」のボタン・稼働中のセッションの区画・過去のセッションの区画・「設定」のボタンを持たなければならない。
  - 稼働中の区画は O-1 の `RunningSessionList` を、過去の区画は R-2 の `SessionListScreen` の一覧の部分 (フォルダごとのグループ・所在の絞り込み) を、行と規則を変えずに置く (画面の外枠・見出しは外す。区画の幅に収める調整の範囲は plan)
  - 稼働中の区画が 0 件のときは「稼働中のセッションはありません。」(今の文言) を 1 行で出す
  - 2 つの区画はそれぞれの見出しを持ち、独立にスクロールする。稼働中の区画は高さの上限を持つ
  - 稼働中の区画の見出しに、注意が要るセッションの件数の印 (今の `SessionNavBadge` の役割) を出す
- **FR-003**: 中央の面は、選んだ行に応じて次のどれか 1 つを出さなければならない。
  - 稼働中の行 → 実行中の Chat (今の `SessionScreen` のセッションのペイン)
  - 過去の行 → 過去ログの transcript (今の `ChatScreen`)
  - 未選択 → 空の状態 (element `EmptyState`)。「新規起動」と、フォルダが未登録なら「設定 → 作業フォルダ」を出す
- **FR-004**: 面の切り替えは、稼働中のセッションの接続・transcript・下書き・キューを壊してはならない (X-5 FR-008。`useRunningSessionStoreWiring` は App の寿命で 1 回だけ張る)。稼働中の行と過去の行を行き来しても、稼働中の会話の状態は保たれる。スクロールの位置は保たない (戻ると下端に追従する今の振る舞い)
- **FR-016**: 過去のセッションの区画の初回の取得 (`listSessions`) は、ランタイムの一覧 (`listRuntimes`) が解決した後に行わなければならない。区画はアプリの起動の直後からマウントされるが、R-2 の「ランタイムの検出より先に列挙しない」(`useSessions.ts:71-77` / `src/main/index.ts:192-196`) を保つ
- **FR-005**: 中央の面の上端に、表示中のセッションの見出し (題・フォルダ・状態) を置く領域 (中央のヘッダ) を持たなければならない。今の `SessionHeader` と transcript の密度の切り替えはここに置く。**後続 feature (O-3〜O-6) が中央のヘッダとサイドバーに足す表示の置き場は、本 spec の領域の名前 (サイドバー・中央のヘッダ・中央の本体) で書く**
- **FR-006**: 支援技術への読み上げ (`SessionAttentionAnnouncer`) は、どの面を表示していても、設定のダイアログを開いていても働かなければならない。「見ているセッション」は data-model §1 の `watchedId` で決め、読み上げと承認待ちの件数のボタン (`nextAwaiting`) が同じ定義を使う。`selectedId` が変わる経路 (行の選択・起動の受け付け・承認待ちへの移動・close) のどれでも、中央の面が追随する

#### 右のペイン (US-4)

- **FR-014**: 右のペインは、タブで中身を切り替える面でなければならない。
  - タブは 1 か所の表 (renderer) に登録する。各タブは id・文言・表示できる条件 (表示中のセッションの種類)・中身を持つ。後続 feature はこの表に行を足す
  - 本 feature のタブは「概要」の 1 つ。表示できるタブが 1 つでもタブの見出しを出す (後続で増える前提の形を先に固める)
  - 既定で畳む (既定のウィンドウの幅で中央の幅を今と同じ程度に保つため。data-model §2)。畳んだ状態と選んだタブは再起動で既定に戻る
  - タブの中身は renderer の DOM の中に描くものに限る。外部コンテンツ (Browser / PR の Webview) のタブはこの表で表さない (AD-046 Decision 4)
  - 左・中央・右の幅の分け方 (既定の幅・最小の幅・ドラッグで変えられるか) の正本は data-model
- **FR-015**: 「概要」のタブは、renderer が既に持つ値だけで、表示中のセッションの概要を出さなければならない。
  - 項目と出所の正本は data-model §5 (稼働中は起動の設定、過去は一覧の行とグループの値)。中央のヘッダと重なる項目は出さない
  - 新しい IPC・preload の関数を足さない。会話由来の文字列は一覧と同じ表示用の値を使う
  - 未選択は空の状態

#### 起動 (US-2)

- **FR-007**: 「新規起動」は、どの面からでも起動ダイアログ (X-4 の `LaunchDialog`) を開かなければならない。
  - 起動が受け付けられたら、ダイアログを閉じ、そのセッションを選んだ状態にして中央に出す。閉じたら元の面に戻る
  - 起動中は閉じられない。拒否・失敗はダイアログを閉じずに理由を出す
  - 失敗したセッションを閉じたとき (「閉じて起動し直す」) は、ダイアログを前回の設定と理由つきで開く (X-4 US-1 AC7。data-model §1 の遷移)

#### 設定 (US-3)

- **FR-008**: 「設定」は、全面のダイアログを開かなければならない。
  - 左に 4 項目 (ランタイム・作業フォルダ・プロバイダ・組み合わせ) とテーマの切り替え、右に選んだ項目の今の画面 (`RuntimeListScreen` / `WorkspaceFoldersScreen` / `ProviderScreen` / `ResolutionScreen`) を中身を変えずに出す
  - Esc と閉じるボタンで閉じ、開いた元の要素にフォーカスを戻す。閉じたら中の画面を unmount する (覚えるのは項目の id だけ。Provider の画面の平文の秘密を残さない)。開いた項目は再起動で既定に戻る
  - element は registry の `Settings` を先に確かめ、合わなければ既存の Dialog で作る (Principle XIII。理由を対応表の F 節の備考に書く)
- **FR-009**: 画面をまたぐ受け渡し (一覧の「登録」→ 作業フォルダの登録の初期値。`seedFolderDraft`) は、設定のダイアログを「作業フォルダ」の項目で開く形にしなければならない。設定で登録・変更したフォルダ・ランタイム・プロバイダは、閉じた後のサイドバーと起動ダイアログに反映される (今の各ストアの再取得の振る舞いを保つ)

#### 状態と記録

- **FR-010**: 面の状態 (選んだ行・設定のダイアログの開閉と項目・サイドバーの畳み) は `stores/ui.ts` に置き、`SCREENS` / `ScreenId` / `setScreen` をこの状態に置き換えなければならない。永続化しない。今の画面の ID を参照するコードとテストを残さない
- **FR-011**: E2E (偽の supervisor)・スクリーンショットの検証・実機計測のハーネスは、新しいシェルで通らなければならない。
  - ナビゲーションのボタンを押していた手順 (`e2e/support/launch.ts:47` / `e2e/launch-dialog.spec.ts:18` / `perf/real-sessions.spec.ts:189,191`) をサイドバーの「新規起動」に直す。locator はサイドバーに限る (「新規起動」の文言は中央の空の状態にも出る)
  - 基準画像 (composer の領域) は、右のペインを既定で畳むことで今の幅 (composer の上限 704px) を保ち、変えない。変わったときは撮り直し、人間の見た目の承認 (Principle VIII (B)) を quickstart-results に記録する
  - perf は CI で流さないので、実行しない。直した手順は O-3 の義務 (2) を引き継ぐ feature が実機で確かめる (perf の安全柵・出力は変えないので、実機計測ハーネスの ADR の条件には当たらない)
- **FR-012**: 目標レイアウトの採用を ADR (AD-046、**proposed**) に記録しなければならない (U-5)。
  - AD-025 の目標レイアウト (左 Thread list・中央 Chat・右 Workspace / Panel) を採用する。右は枠とタブの仕組みと「概要」までを本 feature で作り、Changes / PR の Webview / Terminal / Files / Browser を OPT-panel に送る

  - 右のペインに外部コンテンツを載せるときの境界: 主ウィンドウの `webviewTag` を有効にしない (main が管理する `WebContentsView`)、モーダル (設定・起動・承認) を開いている間は外部のビューを隠す、renderer が報告する配置の矩形を main で検証する
  - 面の領域の名前 (サイドバー・中央のヘッダ・中央の本体・右のペインのタブ・設定のダイアログ) を、後続 feature が置き場所を書く語彙として定める
  - AD-025 (accepted) の本文は変えない
