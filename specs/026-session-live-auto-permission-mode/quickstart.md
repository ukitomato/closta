# Quickstart: 権限モードの Auto (026)

実機で確かめる手順。結果は `quickstart-results.md` に書く。行えなかった項目は「未実施」と書いてマージする (spec SC-005・夜間の規則)。コマンドは `docs/discovery.md` の "Build / Test / Lint" 表の agent 用の列。

## V-0 自動の検証が緑

1. 型・lint・単体テスト・Constitution 検証・rule fixture・E2E を通す (`docs/discovery.md` の表の順)
2. Constitution 検証の項目 16 が ok、rule fixture の新設 `sdk-set-permission-mode-escalation-literal` が発火して期待どおり、項目 21 (ui-coverage) が ok

## V-1 起動の設定で Auto (Win32Runtime。隔離なし)

1. Win32Runtime のフォルダで起動の設定を開き、権限モードの選択肢が「Manual / Plan / Don't Ask / Auto」の 4 つ (名前は Claude Code の表記。AD-065) で、`Accept edits` / `Bypass Permissions` が無いことを見る
2. 「Auto」を選ぶ → 確認が出て、焦点が「取り消す」にあることを見る。「取り消す」で前の値に戻る
3. もう一度選んで「Auto にする」→ 起動 → 中央のヘッダの下に Auto の帯 (amber。「選んだ権限モード「Auto」で動いています」と「このランタイムには隔離がありません」) が出る。スクリーンリーダー (ナレーター) が帯の文を 1 回だけ読む
4. 別のセッションに切り替えて戻る → 帯は出たまま、読み上げは起きない

## V-2 実行中の切り替え

1. `default` で起動したセッションの composer の左の権限モードの選択で「Auto」を選ぶ → 承認カードの位置に確認が出る → 取り消す → 何も変わらない (選択は「Manual」のまま。焦点は composer の入力に戻る)
2. もう一度選んで承諾 → セッションは止まらずに `auto` に変わり、帯が出て 1 回だけ読み上げられる
3. 「Manual」に戻す → 確認なしで変わり、帯が消える
4. 確認を開いたままセッションを停止する → 確認が閉じ、要求が送られない (ログに `set-permission-mode` が無い)
5. 読み上げの位置 (ナレーター): Auto で動いているセッション A と `default` のセッション B を用意し、B を表示しているときに A へ切り替える → 読み上げが起きない。B を Auto に切り替える (承諾) → 1 回だけ読み上げ、A に切り替えて B に戻しても増えない

## V-3 分類器の判断 (SC-005)

1. V-2 の 2 の状態で、ファイルを読む・書く・コマンドを実行する依頼を出す
2. 分類器が許可した操作が承認カードなしで実行され、拒否した操作が今の拒否の表示に出ることを記録する。判断できずに承認カードが出た操作があれば、それも記録する (research R-01)
3. `auto` が使えないアカウント・モデルなら、起動の失敗または変更の失敗 (`rejected`) の今の表示に出ることを記録する (spec Assumptions)

## V-4 プリセットと再開

1. `auto` の設定をプリセットに保存し、起動の設定を開き直してプリセットを適用 → 起動を押すと確認が出る (適用で確認を省かない)。同じダイアログで Auto を選んで承諾 → Manual に戻す → `auto` のプリセットを適用 → 起動を押しても確認が出る (前の承諾が残らない)
2. 保存した `presets.json` の `schemaVersion` が 3
3. `auto` で動いている行から再開を開く → 権限モードの初期値が「Manual」(`default`)
4. 終わったセッションの再開のフォームで Auto を選び承諾して再開する → 再開が `auto-mode-unconfirmed` で拒否されずに `auto` で始まる (再開の経路で印が届く)
