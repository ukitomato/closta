# Quickstart: 権限モードの Auto (026)

実機で確かめる手順。結果は `quickstart-results.md` に書く。行えなかった項目は「未実施」と書いてマージする (spec SC-005・夜間の規則)。コマンドは `docs/discovery.md` の "Build / Test / Lint" 表の agent 用の列。

## V-0 自動の検証が緑

1. 型・lint・単体テスト・Constitution 検証・rule fixture・E2E を通す (`docs/discovery.md` の表の順)
2. Constitution 検証の項目 16 が ok、rule fixture の新設 `sdk-set-permission-mode-escalation-literal` が発火して期待どおり、項目 21 (ui-coverage) が ok

## V-1 起動の設定で Auto (Win32Runtime。隔離なし)

1. Win32Runtime のフォルダで起動の設定を開き、権限モードの選択肢が「通常 (操作ごとに承認) / 計画のみ (実行しない) / 事前承認のみ (承認カードを出さない) / 自動で判断」の 4 つで、`acceptEdits` / `bypassPermissions` が無いことを見る
2. 「自動で判断」を選ぶ → 確認が出て、焦点が「取り消す」にあることを見る。「取り消す」で前の値に戻る
3. もう一度選んで「自動で判断にする」→ 起動 → 中央のヘッダの下に Auto の帯 (amber。「選んだ権限モード「自動で判断」で動いています」と「このランタイムには隔離がありません」) が出る。スクリーンリーダー (ナレーター) が帯の文を 1 回だけ読む
4. 別のセッションに切り替えて戻る → 帯は出たまま、読み上げは起きない

## V-2 実行中の切り替え

1. `default` で起動したセッションのヘッダで「自動で判断」を選ぶ → 確認 → 取り消す → 何も変わらない (概要のタブの「現在の権限モード」が「通常」のまま)
2. もう一度選んで承諾 → セッションは止まらずに `auto` に変わり、帯が出て 1 回だけ読み上げられる
3. 「通常」に戻す → 確認なしで変わり、帯が消える
4. 確認を開いたままセッションを停止する → 確認が閉じ、要求が送られない (ログに `set-permission-mode` が無い)

## V-3 分類器の判断 (SC-005)

1. V-2 の 2 の状態で、ファイルを読む・書く・コマンドを実行する依頼を出す
2. 分類器が許可した操作が承認カードなしで実行され、拒否した操作が今の拒否の表示に出ることを記録する。判断できずに承認カードが出た操作があれば、それも記録する (research R-01)
3. `auto` が使えないアカウント・モデルなら、起動の失敗または変更の失敗 (`rejected`) の今の表示に出ることを記録する (spec Assumptions)

## V-4 プリセットと再開

1. `auto` の設定をプリセットに保存し、起動の設定を開き直してプリセットを適用 → 起動を押すと確認が出る (適用で確認を省かない)
2. 保存した `presets.json` の `schemaVersion` が 2
3. `auto` で動いている行から再開を開く → 権限モードの初期値が「通常」(`default`)

## V-5 隔離のあるランタイム (行えれば)

`isAutoModeAllowed` が true のランタイム (bubblewrap のある WSL) があれば、Auto を選んで確認が出ないことを見る。無ければ「未実施 (該当のランタイムが無い)」と書く (単体テストで確かめている)
