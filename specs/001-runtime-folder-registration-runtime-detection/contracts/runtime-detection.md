# Contract: ランタイム検出 (`infra` ↔ `domain`)

**Spec**: [../spec.md](../spec.md) | **Research**: [../research.md](../research.md) | **Data model**: [../data-model.md](../data-model.md)

`domain` がインタフェースを宣言し、`infra` が実装する (AD-023 §3)。
境界を越えるのは `RuntimeDescriptor` という**値**であって、検出の手続きではない。

## インタフェース (`src/domain/runtime/interfaces.ts`)

| 操作                  | 責務                                                                                                                                                                                              |
| --------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `list()`              | インストール済みランタイムを列挙する。capabilities は未判定でよい                                                                                                                                 |
| `verifyRunning(ids?)` | 実行状態を取り直す。**実行中確認済みの値を生成できる唯一の経路**。引数を省略すると全ディストロ分を 1 回で取得する。**返す値はディストロごとに分かれ、それぞれが対象ディストロの識別子を保持する** |
| `probe(distro)`       | capabilities とマッピングを確定させる。**実行中確認済みの値しか受け取らない**                                                                                                                     |

`AgentRuntime` は `descriptor` と `path` を持つ (data-model §7)。

実行中確認済みの値を表す型は、`verifyRunning` を含むモジュールの外から組み立てられない形にする。
「停止中ディストロにプロセスを起動しない」を**約束ではなく型の制約**にするためである。

**この値は対象ディストロの識別子を保持し、受け取る側は入口で一致を検証する** (data-model §5)。
識別子を持たないと、A について取った**正規の**値で B を操作でき、
B が停止中なら UNC アクセスが B を起動して SC-005 が破れる。
`tasks.md` の違反サンプルは「型の偽造」だけでなく**正規の値の流用**も対象にする。

## C-1: `wsl.exe` の呼び出し回数

| 段階                     | 呼び出し                                     | 回数                     |
| ------------------------ | -------------------------------------------- | ------------------------ |
| `list()`                 | 名前の列挙 / 実行中の列挙 / バージョンの列挙 | **3** (並列)             |
| `verifyRunning()` (一括) | 実行中の列挙                                 | **1**                    |
| `probe(distro)`          | ディストロ内でのスクリプト実行               | **1** (ディストロあたり) |

**判定バッチは `verifyRunning()` を 1 回呼んで全ディストロの実行状態を得てから、
実行中のものに `probe` を並列発行する。ディストロごとに `verifyRunning` を呼ばない。**

**実行中の WSL1 にも `probe` を発行する。** FR-004 が免除するのは sandbox 判定の実地テストで
あってマッピングの取得ではない。WSL1 に対する呼び出しは**マッピングの取得だけ**を行い、
capabilities は固定値を採る。発行しないとマッピングが無いまま `probeState: done` になり、
所在 `windows` のフォルダがすべて変換不能になる (data-model §8 第 2 段)。

AD-015 の実測で `wsl.exe` の固定起動コストは約 1.5 秒である。並列化と一括取得により
`list()` は約 1.6 秒、判定バッチ全体は約 3.2 秒に収まり SC-004 を満たす。
**呼び出し回数をディストロ数にも利用者の操作回数にも比例させてはならない** (FR-010)。

## C-2: 出力の解釈 — 環境・ロケールに依存しない

| 規則                                                                               | 根拠                                               |
| ---------------------------------------------------------------------------------- | -------------------------------------------------- |
| すべての `wsl.exe` 呼び出しで UTF-8 出力を要求する                                 | 既定は UTF-16LE (AD-015 §4)                        |
| 行分割後に末尾の復帰文字を除去する                                                 | 改行は CRLF のまま                                 |
| **名前は名前だけを返す列挙の出力**を正本とする                                     | 列整形・翻訳の影響を受けない                       |
| **実行状態は実行中の列挙との積集合**で決める                                       | 状態文字列はロケール依存                           |

| **バージョンは、行から既知の名前を最長一致で取り除いた残りの最終トークンから読む** | 「行内の最初の数値」では `Ubuntu-26.04` で誤読する |

UTF-16LE / CRLF / 翻訳済みヘッダ / 空白を含む名前 / 数字を含む名前をフィクスチャに含める (SC-011)。

## C-3: 副作用の禁止

| 規則                                                                               | 根拠                                                       |
| ---------------------------------------------------------------------------------- | ---------------------------------------------------------- |

| **確認済みの値が保持する識別子と、操作対象の識別子の一致を入口で検証する**         | 正規の値を別ディストロに流用する経路を塞ぐ (data-model §5) |
| **確認済みの値には有効期間がある** (data-model §5)。期限切れの値を使ってはならない | C-1 の呼び出し予算と両立させるため                         |

| **`wsl.exe` を名指せるのは `src/main/infra/runtime/**` のモジュールのみ**          | FR-041                                                     |
| **ディストロ内で実行するスクリプトは定義済みのものに固定し、動的に組み立てない**   | FR-037 (f)                                                 |
| **定義済みスクリプトの内容の変更には ADR を要する**                                | 下記                                                       |
| パッケージのインストール・OS 設定の変更・ディストロの作成を行わない                | Constitution Principle VI                                  |
| 不足依存は**アンカー付きの名前**として返すだけ。コマンド文字列を持たない           | FR-009                                                     |

### スクリプトの検証方針

コマンド名の許可リストだけでは不十分である。出力系のコマンドとリダイレクトを
組み合わせればディストロ内に永続的な変更を残せるため、コマンド名を許しても
形が許されてしまう。**スクリプトそのものを定義済みの内容に固定し、検証はその一致で行う。**

**固定だけでは足りない。** 一致検証が判定できるのは「実行されるスクリプトが登録済み定数と
一致するか」だけであり、**定数の内容そのものが Principle VI に反するかは誰も見ない**。
定数と実行箇所を同じ PR で書き換えれば、`>> ~/.bashrc` やパッケージ導入を含むスクリプトが
検証 8 項目と CI を通過する。コマンド名許可リストで塞いだはずの出口に戻る。

そのため**定数の内容の変更には ADR を要する** — モジュール許可リスト (FR-041) と同じ強さで扱う。
PR diff に現れ、`architecture-reviewer` と人間の判定対象として固定される。

定数には次の不変条件が付随する。**これは ADR レビュー (人間) が担保するものであり、
機械検証されない。**

- **ディストロ内に永続的な変更 (ファイル・パッケージ・OS 設定) を残さない。**
  プロセスの寿命で消える一時資源の生成 — user namespace の試験生成 (AD-015 §8 の判定 4) — は許す
- 標準入力を読まない (C-4)

機械側で担保できるのは次の 3 点であり、SH-014 の項目 6 はこの 3 つを検査する。
**「定数と一致するか」だけでは足りない** — 定数に文字列を連結して書き込めば
「定数が存在する」検査を通過してしまう。

1. 定数が**単一のリテラル**であること (連結・テンプレート・関数呼び出しで組み立てられていない)
2. 標準入力へ書く式が**その定数の識別子そのもの**であること (連結・補間を伴わない)
3. 定数の内容が、許可するコマンド形の allow-list に収まること

スクリプトは実行状態の確認と同じ呼び出しで**マッピングと capability 判定の材料を
まとめて返す**。取得した材料の整形はホスト側で行い、スクリプト側で加工しない。

## C-4: 引数の渡し方

| 規則                                                                                                                                                                                                | 根拠                                                                                                           |
| --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------- |
| 引数は**配列**で渡す。シェル文字列を組み立てない                                                                                                                                                    | インジェクションの回避                                                                                         |
| ディストロ名は検出済みのものに一致することを確認してから渡す                                                                                                                                        | 未信頼入力の検証                                                                                               |
| **ディストロ名は文字種の制約を満たすことを列挙の時点で確認する** — バックスラッシュ・`/`・`:`・NUL・制御文字を含まず、先頭が `-` でないこと。満たさない名前は descriptor を作らず列挙不能として返す | 「検出済みの名前に一致する」は**検出自身が出力元である以上恒真**であり、文字種を何も制約しない (data-model §4) |
| **スクリプトは引数ではなく標準入力で渡す**                                                                                                                                                          | `wsl.exe` の引数処理は**バックスラッシュを消す** (AD-015 §5)。整形コマンドが静かに壊れる                       |
| **バックスラッシュを含む任意の引数**を `wsl.exe` に渡さない                                                                                                                                         | 同上。パスに限った制約ではない                                                                                 |

標準入力でスクリプトを渡す場合、スクリプト自身が標準入力を占有する点に注意する。
標準入力を読むコマンドを含めてはならない。この制約は C-7 の拡張時にも適用される。

## C-5: 失敗時の扱い

| 状況                                                        | 返すもの                                                                                                                                                                                        |
| ----------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `wsl.exe` が存在しない / 列挙が非 0 終了                    | `Win32Runtime` のみ。**例外を投げない** (FR-012 / SC-015)                                                                                                                                       |
| **バージョン列挙だけが失敗した**                            | `wslVersion: null`。**実地判定を行わず** `sandbox` / `autoModeSafe` を `unknown`、`probeState` を `failed` とする。WSL1 と WSL2 を区別できない以上、WSL1 の固定値も WSL2 の実地判定も根拠を欠く |
| **呼び出しが期限内に完了しない**                            | 判定失敗として扱い capabilities を未判定に戻す。期限値は実装で決めてよい。辺が無いと `probing` のまま留まり、利用者への解消手順が「待て」だけになる                                             |
| **マウント情報の要素が形式を満たさない** (data-model §2)    | マッピング取得の失敗として扱う。**部分的に欠けたマッピングを採用しない**                                                                                                                        |
| **判定出力が完了を示していない / 期待する項目が欠けている** | 判定失敗として扱い、capabilities を未判定に戻す                                                                                                                                                 |
| `probe` が非 0 終了                                         | 同上                                                                                                                                                                                            |
| 実行状態の確認で停止中が返った                              | `probe` を発行せず、呼び出し元に「起動が必要」を返す                                                                                                                                            |
| WSL 側ファイルアクセスが使えない                            | **所在ごとの失敗**として扱う。他の所在に影響させない                                                                                                                                            |
| パスが長さ制限を超えた / 読み取り権限がない                 | 種別を区別して返す                                                                                                                                                                              |

**項目の欠落を「問題なし」と解釈してはならない。** AD-015 §8 が
「キー不在は問題なし」とするのは**確認コマンドが正常終了したうえで**の話である。
スクリプトを逐次読む方式では途中で失敗しても前半だけが出力された状態で正常終了しうるため、
**完了の標識と項目の完全性の両方で守る**。確認コマンドの終了状態も出力に含める。

| 規則                                                                               | 根拠                  |
| ---------------------------------------------------------------------------------- | --------------------- |
| キャッシュキーにランタイム識別子 (ディストロ名を含む) を使う                       | FR-011                |

| キャッシュはメモリ上。ディスクに永続化しない                                       | spec `## Assumptions` |

## C-7: 拡張点 (I-1 への申し送り)

probe スクリプトは項目単位の出力を返す形であり、**項目の追加で拡張できる**。
I-1 が docker endpoint を検出する際は項目を 1 つ足すだけでよく、全ディストロの再走査は不要である。

追加する項目は (a) 標準入力を読まないこと、(b) 定義済みスクリプトの一部として登録され
検証の照合対象が更新されること、(c) **定数の変更として ADR を伴うこと** (C-3)、
(d) **ディストロ内に永続的な変更を残さないこと** (一時資源の生成は許す) の
4 条件を満たさなければならない。

## パス変換 (`src/domain/runtime/`)

**純粋関数。`infra` を知らず I/O を持たない。**
パス操作の標準モジュールを import してよいのは**この実装モジュール 1 つだけ** (FR-025)。

| 規則                                                                                                                                                                                                                                                |
| --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **すべての変換関数が入口で名前空間識別子の一致を検証する。** 不一致は変換不能を返す                                                                                                                                                                 |
| **`from === to` は恒等**であり接頭辞照合を行わない。`Win32Runtime` の `host` がこれにあたる                                                                                                                                                         |
| **`isSameDistro(a, b)`** — 種別を問わずディストロ成分の**完全一致**で判定し、`host` は常に偽。**`NamespaceId` から成分を取り出してよい唯一の場所**とする                                                                                            |
| **UNC 形式との相互変換は対象ディストロ識別子を必須引数として受け取り**、値に埋め込まれたディストロ名との一致を検証する                                                                                                                              |
| **POSIX 値の成分にバックスラッシュ・NUL・制御文字が含まれる場合は変換不能を返す。** POSIX 意味論ではバックスラッシュは通常の文字であり `.` / `..` の解決規則が発火しないため、含んだまま UNC へ変換すると値が字面で示す位置とは別の位置に解決される |
| **UNC 形式への変換は合成後に再正規化し、結果が対象ディストロの share 配下に収まることを検証する。** 収まらなければ変換不能を返す                                                                                                                    |
| ホスト名前空間とランタイム名前空間で**異なる意味論**を使う。プラットフォームによって挙動が変わる API を使わない                                                                                                                                     |
| 接頭辞の照合は**パスセグメント境界**で行い、複数一致なら**最長の接頭辞**を採る                                                                                                                                                                      |
| マッピングに現れない接頭辞は**変換不能**を返す。推測で対応を作らない                                                                                                                                                                                |
| 合成は `a.to === b.from` のときのみ成立し、同じ照合規則に従う (FR-026)                                                                                                                                                                              |

**`ui` はこの実装モジュールに到達してはならない。** 越境判定に必要な接頭辞照合は
標準モジュールに依存しない別モジュールに置く (data-model §7)。

**性質テスト** (SC-001): 往復不変 / UNC 往復 / ドライブレターの大小非依存 /
末尾セパレータ非依存 / 非既定のマウント位置 / マッピングに無い接頭辞で変換不能 /
接頭辞が互いに前方一致するマウント位置の共存 / 別名前空間のパスで変換不能 /
**別ディストロの UNC 値を渡すと変換不能** / **`Win32Runtime` の恒等変換** /
**バックスラッシュを含む POSIX 値で変換不能** /
2 つのマッピングの合成が逐次適用と一致。
