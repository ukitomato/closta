# Contract: 作業フォルダの永続化 (`infra/settings`)

**Spec**: [../spec.md](../spec.md) | **Data model**: [../data-model.md](../data-model.md) | **IPC**: [ipc-capability.md](ipc-capability.md)

IPC 境界と**同じ粒度**で名前空間を保持する。

## 置き場所と依存

| 項目                     | 規則                                                                    |
| ------------------------ | ----------------------------------------------------------------------- |
| 実装                     | `src/main/infra/settings/`                                              |
| 保存先                   | Electron のユーザデータディレクトリ配下の JSON ファイル                 |
| **`electron` の import** | **してはならない。** ユーザデータディレクトリのパスを**引数で受け取る** |
| パス組み立て             | `domain` のパス API を使う。標準モジュールを直接 import しない          |

ディレクトリの解決には Electron API が必要だが `infra` は許可ディレクトリではない
(FR-038 / AD-023 §8)。**`app` レイヤの composition root が値を解決して注入する。**

## オンディスク形式

```json
{
  "schemaVersion": 1,
  "folders": [
    {
      "id": "wf_01J...",
      "location": { "kind": "wsl", "distroName": "Ubuntu-26.04" },
      "path": { "namespace": "wsl:Ubuntu-26.04", "value": "/home/u/repo" },
      "displayName": "repo",
      "registeredAt": 1789000000000
    }
  ]
}
```

| フィールド               | 規則                                                  |
| ------------------------ | ----------------------------------------------------- |
| `schemaVersion`          | **必須**。R-1 は `1`                                  |
| `folders[].path`         | **IPC の `PathDTO` と同じ形**。素の文字列で保存しない |
| `folders[].reachability` | **保存しない。** 起動時に判定し直す実行時の値である   |

**秘密情報のフィールドを持たない** (Constitution Principle V / FR-019)。
保存するフィールドはコード上の allow-list で固定し、未知のキーは読み書きのどちらでも通さない。

Principle V の自動検証は SQL のカラム型に依存しており JSON 設定ファイルを検査できない。
検証条件の追随は AD-024 のスコープに含め、それまでは allow-list を実装側の担保とする。

## 読み戻しの規則

| 状況                                                                                                                 | 振る舞い                                         |
| -------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------ |
| `schemaVersion` が一致                                                                                               | 各レコードを検証して復元する                     |
| `schemaVersion` が未知 / 欠落                                                                                        | 復元せず `schema-version-unknown` として計上する |
| JSON の解析に失敗                                                                                                    | 復元せず `parse-failed` として計上する           |
| **所在とパスの名前空間が一致しない**                                                                                 | 復元せず `namespace-mismatch` として計上する     |
| パスが名前空間の形式に合致しない                                                                                     | 復元せず `invalid-path` として計上する           |
| **パス値が NUL / 制御文字を含む、またはランタイム名前空間の値がバックスラッシュを成分に含む**                        | 復元せず `invalid-path` として計上する           |
| **`location` が既知の形式でない、または `kind === 'wsl'` の `distroName` が data-model §4 の文字種制約を満たさない** | 復元せず `invalid-record` として計上する         |
| **`id` が形式不正、または他のレコードと重複する**                                                                    | 復元せず `invalid-record` として計上する         |
| **`displayName` が長さ上限を超える、または制御文字を含む**                                                           | 復元せず `invalid-record` として計上する         |
| **`registeredAt` が有限の数値でない**                                                                                | 復元せず `invalid-record` として計上する         |
| 一部のレコードだけ壊れている                                                                                         | **読めた分を復元し、件数と理由キーを返す**       |

**allow-list はキー名の許可であって値の検証ではない。** 未知のキーを落とすだけでは、
既知のキーに任意の値が入ったレコードがそのまま IPC と UI に流れる。
`id` の一意性を要求しないと `unregisterFolder(id)` / `resolveFolderRuntime(folderId, ...)` の
対象が一意に決まらず、巨大な `displayName` は一覧描画を止めて SC-004 の
「再表示 100 ミリ秒」を破る。

### 名前空間の照合は `domain` の 1 関数に集約する

`isNamespaceConsistent(location, path)` が判定する。所在 `windows` はホスト名前空間に、
所在 `wsl:<D>` は**ディストロ名まで含めて**対応する名前空間に一致しなければならない。

**IPC 境界 ([ipc-capability.md](ipc-capability.md)) と永続化境界の双方がこの関数を呼ぶ。**
粒度を別々に定義すると、所在の種別だけが一致してディストロ名が異なるレコードが
片方の境界だけを通過し、以後の解決が誤ったランタイムに対して「到達可能」と判定する。

所在から型を復元する際は**この判定を通してから**行う。一律に片方の型を当てると、
所在が WSL のエントリがホスト名前空間の型として復元される。
**これは型検査では検出できない** (JSON からの値は `unknown` である)。

## 書き込みの規則

| 規則                                                                                     | 根拠                                                                                                                              |
| ---------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------- |
| **復元できなかったファイル・レコードは上書き前に退避する。退避が完了するまで置換しない** | FR-019。退避がないと、起動後の 1 回の登録操作で元ファイルが消える。将来バージョンのファイルを旧バージョンで開いた場合は全件を失う |
| **アプリは単一インスタンスに制限する**                                                   | FR-020。2 インスタンスの同時書き込みで登録が後勝ちで消える                                                                        |
| 書き込みは一時ファイル + rename による atomic 置換とする                                 | 書き込み中のクラッシュで全件を失わない                                                                                            |
| 書き込みのたびに `schemaVersion` を出力する                                              | 将来の移行判定のため                                                                                                              |

単一インスタンス制限は `app` レイヤ (Electron 許可箇所) に置くため FR-038 に抵触しない。
**退避先は利用者への報告に含める** (FR-047 に従い訳出する)。

## テスト

| 観点       | 内容                                                                                                                                                             | 対応 SC |
| ---------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------- |
| 復元       | 所在 `windows` / `wsl` の両方、空白・日本語・非 ASCII を含むパスが 100% 復元される                                                                               | SC-013  |
| 重複       | ドライブレターの大小差・末尾セパレータの有無を正規化して重複を 0 件にする                                                                                        | SC-013  |
| 破損       | JSON 破損 / `schemaVersion` 不一致 / **所在の種別は一致するがディストロ名が異なる** の 3 ケースで、読めた分が復元され件数・理由・退避先が返る。**起動失敗 0 件** | SC-013  |
| UI 到達    | 件数と理由が renderer に届き描画される (preload をスタブした単体テスト)                                                                                          | SC-013  |
| allow-list | 未知のキーを含むレコードが書き戻しで増殖しない                                                                                                                   | FR-019  |

## 拡張点

- X-3 / X-4 が Provider 設定やプリセットを同じ層に載せる場合も、
  **秘密情報は OS キーチェーンの参照キーのみ**とする (Constitution Principle V / AD-011)
- I-1 が所在にコンテナを追加する場合、`schemaVersion` を上げて移行を定義する
