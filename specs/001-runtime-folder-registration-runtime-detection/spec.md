## User Scenarios & Testing _(mandatory)_

### User Story 1 - 起動先ランタイムの検出と提示 (Priority: P1)

アプリを起動すると、このホストで Claude Code を動かせる場所が一覧で示される。
Windows ネイティブ (`Win32Runtime`) と、インストール済みの WSL ディストロごとの
`WslRuntime` が並び、それぞれに「無人実行を安全に回せるか」が添えられる。

**Why this priority**: 他のすべての操作の前提。`runtime` charter の Journey 1 そのものであり、
`session` / `isolation` / `ui` の全 domain がこの出力に依存する。

**Independent Test**: WSL ディストロを 1 つ以上持つ Windows ホストでアプリを起動し、
一覧を `wsl -l -v` の出力と突き合わせる。作業フォルダを登録していない状態で検証できる。

**Acceptance Scenarios**:

1. **Given** WSL2 ディストロが 2 つ (1 つ実行中 / 1 つ停止中)、**When** アプリを起動する、
   **Then** `Win32Runtime` 1 件と `WslRuntime` 2 件が現れ、停止中の capabilities は未判定と示される
2. **Given** 実行中の WSL2 ディストロが sandbox の必須依存を満たす、**When** 判定が完了する、
   **Then** sandbox あり / 無人実行「可」と表明され、**seccomp が未判定であることが区別可能に示される**
3. **Given** 実行中の WSL2 ディストロで、必須依存が**そのディストロのマウント配下にしか見つからない**
   (Windows 側の実行ファイルが PATH 経由で見えている状態)、**When** 判定が完了する、
   **Then** その依存は**不在として扱われ**、sandbox なし / 無人実行「不可」と表明され、
   不足依存の名前と導入手順への導線が案内される
4. **Given** WSL1 のディストロ、**When** 判定を行う、**Then** 実地テストなしで sandbox なしと表明される
5. **Given** 判定結果が不完全にしか得られなかった、**When** 解釈する、
   **Then** 判定失敗として扱われ、**欠けた項目を「問題なし」と解釈しない**
6. **Given** 検出が一度完了している、**When** 同じ起動中に再度一覧を開く、**Then** 再走査されず即座に表示される
7. **Given** ユーザが「再検出」を実行する、**When** 走査が走る、**Then** 結果が更新される
8. **Given** 判定済みのランタイム、**When** 再検出で再判定が始まる、
   **Then** 判定中は無人実行「不可」として扱われる (**旧値を据え置いて「可」を表示し続けない**)
9. **Given** WSL がインストールされていないホスト、**When** 起動する、
   **Then** 例外が発生せず `Win32Runtime` のみが現れ、WSL が見つからない旨が示される
10. **Given** 名前に空白を含むディストロ、**When** 一覧を表示する、
    **Then** 名前が切れずに表示され、実行状態も正しく判定される

### User Story 2 - 所在を選んで作業フォルダを登録する (Priority: P1)

作業フォルダを登録するとき、**まず所在 (Windows か、どの WSL ディストロか) を選び**、
そのうえでフォルダを指定する。登録したフォルダは所在つきで残り、次回起動時も復元される。

**Why this priority**: 所在を先に選ばせることが、越境判定と到達可能性判定を
**構造的に決定可能**にする。所在が曖昧なままパス文字列だけを持つと、
Constitution Principle I が守ろうとしている名前空間の分離が入口で崩れる。

**Independent Test**: 検出結果をスタブで与え、Windows 側と WSL 側のフォルダを 1 つずつ登録し、
再起動して復元を確認する。ランタイムの選択とパス解決を伴わずに検証できる。

**Acceptance Scenarios**:

1. **Given** 登録フォルダが 0 件、**When** フォルダ管理を開く、
   **Then** 空状態であることと「まず所在を選ぶ」導線が示される
2. **Given** 所在として「Windows」を選ぶ、**When** フォルダを指定する、
   **Then** 所在 `windows` として一覧に追加される
3. **Given** 実行中の WSL ディストロを所在として選ぶ、**When** フォルダを指定する、
   **Then** ディストロ内のツリーから選択でき、所在 `wsl:<distro>` として追加される
4. **Given** WSL 側のフォルダブラウザ、**When** 複数階層を移動する、
   **Then** 階層移動ごとに待たされることなく、体感上即時に応答する
5. **Given** 登録済みのフォルダ、**When** 同じ所在・同じパスを再登録しようとする、
   **Then** 重複登録されず、既存エントリが選択状態になる
6. **Given** 登録済みフォルダが削除された / 所在ディストロが無くなった、**When** 一覧を表示する、
   **Then** **到達不可**であることが区別され、登録解除の導線が示される
7. **Given** 所在ディストロが**停止しているだけ**の登録フォルダ、**When** 一覧を表示する、
   **Then** **一時的に解決不能**として到達不可と区別され、起動と再検出の導線が示される。
   **登録解除は勧められない**
8. **Given** 任意の登録エントリ (**到達可能なものを含む**)、**When** 登録解除する、
   **Then** 一覧から消える。**到達可能であることを理由に解除を妨げられない**
9. **Given** 停止中のディストロを所在として選ぶ、**When** フォルダ選択を開こうとする、
   **Then** 起動が必要である旨と**起動後に再検出する導線**が示され、**アプリは黙って起動しない**
10. **Given** 案内を見た利用者、**When** アプリ外で起動して再検出する、**Then** フォルダ選択が開ける
11. **Given** 空白・日本語・非 ASCII を含むフォルダ、**When** 登録する、
    **Then** 文字化けや切り詰めなく登録され、**一覧にそのまま表示される**
12. **Given** 読み取り権限のないディレクトリ、**When** 辿ろうとする、
    **Then** アクセスできない旨が日本語で示され、他の所在の操作に影響しない
13. **Given** 登録済みフォルダがある状態で再起動する、**When** 一覧を表示する、**Then** すべて復元される
14. **Given** 永続化ファイルが壊れている / スキーマ版が不一致 / 所在とパスの名前空間が食い違う
    レコードを含む、**When** 起動する、
    **Then** 読めたレコードのみが復元され、**復元できなかった件数と理由が画面上に示され**、
    元データが退避される。起動は妨げられない

### User Story 3 - フォルダとランタイムの組み合わせを解決する (Priority: P1)

登録済みフォルダとランタイムを選ぶと、そのランタイムから見たパスが解決される。
**到達できない**組み合わせは選択肢に現れず、**一時的に解決できない**組み合わせは
選択肢に現れて解消手順が示され、境界をまたぐ (越境する) 組み合わせは選べるが必ず明示される。

**Why this priority**: 本 feature の中核価値。パス変換が両方向で正しく通ることと、
越境を隠さないことが、以降の全 feature が乗る土台になる。AD-016 はディレクトリ走査が
越境時に約 800 倍 (小ファイルの読み取りでは最大 1,180 倍) 遅くなることを実測しており、
黙って選ばせると実用にならない組み合わせに利用者が気付けない。

**Independent Test**: `RuntimeDescriptor` と `WorkspaceFolder` を値として直接組み立て、
`domain` の純粋関数だけで解決結果を確認する。セッション起動も実 WSL も伴わない。

**Acceptance Scenarios**:

1. **Given** 所在 `windows` の `C:\dev\closta`、**When** 実行中の `WslRuntime` で解決する、
   **Then** `/mnt/c/dev/closta` が得られ、**越境**として明示される
2. **Given** 同じフォルダ、**When** `Win32Runtime` で解決する、**Then** 恒等変換され越境しない
3. **Given** 所在 `wsl:<D>` の `/home/u/repo`、**When** 同じディストロで解決する、
   **Then** 恒等変換され越境しない
4. **Given** 所在 `wsl:<D>` の **`/mnt/c/dev/closta`** (当該ディストロの Windows マウント配下)、
   **When** 同じディストロで解決する、**Then** 実体が Windows 側のため**越境**として明示される
5. **Given** 所在 `wsl:<D>` のフォルダ、**When** ランタイムを選ぶ、
   **Then** `Win32Runtime` と別ディストロの `WslRuntime` は**到達不可**として選択肢に現れない
6. **Given** 登録フォルダと、**到達可能だが停止中**の `WslRuntime`、**When** 組み合わせ選択を開く、
   **Then** その組み合わせは**選択肢に現れ**、選ぶと変換後パスは示されず、
   「起動する」「再検出する」の解消手順が示される
7. **Given** 所在 `wsl:<A>` のフォルダと、**停止中の別ディストロ** `WslRuntime(<B>)`、
   **When** 組み合わせ選択を開く、**Then** **到達不可として選択肢に現れない**。
   起動を促してはならない — 起動しても到達不可のままである
8. **Given** 登録フォルダと、**実行中だが判定が未完了**の `WslRuntime`、
   **When** 組み合わせ選択を開く、**Then** その組み合わせは**選択肢に現れ**、
   判定の完了待ちであることと、パスがまだ示せないことが伝えられる
9. **Given** 案内を見た利用者、**When** 起動して再検出する、**Then** 同じ組み合わせが解決される
10. **Given** 解消手順を示された組み合わせだが、実際にはパスがそのランタイムのマッピングに無い、
    **When** 案内どおり起動して再検出する、**Then** 到達不可となり選択肢から消えるが、
    **消えた理由が提示される**。黙って消えない
11. **Given** 選択肢が 0 件になる (到達可能なランタイムが 1 件も無い / **登録フォルダが 0 件**)、
    **When** 組み合わせ画面を開く、**Then** 空白の画面にならず、
    理由と次に取るべき操作 (登録フォルダ 0 件なら登録画面への導線) が示される
12. **Given** マウント位置が既定と異なるディストロ、**When** 変換する、
    **Then** 実際のマウント位置に基づいて変換される
13. **Given** マウント位置が互いに前方一致する (`/mnt/c` と `/mnt/cdrom` など)、
    **When** 変換する、**Then** 誤って短いほうに一致させない
14. **Given** マッピングに現れないドライブ (ネットワークドライブ等) を所在 `windows` として
    登録したフォルダ、**When** `WslRuntime` と組み合わせる、**Then** **到達不可**として
    選択肢に現れず、理由が示される。**同じフォルダは `Win32Runtime` では恒等で解決される**
15. **Given** あるディストロのパスと**別のディストロ**のランタイム、**When** 変換する、
    **Then** 名前空間の不一致として**変換不能**が返る
16. **Given** 任意の組み合わせ、**When** 変換を往復させる、**Then** 元のパスに戻る
17. **Given** WSL 側フォルダのディレクトリを列挙する、**When** パスを UNC 形式に変換する、
    **Then** 逆変換で元のパスとディストロ名に戻る
18. **Given** 越境する組み合わせ、**When** 選ぶ、
    **Then** 選択は許可され、**(a) 想定される影響、(b) 推奨する配置先、(c) 取るべき手順**が案内される
    (アプリが clone / コピー / 移動を行うことはない)

### Edge Cases

- WSL 未インストール / WSL サービス停止 — `Win32Runtime` のみを提示し、エラー画面にしない。
  WSL 側の列挙失敗は**所在ごとの失敗**として扱う
- `wsl.exe` の出力が UTF-16LE / 改行が CRLF / ヘッダと状態文字列がロケールで翻訳される
- ディストロ名に空白・数字を含む (`My Distro` / `Ubuntu-26.04`)
- ディストロ名の変更・削除・重複 — 登録フォルダの所在が解決できなくなる
- 所在 `wsl:<D>` のフォルダが当該ディストロの Windows マウント配下にある — 越境として扱う
- マウント位置が既定でない / 互いに前方一致する
- ネットワークドライブ・UNC パスを所在 `windows` として登録する —
  `Win32Runtime` からは恒等で開けるが、マウントマッピングに現れないため
  `WslRuntime` との組み合わせは**到達不可**になる
- ドライブレターの大文字小文字 / シンボリックリンク
- UNC 経由のパスが Windows の長さ制限を超える
- 読み取り権限のないディレクトリ
- アプリの多重起動
- capability 判定が途中で失敗する / 出力が不完全 — **欠けた項目を「問題なし」と解釈しない**
- **ランタイムは実行中だが判定が未完了 / 失敗** — マッピングが無いため組み合わせを解決できない。
  起動直後と再検出中に必ず通る状態であり、例外経路として扱わない
- WSL のバージョン列挙だけが失敗する — WSL1 と WSL2 を区別できないため実地判定を行わない
- 実行状態のキャッシュと実体の乖離 — WSL2 はアイドルのディストロを自動停止する
- 永続化ファイルの破損 / 将来バージョンのスキーマ — 読めた分を復元し、件数を提示して元データを退避
- 空状態 — 登録フォルダ 0 件 / ランタイムが 1 種類のみ / 到達可能な組み合わせ 0 件。
  いずれも空白の画面にせず次の操作への導線を示す

## Requirements _(mandatory)_

### Functional Requirements

#### ランタイムの検出と capabilities

- **FR-001**: システムは起動時に利用可能なランタイムを走査しなければならない。
  ホストが Windows の場合、`Win32Runtime` 1 件とインストール済み WSL ディストロごとの
  `WslRuntime` を列挙する。ホスト OS の判定はランタイム実装の内側で行う
- **FR-002**: システムはディストロの**名前・バージョン・実行状態**を取得しなければならない。
  いずれの判定にも**ロケール依存の文字列一致を使ってはならない**
- **FR-003**: システムは `capabilities` を**表明**しなければならない。能力がないものを
  「ある」と表明してはならず、判定していないものを「ない」と表明してもならない
- **FR-004**: `Win32Runtime` と WSL1 ディストロは、実地テストを行わず
  sandbox なし / 無人実行不可を表明しなければならない
- **FR-005**: 実行中の WSL2 ディストロについて、システムは AD-015 §8 の実地判定を
  実施しなければならない。必須依存の存在確認では、**WSL interop により Windows 側 PATH から
  解決された実行ファイルを「存在する」と扱ってはならない**。この除外は**当該ディストロの
  マウントマッピングを基準に判定し、特定のマウント位置を決め打ちしてはならない** (FR-018 と同根)
- **FR-006**: システムは seccomp フィルタの状態を「あり / なし / 未判定」の 3 値で保持しなければならない。
  **R-1 では検出方法が未確定のため常に「未判定」を返す**
- **FR-007**: システムは**停止中のディストロを検出のために起動してはならない**。
  停止中は一覧に出しつつ未判定として扱い、**利用者がアプリ外で起動して再検出した時点で**判定する
- **FR-008**: 判定が完了していない、または結果が不明の間、システムはそのランタイムを
  無人実行不可と同等に安全側で扱わなければならない。この解釈は**単一の判定点**に閉じ込め、
  呼び出し側に生の値や再導出の素材を渡してはならない
- **FR-009**: システムは不足している必須依存の名前と、**導入手順を記載した文書への導線**を
  案内しなければならない。**アプリ自身がインストールを行ってはならない**
- **FR-010**: システムは検出結果をキャッシュし、**再検出はユーザの明示操作に限らなければならない**。
  ディストロに対する判定および WSL 側ファイルアクセスの前には実行状態を確認しなければならないが、
  **その確認の回数を、ディストロ数および利用者の操作回数に比例させてはならない**。
  これは**境界で強制する制約**であり、UI の作り方に委ねてはならない —
  再検出・判定・ブラウズ開始は同時実行を 1 本に束ね、追加要求は既存結果へ合流させる
- **FR-011**: キャッシュのキーにはランタイム識別子 (ディストロ名を含む) を使わなければならない
- **FR-012**: システムは WSL が利用できないホストでもエラーにならず動作を続けなければならない

#### 作業フォルダの登録

- **FR-013**: 利用者は**先に所在を選び**、そのうえでフォルダを指定できなければならない。
  登録フォルダが 0 件のときは空状態として導線を提示する
- **FR-014**: システムは登録された作業フォルダを所在つきで永続化し、再起動後も復元しなければならない
- **FR-015**: システムは WSL 側のファイルツリー列挙に `wsl.exe` を使ってはならない。
  UNC 経由とし、**実行中であることを確認済みのディストロに対してのみ**発行する。
  ブラウズはセッションを開く操作を入口とし、**所在 `windows` に対してこの入口を開いてはならない**。
  理由は経路の一本化である — ホスト側のフォルダ選択はネイティブダイアログ (FR-013 / FR-038) に
  統一し、ホスト用のブラウズ実装を持たない。**これはホストファイルシステムへの到達を
  塞ぐものではない** — 所在 `wsl:<D>` のブラウズは Windows マウント配下を辿れ、
  それは US-3 が越境として明示的に認めている経路である。
  **UNC 形式は `infra` の内側に閉じ、所在配下を列挙・登録・永続化する経路が渡すパスは
  所在の名前空間で表さなければならない** (組み合わせの解決結果が返すパスはランタイムの
  名前空間であり、この規則の対象外。[data-model.md](data-model.md) §8)
- **FR-016**: システムは同一の所在・同一パスのフォルダを重複登録してはならない。
  ドライブレターの大小差と末尾セパレータの有無は正規化後に同一とみなす
- **FR-017**: システムは**すべての登録エントリに登録解除の操作を提供し**、一覧上で各エントリの
  到達可能性を **FR-027 と同じ 3 値**で区別しなければならない。
  **解除を「勧める」表示 (推奨・強調・導線の優先提示) を出すのは「到達不可」のエントリだけ**とする。
  「一時的に解決不能」(所在ディストロが停止しているだけ等) には解消手順を示し、
  **解除を勧めてはならない**。ただし**操作そのものを到達可能性で制限してはならない** —
  越境の案内 (FR-031) は旧エントリの登録解除を手順に含み、越境するエントリは「到達可能」
  であるため、制限すると案内が実行不能な指示になる
- **FR-018**: システムは停止中のディストロを所在として選んだ場合、起動が必要である旨と
  **起動後に再検出する導線**を示さなければならない。**アプリが黙って起動してはならない**
- **FR-019**: 永続化ファイルは**スキーマ版**を持ち、パスを**名前空間つきで**保持しなければならない。
  所在とパスの名前空間 (**ディストロ名まで含む**) が食い違うレコードは復元しない。
  **復元できなかったファイル・レコードは上書き前に退避し、件数と理由を利用者に提示しなければならない**。
  永続化スキーマに秘密情報のフィールドを持ってはならない
- **FR-020**: アプリは**単一インスタンス**に制限しなければならない

#### パス変換と組み合わせの解決

- **FR-021**: システムはホスト・ランタイム内部・WSL への UNC 経路の 3 つの名前空間を
  型レベルで分離しなければならない。ランタイム名前空間のパスは**どのランタイムに属するかを
  実行時に保持**し、変換 API は入口で名前空間の一致を検証しなければならない
- **FR-022**: システムは名前空間間の変換を**両方向**で提供しなければならない
- **FR-023**: システムはパス変換のマッピングを、**実行中のディストロについて capability 判定と
  同じ 1 回の呼び出しで**取得し、以後の個々の変換はホスト側で計算しなければならない
- **FR-024**: システムはマウント位置を決め打ちしてはならない。マッピングは
  マウントオプションから導出し、設定による変更に追従しなければならない。
  **ファイルシステム種別でフィルタしてはならない**
- **FR-025**: システムはアプリケーションコードでのパス操作をすべて `domain` が公開する
  パス API 経由に限定しなければならない。パス操作の標準モジュールを直接 import してよいのは
  **このパス API の実装モジュール 1 つだけ**とする
- **FR-026**: システムは変換を**名前空間のペア**として表現し、多段変換を合成で表せる形に
  しなければならない
- **FR-027**: システムは到達可能性を **「到達可能」「到達不可」「一時的に解決不能」の 3 値**で
  判定しなければならない。3 つ目は「利用者が取るべき操作がある」状態を表す。
  **この 3 値は、組み合わせの解決結果と登録フォルダ一覧の双方で同じ意味で用いる** (FR-017)
- **FR-028**: システムは「到達不可」の組み合わせを選択肢に出してはならない。
  **「一時的に解決不能」は選択肢に出し、解消手順を 1 つ以上示さなければならない**。
  選択肢が 0 件になる場合は理由と次に取るべき操作を提示しなければならない。
  **利用者が解消手順を実行した結果「到達不可」に確定した組み合わせは、選択肢から消すと同時に
  その理由を提示しなければならない。黙って消してはならない** —
  変換材料は解消手順の実行後にしか得られないため、「起動して再検出せよ」と案内したうえで
  到達不可に落ちる列が必ず残る
- **FR-029**: システムは越境と到達可能性を、**到達可否 → 変換材料の有無 → 変換と越境**の
  順に判定しなければならない。**実行状態を到達可否より先に見てはならない** —
  起動しても到達不可のままの組み合わせに「起動して再検出せよ」と案内することになる。
  判定順序と表は [data-model.md](data-model.md) を正とする。
  所在が WSL であっても、パスが当該ディストロの Windows マウント配下にある場合は**越境**とする
- **FR-030**: システムは越境する組み合わせを**選択可能にしたまま**明示しなければならない
- **FR-031**: システムは越境時、**(a) 想定される影響、(b) 推奨する配置先、(c) 取るべき手順**を
  案内しなければならない。手順には推奨先への配置・新規登録・旧エントリの登録解除を含める。
  **アプリが clone / コピー / 移動を行ってはならない**
- **FR-032**: プラットフォーム分岐は `AgentRuntime` 実装の内側に閉じなければならない

#### プロジェクト基盤と依存規則の強制

- **FR-033**: プロジェクトの骨格は **electron-vite の公式 CLI** が生成するものを土台とし、
  ディレクトリ構成を手で作り替えてはならない。続けて **assistant-ui の公式 CLI** で
  design system を導入する。本 feature では chat 用の Element を採用しない
- **FR-034**: レイヤ構成は `app` / `ui` / `agents` / `infra` / `domain` の 5 レイヤとし、
  公式 scaffold からの**差分**として表現しなければならない
- **FR-035**: システムは AD-023 §7 の依存規則 (許可行列と禁止規則の全項目) を、
  **ただし `ui → domain` の範囲は AD-025 の定義 (型と副作用のない純粋関数まで) を採って**、
  **ESLint** (編集時・直接 import) と **dependency-cruiser** (推移的依存・循環・`require()` 形式) の
  **両方**で強制しなければならない。**`ui` から node builtin への推移的到達の禁止**を含む
- **FR-036**: Constitution Principle I / II / VII の検証を整備しなければならない。
  **Principle II の検証は識別子の直接参照だけでなく、等価な API と構文変形も対象とし、
  許可ディレクトリを実名で定義しなければならない**
- **FR-037**: Constitution Principle VI の検証を**許可リスト方式**で整備しなければならない。
  対象は (a) 特権コマンド文字列の不在 (Linux / Windows 両方)、(b) `wsl.exe` に渡す引数、
  (c) `wsl.exe` を名指せるモジュール、(d) docker CLI を名指せるモジュール、
  (e) 許可モジュール内での docker のイメージ構築サブコマンドの不在、
  (f) ディストロ内で実行するスクリプトの内容 (**内容の変更には ADR を要する**)、の 6 つとする。
  **検証スコープは `src/` と `scripts/` に加え、ビルド構成 (`package.json` の scripts /
  CI 定義 / パッケージング設定) を含めなければならない。除外はファイル単位の明示リストとし、
  ディレクトリ単位で除外してはならない。** 違反サンプル置き場はルール検証ランナーが展開する
  入力であり、通常検証のスコープ外とする
- **FR-038**: `electron` の import は `app` レイヤと `infra/secrets/` に限定しなければならない。
  Electron API を要する値と操作は、**`app` レイヤで解決して `infra` に引数として渡す**
- **FR-039**: renderer は `contextIsolation` / `sandbox` を有効に、`nodeIntegration` を無効にし、
  preload は**単一の capability** を公開しなければならない。
  **main 側は送信元とペイロードの双方を未信頼として検証しなければならない。**
  送信元の検証は「**配信元 origin の main frame** からの呼び出しである」ことの確認とし、
  不一致は応答せず破棄する (AD-023 のセキュリティ要件)。
  **許可する origin の集合は 1 つの定数に集約し、検証スクリプトの対象に含めなければならない。**
  開発ビルドが dev サーバから配信する場合はその origin を集合に含める —
  **送信元検証を環境で無効化する分岐を作ってはならない**。
  無効化の分岐は出荷物でも条件 1 つで外せる形になる
- **FR-040**: renderer は `file://` ではなく**アプリ内で登録したカスタムプロトコルで配信**し、
  **OS へのプロトコル関連付けを行ってはならない**。
  **プロトコルハンドラは、正規化後も同梱 renderer 出力ディレクトリ配下に収まる要求だけを
  解決しなければならない。** 親ディレクトリ参照とその符号化形を含め、外に出る要求は拒否する。
  **CSP は既定を `default-src 'none'` とし、スクリプト・スタイルを自己オリジンに、
  画像を自己オリジンと `data:` に限り、`connect-src` / `object-src` / `frame-ancestors` /
  `base-uri` を封じなければならない。`unsafe-inline` / `unsafe-eval` を含めてはならない。**
  「絞る」とだけ書くと、満たしたまま防御効果を 0 にできる。
  **開発ビルドでは dev サーバの origin と HMR に要する接続先を directive に加える。
  `unsafe-eval` は両環境で禁じる。`unsafe-inline` は開発ビルドの `script-src` /
  `style-src` に限り許す** — `@vitejs/plugin-react` の React Refresh preamble と
  Vite client がインライン script / style を使うため、禁じると開発ビルドで
  `can't detect preamble` となりアプリが起動しない (R-1 実装時に実測)。
  公式の dev フロー (AD-023 が土台とするもの) と両立しない要求は置かない。
  **緩和は CSP を組み立てる 1 関数の dev 分岐にのみ現れ、ゲートは `app.isPackaged` とする**
  — 環境変数で判定すると出荷物でも環境変数 1 つで有効化できる。
  開発用の CSP 定義も検証スクリプトの走査対象に含め、除外リストへ移してはならない。
  **`window.open` と外部 URL へのトップレベル遷移を拒否しなければならない** —
  CSP の `frame-ancestors` / `base-uri` はこれを覆わない (AD-023 のチェックリスト項目)
- **FR-041**: プロセス起動は特定のモジュールに限定しなければならない。`wsl.exe` を名指せるモジュールと
  プロセス起動 API を使えるモジュールを**許可リストで管理**し、その外からの起動を検証で止める。
  許可リストの正本は検証スクリプト内の定数とし、**追加には ADR を要する**
- **FR-042**: 配布メタデータは AD-023 の「公開 ID と配布メタデータ」に従わなければならない
- **FR-043**: インストーラ生成を 1 回通し、ネイティブバイナリの asar 展開に致命的な非互換が
  ないことを確認しなければならない (SPIKE-13 の第 1 段階)

#### 体裁とドキュメント

- **FR-044**: README は**全文英語**とし、現在の実装 status を明示しなければならない。
  未実装の機能を実装済みであるかのように記述してはならない
- **FR-045**: リポジトリルートに **MIT License** の `LICENSE` を置き、`package.json` と一致させる
- **FR-046**: 本 feature で導入・変更する用語を `docs/glossary.md` に反映しなければならない
- **FR-047**: UI のラベル・メッセージは日本語を第一言語とし、内部識別子をそのまま提示してはならない
- **FR-048**: 本 feature は **sandbox の必須依存の導入手順を記載した文書**を作成しなければならない。
  FR-009 の導線はこの文書を指す。文書は `src/` の外に置く

### Key Entities

- **WorkspaceFolder (作業フォルダ)**: 所在・パス・表示名・到達可能性 (**3 値**)・登録日時を持つ。
  所在は登録時に明示的に選ばれ、パス文字列から推測されない
- **Location (所在)**: 作業フォルダがどのファイルシステム名前空間に属するかを表す値
- **RuntimeDescriptor**: 検出結果から生成されるランタイムの**値** (データ)。
  識別子・種別・ディストロ名・WSL バージョン・実行状態・`capabilities`・マッピング・検出時刻
- **AgentRuntime**: `RuntimeDescriptor` にパス API を束ねたインタフェース。
  起動契約は本 feature に含まない (X-1 で追加する)
- **Capabilities**: 判定の進行状態・sandbox の種別・無人実行の可否・seccomp の状態・
  不足依存の一覧と導線・判定時刻
- **HostPath / RuntimePath / WslUncPath**: 3 つのパス名前空間。
  `RuntimePath` と `WslUncPath` は**どのディストロのものかを実行時に保持する**
- **PathMapping**: 2 つの名前空間のあいだの対応
- **FolderRuntimeResolution**: 組み合わせの解決結果。到達可能性 (3 値)・理由・越境・
  変換後パス・越境時の推奨案内・解消手順

## Success Criteria _(mandatory)_

- **SC-001**: パス変換テストが **100% 通過**する。往復不変 / UNC 往復 / ドライブレターの大小非依存 /
  末尾セパレータ非依存 / 非既定のマウント位置 / マッピングに無い接頭辞で変換不能 /
  接頭辞が互いに前方一致するマウント位置の共存 / 別名前空間のパスで変換不能 /
  別ディストロの UNC 値で変換不能 / `Win32Runtime` の恒等変換 /
  **バックスラッシュを含む POSIX 値で変換不能** /
  2 つのマッピングの合成が逐次適用と一致 を含む (charter KPI。計測経路: Vitest)
- **SC-002**: ホストに存在する WSL ディストロを取りこぼさない。一覧が `wsl -l -v` と 1 対 1 で一致する。
  **文字種制約を満たさない名前は「列挙不能」として理由つきに提示され、この 1 対 1 の対象に含まれる**
  (黙って落とさない)。
  名前に空白・数字を含むディストロを含む (charter KPI の WSL 部分。docker endpoint 部分は I-1)
- **SC-003**: `capabilities` の表明が、同一ホストで手動実行した AD-015 §8 の判定結果と**一致**する。
  `Win32Runtime` の固定値、必須依存がマウント配下にのみ解決される環境 (既定・非既定の
  マウント位置の両方)、判定出力が不完全な場合を含む (charter KPI。計測経路: Vitest + quickstart)
- **SC-004**: ランタイム一覧の初回描画が **3 秒以内** (`ready-to-show` 起点)。
  capability 判定バッチ全体が **4 秒以内**。キャッシュヒット時の再表示が **100 ミリ秒以内**。
  **フォルダブラウザの階層移動が 300 ミリ秒以内** (ただし**ブラウズセッションの有効期間を
  またぐ 1 手を除く** — 実行状態の再確認を伴うため 2 秒以内とする)。
  計測経路: 開発ビルドが出力する計測ログの値で判定する
- **SC-005**: 検出・一覧表示・フォルダ選択・組み合わせ解決のいずれにおいても、
  **アプリが停止中のディストロに対して起動を伴う操作を発行することが 0 件**である。
  計測経路: 検証前後の `wsl -l -v` の比較 + 停止中ディストロの識別子で IPC を直接呼んで拒否されること
  - ブラウズセッションの有効期間内に実体を停止させて階層移動したときの挙動の記録。
    **有効期間内に実体が停止した場合は残余として扱う** — 実行状態の確認をキャッシュする以上、
    確認から操作までの窓は消せない ([data-model.md](data-model.md) §5)。
    「0 件」を発行側の行為で定義するのは、**保証できないものを保証すると書かない**ためである
- **SC-006**: 越境と判定された組み合わせについて、**例外なく**影響・推奨配置先・手順が提示される。
  計測経路: 解決関数のユニットテスト + preload をスタブした renderer 単体テスト
- **SC-007**: 登録済みフォルダ × 検出済みランタイムの**全組み合わせ**について、
  **「到達不可」のものが選択肢に現れる件数が 0 件**であり、
  **「一時的に解決不能」のものは選択肢に現れて解消手順を伴う**。
  計測経路: 解決表の全セルを網羅するユニットテスト + renderer 単体テスト
- **SC-008**: 違反サンプル群 (a) **ルールが直接見ている形**のすべてが検出される (全数検出)。
  加えて、**US-4 の Acceptance Scenario が「止まる」と明記する経路は、群 (a) / (b) の別を問わず
  すべて全数検出される**。AC-1 〜 AC-11 が名指す経路すべてがこれにあたり、いずれも
  SH-011 〜 SH-014 と型検査が実装対象としているため未検出を許容しない。
  **該当する AC を 3 つだけ列挙する形にしない** — 列挙すると、同じ構造を持つ残りが
  拘束を外れて「未検出でも記録すれば可」の側に落ちる
- **SC-009**: 規則に適合した状態のコードベースに対し、lint・型検査・依存グラフ検証・
  Principle 検証スクリプトを実行して**違反 0 件**で完了する。違反サンプルを保持したまま満たす
- **SC-010**: インストーラ生成が**エラーなく 1 回完走**し、生成物にネイティブバイナリが
  展開された状態で含まれる
- **SC-011**: UTF-16LE 出力・CRLF 終端・翻訳済みヘッダ・空白を含むディストロ名が
  文字化けや切れなく扱われ、日本語・非 ASCII を含むフォルダ名とディストロ名が
  **UI 上でそのまま表示される** (計測経路: Vitest のフィクスチャ + quickstart)
- **SC-012**: `README.md` が (a) 1 行要約、(b) 現在の実装 status、(c) ライセンス表記 の 3 節を持ち、
  未実装機能が実装済みとして記述された箇所が **0 件**。`LICENSE` が MIT 全文と著作権者・年を含み
  `package.json` と一致する
- **SC-013**: 登録フォルダの復元が **100%**、重複登録が **0 件**、永続化ファイルの破損・
  スキーマ版不一致・名前空間不一致のいずれでも**起動失敗 0 件**で、
  **復元できなかった件数と理由が画面上に描画され**、元データが退避される
  (計測経路: Vitest + renderer 単体テスト + quickstart)
- **SC-014**: アプリを 2 回起動したとき、2 つ目が既存ウィンドウに合流し、
  **永続化ファイルの更新時刻が変化しない**
- **SC-015**: WSL が利用できないホスト条件で起動したとき、例外が **0 件**で
  `Win32Runtime` 1 件が現れ、WSL が見つからない旨が提示される
  (計測経路: プロセス起動レイヤを差し替えた Vitest + renderer 単体テスト)
- **SC-016**: renderer が `file://` 以外のプロトコルで配信される。**CSP が FR-040 の directive を
  満たし、`unsafe-eval` をどちらの環境でも含まず、`unsafe-inline` が
  開発ビルドの `script-src` / `style-src` 以外に現れない**。**プロトコルハンドラが同梱ディレクトリ外への
  要求 (符号化された形を含む) を拒否する**。OS へのプロトコル関連付け API の呼び出しが **0 件**。
  **`window.open` と外部 URL へのトップレベル遷移が拒否される。**
  計測経路: CSP (**directive 集合を満たすことと禁止形の不在の両方**) と関連付け API と
  ナビゲーション拒否は**検証スクリプトの項目**、ハンドラの封じ込めは**ハンドラ単体テスト**、
  配信プロトコルは開発者ツールでの確認。
  **開発ビルドとパッケージ済みビルドの双方で満たすこと**
- **SC-017**: 違反サンプル群 (b) **等価経路**のうち **SC-008 が全数検出を求めるものを除いた**
  ものについて、検出 / 未検出の一覧が記録され、未検出のものには次に塞ぐ feature ID が
  割り当てられている。サンプルは破棄しない
- **SC-018**: **IPC の未信頼入力検証表の各行**について、不正入力が拒否されることが示される。
  行を 3 つだけ列挙する形にしない — 列挙すると同じ構造の残りが拘束を外れる。
  計測経路: preload をスタブせず **main 側ハンドラを直接呼ぶ**ユニットテスト。
  最低でも送信元不一致 / 期限切れトークン / 他送信元のトークン /
  `unc:<D>` を `wsl:<D>` として渡す / バックスラッシュを含む POSIX 値 /
  未検出 descriptor の所在 / 所在 `windows` への `beginBrowse` を含む

## Assumptions

`[USER]` は起案時に人間が確定したもの、`[ASSUMED]` は本 spec で自動採用したもの。

- **[USER]** 導線は「所在を先に選ぶ」形にする。越境判定は所在とランタイムとマッピングで
  構造的に決まり、実測は行わない
- **[USER]** 停止中のディストロは検出のために起動しない
- **[USER]** sandbox capability の実地判定は R-1 に含める
- **[ASSUMED]** 所在が WSL のフォルダは `Win32Runtime` から到達不可として扱う。
  UNC パスを cwd とするネイティブ Windows プロセス起動は AD-015 で検証されていない
- **[ASSUMED]** 越境の閾値 (フォルダサイズ等) は設けない
- **[ASSUMED]** 登録フォルダの永続化は設定ファイル (JSON)。SQLite は R-2 以降
- **[ASSUMED]** 検出キャッシュはアプリプロセスの寿命とし、ディスクに永続化しない
- **[ASSUMED]** 所在 `windows` の登録パスは **renderer の主張をそのまま受理する**。
  ピッカー由来であることは要求しない。到達可能性の実在確認を**登録済みエントリに限る**ことで、
  任意パスの存在を問い合わせる経路を作らない
- **[ASSUMED]** 実行状態の確認をキャッシュする以上、確認から操作までの窓は消せない。
  **SC-005 はアプリ側の発行行為で測り、窓の内側は残余として受け入れる**
- **[ASSUMED]** ランタイム名前空間の弁別は型ではなく実行時検証で行う。
  名前空間識別子は実行時に決まる値であり、静的な型として扱えない
- **[ASSUMED]** SC-004 の 3 秒は Electron 自身の起動時間を含まない
- **[ASSUMED]** CI ランナーは Windows を基準とする
- **[ASSUMED]** LICENSE の著作権者は `ukitomato`、年は 2026
- **[ASSUMED]** 本 feature で解消するのは Constitution 未解決 Principle 候補 #2 の
  「自プロジェクトの LICENSE」部分のみ。第三者依存の NOTICE は D-1
- **[ASSUMED]** リポジトリの public 化は D-1 で行う
- **[ASSUMED]** Agent SDK は依存として入れるが本 feature では呼び出さない
- **[ASSUMED]** 本 feature の UI は 3 画面。transcript 表示は R-3
- **[ASSUMED]** capability 判定は非同期に行い、一覧提示をブロックしない
- **[ASSUMED]** `ui` から `domain` へは型と副作用のない純粋関数まで許す。
  ただし node builtin に到達するモジュールには到達させない (AD-025 に記録)

## Out of Scope

- `capabilities` を**使って**権限モードを制限すること → `isolation` (I-3)。
  本 feature の判定点は**未確定値の安全側解釈**であってゲートではない
- **`AgentRuntime` の起動契約 (argv 構築・プロセス起動)** → `session` (X-1)
- `DockerRuntime` と **docker endpoint の検出** → `isolation` (I-1)。
  `runtime` charter の In scope に残る記述は本 feature で `isolation` 側へ移す
- **ディストロの起動 / 停止の継続的な「検知」** → R-1 では行わない。
  再検出はユーザの明示操作に限り、操作直前の実行状態確認で代替する
- **seccomp フィルタの検出方法の確定** → I-3
- **`capabilities` の鮮度管理 (再判定の要否判断)** → `isolation` (I-3)。
  R-1 のキャッシュはアプリプロセスの寿命で有効とし、再判定は利用者の明示操作に限る。
  無人実行のゲートを持つ I-3 が鮮度の要件を決める
- `DirectRuntime` (macOS / Linux ホスト) → OPT-mac
- セッションの列挙・起動・監視、ディストロ内の `claude` 実行パス解決 → `session`
- transcript の表示、会話 UI の Element → `ui` (R-3)
- Provider・認証・環境変数の導出 → `provider` (X-3)
- 署名つきインストーラの配布、自動更新、第三者依存の NOTICE → D-1
- WSL ディストロの作成、Docker イメージのビルド、sandbox 依存パッケージの導入 → **非目標**
- 越境時の実測ベンチマークと閾値判定 → 実データが揃ってから再検討
