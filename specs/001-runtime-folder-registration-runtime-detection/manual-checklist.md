# 手動確認の手順 (SH-048 の残り)

`quickstart.md` のうち**画面操作が必要な項目**だけを、実際のボタン名と順序で並べたもの。
結果は [quickstart-results.md](quickstart-results.md) に追記する。

**この順序で行う理由**: WSL の実行状態を行き来させる回数を最小にしてある。
順序を崩すと「停止中のディストロを使う手順」と「実行中のディストロを使う手順」で
同じディストロを何度も起動・停止することになる。

---

## 0. 準備

### 0-1. ディストロの役
（役を固定する。どれを触ってよいかが曖昧だと SC-005 の判定が濁る）

| ディストロ | 役 |
|---|---|
| `Ubuntu-26.04` | **触らない**。実行中のまま。既定ディストロ |
| `Ubuntu-22.04` | **試験台**。起動・停止を繰り返す |
| `podman-machine-default` | **絶対に触らない**。停止中のまま。これが最後まで `Stopped` なら SC-005 の証拠になる |
| `wsl-vpnkit` | 触らない |

### 0-2. 開始状態を作る

```powershell
wsl --terminate Ubuntu-22.04
wsl -l -v          # ← この出力を控える。最後に突き合わせる
```

`Ubuntu-22.04` と `podman-machine-default` が `Stopped`、
`Ubuntu-26.04` が `Running` になっていること。

### 0-3. 確認用のフォルダを作る

日本語と空白を含む Windows フォルダ、WSL 側のフォルダ、読み取り権限のないディレクトリ。

```powershell
# 日本語 + 空白を含む Windows フォルダ
New-Item -ItemType Directory -Force "$env:USERPROFILE\closta-verify\確認用 フォルダ 日本語" | Out-Null
```

WSL 側は `Ubuntu-26.04` に作る（試験台ではない方。停止させないので途中で消えない）。

```powershell
wsl -d Ubuntu-26.04 -- sh -c 'mkdir -p "$HOME/closta-verify/深い/階層/の/確認"'
wsl -d Ubuntu-26.04 -- sh -c 'mkdir -p "$HOME/closta-verify/no-read" && chmod 000 "$HOME/closta-verify/no-read"'
```

**権限のないディレクトリは WSL 側に作る。** 所在 `windows` の入口は
ネイティブダイアログだけであり、フォルダブラウザを通らないので
`permission-denied` の経路に入らない。辿る操作があるのは WSL 側だけである。

> 後片付けは一番下の「9. 後片付け」にまとめてある。

### 0-4. アプリを起動する

```powershell
pnpm dev
```

**SC-004 を測るのは 2 回目の起動である。** 1 回目は Vite の依存再最適化と競合して
同じコードでも超過する（実測で `probe-batch` が 8,977ms → 3,667ms に変わった）。
**依存を変えていなければ 1 回目でよい。**

ターミナルの `[measure]` 行を見える位置に置いておく。

## 1. V-1 の残り — ランタイム一覧

起動直後に開いている「**ランタイム**」タブ。

### 1-1. 一覧の内容 (SC-002 / SC-011)

- [ ] `Windows (ホスト)` が 1 件ある
- [ ] `WSL: <名前>` が `wsl -l -v` のディストロと **1 対 1** で並ぶ（数も名前も）
- [ ] `Ubuntu-26.04` の「**WSL バージョン**」が **2** と出る
      → **`26` と出たら SC-011 の不合格**（行内の最初の数値を採っている）
- [ ] 既定ディストロに `(既定)` が付く
- [ ] 文字化けが無い。名前が途中で切れていない

### 1-2. capabilities (SC-003)

`Windows (ホスト)` のカード:

- [ ] 「隔離機構」= `なし`
- [ ] 「無人実行」= `不可`
- [ ] 「判定」が `判定中` のまま止まっていない（固定値経路なので即 `判定済み`）

`WSL: Ubuntu-26.04`（実行中・WSL2）のカード:

- [ ] 「判定」が `判定中` → `判定済み` に変わる
- [ ] 「隔離機構」に `bubblewrap` または `なし` が出る
- [ ] 「**seccomp**」が `あり` / `なし` / `未判定` のどれかで、**`未判定` と `なし` が別の語になっている**
      → 同じ語なら SC-003 の不合格
- [ ] 不足依存があれば「不足している必須依存」に**名前**と
      `docs/runtime/wsl-sandbox-dependencies.md#bubblewrap` のような**導線**が出る
- [ ] **その導線に `apt install` のようなコマンド文字列が無い**（FR-009）

`WSL: Ubuntu-22.04`（停止中）のカード:

- [ ] 「実行状態」= `停止中`、「判定」= `未判定`
- [ ] 「無人実行」= `未判定`（`不可` に潰れていない）

### 1-3. 停止中を起動していないこと (SC-005) — その 1

別のターミナルで:

```powershell
wsl -l -v
```

- [ ] 0-2 で控えた出力と**完全に一致**する

### 1-4. 停止中を起動していないこと (SC-005) — その 2

アプリのウィンドウで **F12** を押して DevTools を開き、Console に貼る
（`optimizer.watchWindowShortcuts` が開発ビルドで F12 を割り当てている。
効かなければ Alt でメニューを出して View → Toggle Developer Tools）:

```js
await window.closta.probeRuntime('wsl:Ubuntu-22.04')
await window.closta.probeRuntime('wsl:podman-machine-default')
await window.closta.beginBrowse({ kind: 'wsl', distroName: 'Ubuntu-22.04' })
await window.closta.beginBrowse({ kind: 'podman-machine-default' })
await window.closta.beginBrowse({ kind: 'windows' })
```

- [ ] 上の 3 つが `{ error: 'distro-not-running' }` を返す
- [ ] 4 つ目（`kind` が不正）が拒否される
- [ ] 5 つ目が `unsupported-location` を返す（Windows の入口はピッカーだけ）
- [ ] **叩いたあとに `wsl -l -v` が変わらない**

### 1-5. キャッシュと再検出 (SC-004 / SC-003)

- [ ] 「作業フォルダ」タブに移り、「ランタイム」に戻る
      → ログに `list-runtimes-cached ... (ok)` が出て **100ms 未満**
- [ ] 「**再検出**」を押す → 一覧が更新される
- [ ] 判定済みだったディストロの再判定中、「無人実行」が **`可` のまま残らない**
      （`未判定` に戻ってから確定する）

### 1-6. V-6 の残り — 配信プロトコル (SC-016)

DevTools の Console で:

```js

```

- [ ] `file:` **ではない**（開発ビルドなら `http:`、パッケージ済みなら `app:`）

## 2. V-2 — フォルダ登録

「**作業フォルダ**」タブ。

### 2-1. 空状態 (FR-028)

登録 0 件の状態で開く（初回起動なら自動的にこの状態）。

- [ ] 空白の画面にならず、登録への導線が出る

### 2-2. Windows フォルダを登録する

- [ ] 「**Windows のフォルダを選ぶ…**」を押す → **OS のネイティブダイアログ**が開く
- [ ] `%USERPROFILE%\closta-verify\確認用 フォルダ 日本語` を選ぶ
- [ ] 一覧に**日本語のフォルダ名がそのまま**出る（SC-011）

### 2-3. WSL フォルダを登録する

- [ ] 「`WSL: Ubuntu-26.04`」のボタンを押す → ブラウザが開く
- [ ] 「親へ」「ルートへ」と項目クリックで **3 階層以上**下りる
      （`$HOME/closta-verify/深い/階層/の/確認` まで）
- [ ] ログの `browse-step` が毎回 **300ms 未満**（SC-004）
- [ ] 「**ここを登録する**」を押す → 一覧に出る

### 2-4. 重複登録 (SC-013)

- [ ] 同じフォルダをもう一度登録しようとする
- [ ] **増えない**。既存エントリが選択状態になる

### 2-5. 権限のないディレクトリを辿る

- [ ] 「`WSL: Ubuntu-26.04`」でブラウザを開き、`closta-verify` まで下りる
- [ ] `no-read` を選ぶ
- [ ] 「**このフォルダを読む権限がありません**」と出る
- [ ] **アプリが落ちない**。前の階層に戻れる

### 2-6. 有効期間をまたぐ 1 手 (SC-004 / SC-005)

- [ ] 「`WSL: Ubuntu-26.04`」でブラウザを開き、2〜3 階層下りる
- [ ] **そのまま 35 秒以上放置する**（有効期間は 30 秒）
- [ ] 別のターミナルで `wsl -l -v` を控える
- [ ] 画面で 1 階層移動する
- [ ] 「選択の有効期間が切れました」等の扱いになる
- [ ] `wsl -l -v` が**変わっていない**
- [ ] **同じ位置から続行できる**（ルートに戻されていない）
- [ ] ログの `browse-step-revalidate` が **2,000ms 未満**

### 2-7. 停止中ディストロの導線 (FR-018 / SC-005)

- [ ] 「`WSL: Ubuntu-22.04` **(停止中)**」のボタンが**押せない**状態になっている
- [ ] 「停止中のディストロは辿れません」と、
      `ディストロを起動する` → `ランタイムを再検出する` の手順が出る
- [ ] `wsl -l -v` が変わっていない（表示だけで起動していない）

次に、アプリの**外**で起動する:

```powershell
wsl -d Ubuntu-22.04 -- true
wsl -l -v          # Ubuntu-22.04 が Running
```

- [ ] 画面の「**ランタイムを再検出**」を押す
- [ ] `WSL: Ubuntu-22.04` のボタンが押せるようになり、ブラウザが開ける
- [ ] ついでに `Ubuntu-22.04` 側にフォルダを 1 件登録しておく（2-11 で使う）

### 2-8. 有効期間**内**に停止した場合の記録（残余。合否を判定しない）

**ここは「起動が起きても不合格としない」区間である**（data-model §5）。
実行状態の確認をキャッシュする以上、確認から操作までの窓は消せない。
**消せないものを「0 件」と書かない**ために、挙動を観察して記録するだけにしてある。

試験台は `Ubuntu-22.04`（2-7 で起動済み）を使う。`Ubuntu-26.04` は停止させない。

- [ ] 「`WSL: Ubuntu-22.04`」でブラウザを開き、1 階層下りる
- [ ] **30 秒経つ前に**別のターミナルで `wsl --terminate Ubuntu-22.04`
- [ ] すぐに画面で 1 階層移動する
- [ ] 起きたことを**そのままの文言で**書き留める
      （エラーが出たか / 空になったか / 再起動が起きたか）
- [ ] `wsl -l -v` を控える。**`Running` に戻っていても不合格としない**

### 2-9. 再起動での復元 (SC-013 / SC-014)

- [ ] `pnpm dev` を Ctrl+C で止め、もう一度起動する
- [ ] 登録内容が**すべて**復元される
- [ ] 永続化ファイルの更新時刻を控える:

```powershell
Get-Item "$env:APPDATA\closta\workspace-folders.json" | Select-Object LastWriteTime
```

- [ ] アプリが起動している状態で**もう一度** `pnpm dev` を別ターミナルで実行する
- [ ] **既存ウィンドウに合流する**（2 つ目のウィンドウが出ない）
- [ ] 上のファイルの `LastWriteTime` が**変わっていない**（SC-014）

### 2-10. 到達不可と登録解除 (SC-013 / FR-017)

- [ ] エクスプローラで `確認用 フォルダ 日本語` を**リネーム**する
- [ ] 一覧で「**使えない**」として区別され、
      「— 登録の解除をおすすめします。」が付く
- [ ] 「**登録を解除**」を押す → 一覧から消える
- [ ] **到達可能なエントリにも「登録を解除」が出ている**
      （出ていないと越境案内の手順が実行できない）

### 2-11. 所在 WSL のフォルダを残して停止させる (FR-017 / SC-005)

- [ ] `Ubuntu-22.04` に 1 件登録されていること（2-7 の最後で登録した分）
- [ ] `wsl --terminate Ubuntu-22.04`
- [ ] 一覧を開く → 「**今は使えない**」として**「使えない」と区別**される
- [ ] `ディストロを起動する` / `ランタイムを再検出する` の導線が出る
- [ ] **解除を勧められないが、「登録を解除」自体は押せる**
- [ ] **この間 `wsl -l -v` が変わらない**（一覧表示が所在ディストロを起動しない）

### 2-12. 永続化ファイルの破損 (SC-013)

アプリを終了してから、3 通りを**1 つずつ**試す（毎回起動して確認 → 次へ）。

```powershell
$f = "$env:APPDATA\closta\workspace-folders.json"
Copy-Item $f "$f.keep"      # 元を退避

# (a) JSON として壊す
'{ "broken"' | Set-Content $f

# (b) スキーマ版を未知の値にする (キーは `schemaVersion`)
Copy-Item "$f.keep" $f
(Get-Content $f -Raw) -replace '"schemaVersion":\s*\d+', '"schemaVersion":999' | Set-Content $f -NoNewline

# (c) 所在の種別は合っているがディストロ名が違う
#     → 所在 `wsl:Ubuntu-nonexistent` に POSIX パスが載った、名前空間の食い違いになる
Copy-Item "$f.keep" $f
(Get-Content $f -Raw) -replace 'Ubuntu-26\.04', 'Ubuntu-nonexistent' | Set-Content $f -NoNewline
```

各回:

- [ ] アプリが**起動する**
- [ ] **復元できなかった件数と理由が画面に出る**
- [ ] 退避ファイル (`workspace-folders.json.<時刻>.bak`) が生成されている

最後に元へ戻す:

```powershell
Copy-Item "$f.keep" $f -Force; Remove-Item "$f.keep"
```

## 3. V-3 — 組み合わせの解決

「**組み合わせ**」タブ。表の各行を確かめる。

### 3-1. 空状態 (FR-028)

- [ ] 登録 0 件で開く → 「登録された作業フォルダがありません。」と
      「作業フォルダ」画面への導線が出る

### 3-2. 解決表

前提として、次を登録しておく:

| # | 所在 | パス |
|---|---|---|
| A | Windows | `C:\dev\closta` |
| B | `wsl:Ubuntu-26.04` | `$HOME/closta-verify/深い` |
| C | `wsl:Ubuntu-26.04` | `/mnt/c/dev/closta` |

`Ubuntu-22.04` は**停止中**にしておく。

- [ ] A × `Windows (ホスト)` → パスが `C:\dev\closta` のまま（恒等）。
      バッジが `同じファイルシステム`
- [ ] A × `WSL: Ubuntu-26.04` → パスが `/mnt/c/dev/closta`。
      バッジが **`ファイルシステムをまたぐ`**。案内に
      **影響・推奨配置先・手順**の 3 点が出る。手順に**元の登録の解除**が含まれる
- [ ] A × `WSL: Ubuntu-26.04` の行が「**選べる**」（`今は選べない` になっていない）— FR-030
- [ ] B × `WSL: Ubuntu-26.04` → 恒等。`同じファイルシステム`
- [ ] C × `WSL: Ubuntu-26.04` → **`ファイルシステムをまたぐ`**（所在が WSL でも
      Windows マウント配下なら越境）
- [ ] B × `Windows (ホスト)` → **選択肢に現れない**。下の「使えない組み合わせ」に
      理由が出る（SC-007）
- [ ] B × `WSL: Ubuntu-22.04`（停止中の別ディストロ）→ **選択肢に現れない**。
      **起動を促されない**
- [ ] A × `WSL: Ubuntu-22.04`（停止中。C: はマッピングに載る）→ **選択肢に現れ**、
      パスは示されず `ディストロを起動する` / `ランタイムを再検出する` が出る
- [ ] 到達不可の説明が `foreign-distro` のような**内部識別子のままでない**（FR-047）

### 3-3. 判定未完了の区別 (SC-007)

- [ ] `Ubuntu-22.04` をアプリ外で起動し、「ランタイム」で「再検出」
- [ ] 判定が終わる**前に**「組み合わせ」を開く
- [ ] A × `WSL: Ubuntu-22.04` が**選択肢に現れ**、
      「ランタイムを調べている最中です」と出る

### 3-4. `blocked` → `unreachable` の確定 (SC-007)

- [ ] マッピングに**載らない**ドライブのフォルダを登録する
      （ネットワークドライブか、WSL にマウントされていないドライブ）
- [ ] 停止中のディストロとの組み合わせが**一度は選択肢に現れる**
- [ ] 案内どおり起動して再検出する
- [ ] **選択肢から消え、消えた理由が「使えない組み合わせ」に出る**
      → 黙って消えたら不合格

### 3-5. 所在のディストロだけを停止した場合 (FR-028)

- [ ] 所在 `wsl:<D>` のフォルダだけを残して `<D>` を停止する
- [ ] 「組み合わせ」を開く → **空白にならず、理由と次の操作が出る**
