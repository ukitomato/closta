#### `pnpm test:rules` の連続実行と所要時間 (2026-09-16)

AD-027 の Consequences は「1 件ずつに分けた直後の初回実行で 5 件の不一致が出たが、
再実行では 21 件すべて一致し**再現しなかった**」「初回実行時は診断出力が無かったため
事後に切り分けられない」と記録している。**非決定性が残っていないことを連続 3 回で確かめた**
(pr-gate Round 2 / po H-101 の推奨)。

| 実行 | exit | 結果 | 所要 |
|---|---|---|---|
| run#1 | 0 | 期待表と一致: **21 件** | 261.9s |
| run#2 | 0 | 期待表と一致: **21 件** | 208.9s |
| run#3 | 0 | 期待表と一致: **21 件** | 330.2s |

**3 回とも 21/21 一致。不一致は再現しなかった。**

**所要時間は 209〜330 秒 (平均 約 267 秒)。** AD-027 の Consequences が
「所要時間が伸びる。検証回数が 20 倍になる。CI の所要時間に直接乗る」と認めた点の実測値である
(SC-004 は CI 時間の予算を持たないため SC 違反ではない)。
**ばらつきが 58% あることを記録する** — 1 イテレーションあたり最大 5 プロセスを `npx` 経由で
起動する構成 (pr-gate Round 2 / architecture M-204) がその供給源として指摘されている。
AD-027 の Alternatives が置いた移行判断「所要時間が問題になった時点で機械可読出力へ移る」の
基準値として、**この 267 秒を出発点とする**。

なお `run.mjs` は各検出器の `exit:<code>/<bytes>` を進捗行に出すため、
次に不一致が出たときは「検出器が走って何も言わなかった」と
「起動に失敗して出力が空だった」を事後に切り分けられる (AD-027 決定 3)。

### V-6 で見つけた欠落と、その過程で見つけた弱点

**(1) ハンドラ単体テストが存在しなかった。**
SC-016 は「同梱ディレクトリ外への要求 (親ディレクトリ参照とその符号化形) が拒否される」ことを
求めているが、`src/main/app/protocol.test.ts` が無かった。作成した (29 ケース)。

**(2) 書いてみたら `isValidSegment` が `:` を通していた。**

`app://bundle/index.html:$DATA` と `app://bundle/C:/Windows/...` が解決されていた。
接頭辞照合 (`startsWith`) は成立するのに、**パスが指すものが同梱ファイルではなくなる** —
`index.html:stream` は NTFS の代替データストリームを、`C:` はドライブ相対を指す。
**封じ込めを接頭辞だけで守ろうとすると漏れる。**

`isValidHostSegment` を追加し、Windows のファイル名で使えない文字 (`:` `<` `>` `"` `|` `?` `*`) を
拒否した。**ホスト名前空間に限る** — POSIX のファイル名は `:` を含めてよいので、
共通の `isValidSegment` で弾くと正当な名前を拒否することになる。

**(3) 自分が書いたテストの期待が 7 件間違っていた。**

`app://bundle/../main/index.js` などは、**WHATWG URL がセグメントを畳んでから**
ハンドラに届く (`pathname` は `/main/index.js`)。同梱ディレクトリ配下を指しており脱出ではない。
「拒否されるはず」と書くのは実装ではなく URL パーサの挙動を試していることになるので、
**畳まれた結果が必ず配下に収まること**を確認する形に改めた。

脱出の試みが止まる 3 段 (URL 正規化 / セグメント検証 / ホスト固有文字の拒否) を
`protocol.ts` の docstring に表にした。**どの段も単独では足りない。**
