**Spec**: [spec.md](spec.md) | **Plan**: [plan.md](plan.md) | **Contracts**: [contracts/](contracts/)

本 feature が実際に動いていることを確認する手順。

## 前提

| 項目 | 要件 |
|---|---|
| OS | Windows 11 |
| WSL | WSL2 が有効。ディストロが **1 つ以上実行中、1 つ以上停止中** |
| Node | Active LTS (ビルドツール用) |
| pnpm | `pnpm-workspace.yaml` の `nodeLinker: hoisted` は配置済み |

WSL 非搭載ホストは実機で用意しない。SC-015 はプロセス起動レイヤを差し替えた
ユニットテストと renderer 単体テストで代替する。

```powershell
wsl -l -v      # 検証前のホスト状態を控える (SC-005 の判定に使う)
```

## セットアップ

```powershell
pnpm install
pnpm dev
```

install が `ERR_PNPM_IGNORED_BUILDS` で落ちる場合は `pnpm-workspace.yaml` の
`allowBuilds` を確認する (AD-023 の検証済み事実)。

### SC-004 は**温まった dev サーバ**で計測する

**依存を変えた直後の初回起動で計測してはならない。**
Vite が `Re-optimizing dependencies because lockfile has changed` を出しながら
依存の再最適化を走らせており、これが CPU と I/O を食う。

実測 (2026-09-15。同一ホスト、同一コード):

| 計測点 | 再最適化と同時 | 温まった 2 回目 | 予算 |
|---|---|---|---|
| `list-runtimes` | 3,106 ms (**OVER**) | 1,730 ms (ok) | 3,000 ms |
| `probe-batch` | 8,977 ms (**OVER**) | 3,667 ms (ok) | 4,000 ms |

**同じコードで合否が反転する。** 初回の値はアプリの性質ではなくビルドツールの
負荷を測っている。`pnpm dev` を一度終了させ、**2 回目の起動で計測する。**

計測点のうち **`probe-batch-verify` / `probe-batch-run` / `probe-one` /
`refresh-runtimes` / `list-folders` は SC-004 が予算を定めていない**ため、
経過時間だけが出て合否は出ない。内訳を見るためにある。

1. アプリを起動しランタイム一覧を開く

| 確認 | 期待 | SC |
|---|---|---|
| 一覧の内容 | `Win32Runtime` 1 件 + `wsl -l -v` のディストロと 1 対 1 | SC-002 |
| 提示までの時間 | 開発ビルドのログで一覧描画が **3000ms 未満**。目視で判定しない。**温まった dev サーバで計測する** (上記) | SC-004 |
| 判定バッチ | 同ログで**`probe-batch` が 4000ms 未満**。内訳 (`-verify` / `-run`) には予算が無い | SC-004 |
| `Win32Runtime` | sandbox なし / 無人実行「不可」 | SC-003 |
| 実行中 WSL2 | 判定完了後に sandbox の有無が示され、**seccomp が「未判定」と区別可能に示される**。不足依存があれば名前と**導入手順への導線**が出る (コマンド文字列が UI に埋め込まれていないこと) | SC-003 |
| 判定中 | 「判定中」と示され、無人実行は不可として扱われる | SC-003 |
| **判定失敗** | **「判定中」と区別して示され、再検出の導線が出る** | SC-003 |
| **列挙不能** | 文字種制約を満たさない名前のディストロが、**理由つきで一覧に現れる** (黙って落ちない) | SC-002 |
| 停止中ディストロ | 一覧に出るが未判定 | SC-002 |
| ディストロ名 | 文字化けなし。**空白を含む名前が切れない**。`Ubuntu-26.04` のような名前でバージョンを誤読しない | SC-011 |

2. 手動で AD-015 §8 の判定を実行し、表明値と突き合わせる (SC-003)

3. **停止中ディストロが起動されていないことを 2 通りで確認する**

```powershell
wsl -l -v      # 検証前と同じであること
```

開発者コンソールから停止中ディストロの識別子で直接叩き、いずれも拒否されること。
叩いたあとも `wsl -l -v` が変わらないこと (SC-005)。

4. 一覧を閉じて開き直す → ログの再表示時間が **100ms 未満** (SC-004)
5. 「再検出」を実行する → 結果が更新される。
   **判定済みディストロの再判定中に「可」の表示が残らない** (SC-003)

## V-2: 所在を選んでフォルダを登録する (US-2)

1. 登録フォルダ 0 件でフォルダ管理を開く → **空状態の導線**が出る
2. 所在「Windows」を選び、**日本語と空白を含む**フォルダを登録する (ネイティブピッカー)
3. 所在に実行中の WSL ディストロを選び、`/home/<user>/...` 配下を登録する
4. **フォルダブラウザで 3 階層以上移動する** → ログで階層移動が **300ms 未満** (SC-004)
5. 同じフォルダを再登録しようとする → 重複登録されず、**既存エントリが選択状態になる** (SC-013)
6. 読み取り権限のないディレクトリを辿る → 日本語でエラーが出て落ちない
7. 所在に**停止中**のディストロを選ぶ → 起動と再検出の導線が出る。
   **`wsl -l -v` で起動していないこと** (SC-005)
8. アプリ外でそのディストロを起動し「再検出」→ フォルダ選択が開ける
9. **フォルダブラウザを開いたまま 30 秒以上放置し、別窓でそのディストロを停止してから
   階層移動する** → セッション期限切れとして扱われ、**`wsl -l -v` が変化しない**。
   その後**同じ位置から登録を続行できる** (ルートに戻されない) (SC-005 / SC-004)
10. **有効期間内 (30 秒以内) に別窓でディストロを停止してから階層移動する** →
    挙動を記録する。**ここは残余として受け入れている区間**であり、
    起動が起きても SC-005 の不合格としない (data-model §5)
11. 登録した日本語フォルダ名が**一覧でそのまま表示される** (SC-011)
12. アプリを再起動 → 登録内容がすべて復元される (SC-013)
13. **アプリをもう一度起動** → 既存ウィンドウに合流し、**永続化ファイルの更新時刻が変わらない** (SC-014)
14. 登録済み Windows フォルダをエクスプローラで削除 / リネーム →
    一覧で**到達不可**として区別され、**登録解除の導線が出る**
15. 到達不可エントリを登録解除 → 一覧から消える (SC-013)。
    **到達可能なエントリも同じ操作で解除できる** (越境案内の手順が実行可能であること)
16. 所在 WSL のフォルダを残したままそのディストロを停止 → 一覧で
    **「一時的に解決不能」として到達不可と区別**され、起動と再検出の導線が出る。
    **登録解除は勧められないが、解除操作自体は選べる**。
    **この間 `wsl -l -v` が変化しないこと** (一覧表示が所在ディストロを起動しない。SC-005)
17. 永続化ファイルを手で壊す (JSON 破損 / スキーマ版の書き換え /
    **所在の種別は合っているがディストロ名が違う**) → 起動でき、
    **復元できなかった件数と理由が画面上に出て**、退避ファイルが生成される (SC-013)

## トラブルシューティング

| 症状 | 原因 |
|---|---|
| ディストロ名が 1 文字おきに見える | UTF-8 出力を要求していない |
| ディストロ名が一覧と突き合わない | 末尾の復帰文字が残っている |
| 空白を含むディストロ名が切れる | 詳細列挙の列を空白区切りでトークン化している |
| バージョンが名前中の数字になる | 「行内の最初の数値」を採っている |
| 判定の出力が一部欠ける | スクリプトを引数で渡し、バックスラッシュが消えた |
| 一覧の提示が十数秒かかる | `wsl.exe` をループ内で呼んでいる |
| フォルダブラウズが階層ごとに待たされる | 階層移動のたびに実行状態を確認している |
| 停止していたディストロが起動している | 実行状態の確認を経ずにコマンドを発行した |
| 全 Windows フォルダが変換不能になる | マウント情報をファイルシステム種別で絞っている |
| 必須依存があるのに sandbox が無効 / その逆 | 解決パスが Windows マウント配下かの判定が特定のパスを決め打ちしている |
| `/mnt/cdrom` が `C:\drom` になる | 接頭辞照合がセグメント境界を見ていない |
| 停止中ディストロに「起動せよ」と言われ、起動すると消える | 実行状態を到達可否より先に判定している |
| 起動直後に組み合わせが選べない / 理由も出ない | 「実行中だが判定未完了」が判定表に無い |
| 別ディストロのフォルダが開けてしまう | UNC 名前空間をディストロ粒度で分けていない |
| 停止していたディストロが UNC アクセスで起動する | 確認済みの値を別ディストロに流用している |
| 一覧が毎日「登録解除」を勧めてくる | 一覧側の到達可能性を 2 値にしている |
| 越境案内どおりに旧エントリを解除できない | 解除**操作**まで到達不可に限定している |
| 起動して再検出したら選択肢が消え、理由も出ない | `blocked` → `unreachable` の確定を黙って処理している |
| `Win32Runtime` が永久に「判定中」と表示される | 固定値経路で `probedAt` を設定していない |
| 越境の解決結果が変換不能になる | 境界の名前空間規則を `runtimePath` にも当てている |
| WSL ブラウズが常に失敗する | `wsl:<D>` と `unc:<D>` を「種別まで完全一致」で比較している |
| `pnpm dev` で IPC がすべて無反応 | 送信元の許可 origin に dev サーバを含めていない |
| アプリ起動だけで停止中ディストロが起動する | 一覧の実在確認を確認済みの値なしで発行している |
| WSL1 があると Windows フォルダが全部到達不可になる | 第 2 段を `probeState` で分岐している |
| WSL フォルダが 1 件も登録できない | `unc:<D>` のまま IPC 境界を越えている |
