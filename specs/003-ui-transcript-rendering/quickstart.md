# Quickstart: transcript の基本表示 (R-3)

実機での確認手順。**SC-010 (見栄えの一次判断) はここでしか測れない**。
R-2 の SH-089 (quickstart 実機再実行) を R-3 が継承する (roadmap R-3 申し送り #7)。
実機操作を伴うため **done の必須完了項目にはしない**が、持ち主は R-3 である。

## 前提

- 開発ホスト (Windows 11 + WSL2)。WSL ディストロ内に履歴のあるセッションがあること
- R-2 のセッション一覧が動作すること (選択できる)
- 温まった dev サーバで 2 回目以降の値を採る (R-2 SH-074 と同じ)

## V-1 過去 transcript を実データで読む (US-1 / SC-001)

1. セッション一覧から履歴のあるセッションを 1 つ選ぶ
2. transcript が開き、user / assistant のメッセージが**記録順**に並ぶ
3. markdown が整形され、コードがハイライトされることを確認する
4. 同じ `sessionId` に SDK を直接呼んだ結果と、件数・順序・役割が一致することを確認する

## V-2 未定義 tool の fallback (US-1 AC-2 / SC-005)

1. tool 実行を含むセッションを選ぶ
2. 専用表示を持たない tool が **fallback 表示** (tool 名・入力・結果) で欠落なく現れることを確認する

## V-3 WSL 内セッションを起動せず読む (US-1 AC-3)

1. 実行中の WSL ディストロ内のセッションを選ぶ
2. **ディストロを起動せず** Windows 側から読み込まれることを確認する
   (R-2 で踏めなかった V-3 出自の確認をここで transcript 文脈で行う)

## V-4 越境 `/mnt/c` のセッション (R-2 SH-089 継承)

1. あるディストロから `/mnt/c/...` として使ったセッションの transcript を開く
2. 本文が読め、レイアウトが崩れないことを確認する (R-2 で該当 `cwd` が 0 件で踏めなかった項目)

## V-5 数千メッセージのスクロール (US-2 / SC-002 / SC-003)

1. 3,000 件超のメッセージを持つ transcript (実データまたは大量 fixture) を開く
2. スクロールが滑らかで、位置飛びが起きないことを確認する
3. 開発ツールで同時マウント DOM ノード数が総件数に比例しないことを確認する
4. 高さの異なるメッセージ (コードブロック・長い tool 出力) を通過しても測定でジャンプしないことを確認する
5. 最下部追従と「最下部へ」操作が機能することを確認する

## V-6 逐次伸長でスクロールが奪われない (US-3 / SC-004)

1. 開発用に本文を段階的に伸ばす経路 (fixture / store 更新) を使う
2. テキストが伸びても表示が崩れず、見ている位置が奪われないことを確認する

## V-7 日本語の健全性 (SC-006)

1. 日本語・全角混在・絵文字・コードを含むセッションを開く
2. フォント崩れ・全角レイアウト崩れが無いことを確認する

## V-8 空・失敗状態 (US-1 AC-4 / data-model §8)

1. メッセージ 0 件のセッション → 空状態 (捏造応答が出ないこと)
2. 停止中の所在のセッション → 理由つきの失敗表示 (R-2 で踏めなかった V-8 空状態を継承)
3. composer が**描画されるが入力できない**こと (送信経路が閉じたまま。FR-013 の実機確認)

## V-9 見栄えの一次判断 (SC-010 / roadmap / charter)

**SC-010 rubric — 各観点を OK/NG で `quickstart-results.md` に記録する** (判定表の記録が done の必須項目。
実機実施自体は人間 deferred だが、記録の有無は SH-067 が機械確認する)。

| b | 日本語全角混在行で行送り・折返しが破綻しない | | |
