# Quickstart: 日本語 composer (X-2)

実機での検証手順。**人間 deferred の視覚/IME 目視**を含む (自動化できない範囲。AD-037 代償節)。
判定結果は `quickstart-results.md` に記録する (R-3 rubric と同じ扱い。実機操作は人間 deferred だが記録は done 必須)。

## 前提

- X-1 の quickstart 前提を満たす (実行中の WSL ディストロ + 登録フォルダ + 有効 composer で live セッションを起動できる)
- Windows / Electron 実機 (Chromium 単一エンジン。AD-001) + OS の日本語 IME (MS-IME 等)

## 検証項目

### V-1 IME 変換確定の Enter が送信にならない (人間 deferred)

1. live composer に日本語を入力し、変換候補が出ている状態で **Enter を押す**
2. **期待**: 送信されず、変換が確定するだけ
3. 確定後にもう一度 **Enter** を押す → **期待**: 送信される
4. **記録**: 確定 Enter の keydown が `isComposing === true` で来て誤送信しないこと (electron 39.8.10 実機タイミングの目視。
   E2E は CDP 注入で担保するが、実機 IME 操作は自動化不可)

### V-2 全角混在でレイアウトが崩れない / 行送りの見え (人間 deferred)

1. 全角・半角・絵文字混在の長文 (複数行になる長さ) を composer に入力する
2. **期待**: 水平あふれ・桁ずれ・要素崩れが無く、textarea が行数に応じて伸びる
3. **記録**: 全角の行送り (line-height) と折返しの**見え**が許容範囲か (基準画像の初回承認)。日本語スクリーンショット比較の
   基準画像はこの判断に基づいて commit する (R-3 rubric-b と同じ扱い)

### V-3 実行中に次の入力を積める (message queue)

1. プロンプトを送り、応答生成中 (`running`) に**次の入力を打って送信**する
2. **期待**: message queue に積まれ、積まれていることが見える (新規起動を伴わない)
3. 現ターンが完了する → **期待**: 積んだ入力が同一セッションの次ターンとして送られる

### V-4 中断でキューが取り消される

1. キューに項目がある状態で**中断**する
2. **期待**: 何が残り (`still_queued`) 何が消えたか (`cancelled`) が提示される

### V-5 下書きが画面再構成をまたいで復元される

1. composer に未送信の下書きを入力中、セッションを失敗 (error) / 強制終了 (killed) 等で**画面状態を遷移**させる
   (Thread が再構成される)
2. **期待**: 打ちかけの下書きが消えずに残る
3. 下書きを送信 / 明示クリアする → **期待**: 下書きが空になる

## CI 検証 (自動)

- `verify` workflow の **IME E2E ジョブ**が緑 (確定 Enter 非送信の回帰固定)
- `verify` workflow の **日本語スクリーンショット比較ジョブ**が緑 (基準画像一致)
- 既存ガードを殺す変更を入れると IME E2E が落ちる (回帰検出。SC-001/006)
