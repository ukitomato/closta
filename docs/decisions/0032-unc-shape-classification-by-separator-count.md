# AD-032: UNC の判定を綴りの列挙から先頭区切りの本数へ

## Context

[AD-029](0029-session-cwd-origin-classification.md) は作業ディレクトリの出自判定を定め、
その §1 の判定表は UNC を **綴りの一覧**で識別する形だった
(「3 綴りをすべて受理」)。§3 は「R-1 のパス API 側に解析関数を **1 つ**追加する」と書いた。

R-2 の実装は pr-gate を 4 round 通るあいだに、この判定を **4 回**書き換えた。
毎 round、表に無い綴りが 1 つ以上見つかった。

| Round | 指摘された綴り | 修正が壊したもの |
|---|---|---|
| 1 | 先頭ハイフン / フォワードスラッシュ | — |
| 2 | デバイス名前空間 (`\\?\UNC\`) | FR-017 — `parseWslUncPath` への接続漏れ |
| 3 | 区切りの重なり (`\\\wsl.localhost\`) | 正当な POSIX 表示 (一括ガードの巻き込み) |
| 4 | 先頭の空白 1 文字 (S4-001) / ディストロ名の大小 (PB4-001) | — |

**表に行を足す形である限り、表に無い綴りは守れない。** 4 round の指摘は
個別の綴り漏れではなく、判定モデルそのものの帰結だった。

[AD-031](0031-adr-in-place-corrections-and-principle-ix-scope.md) が定めた境目に従えば、
これは「事実誤認の訂正」ではなく **決定の変更**であり、後続 ADR を要する。
本 ADR がそれである。

## Decision

### 1. UNC 形の識別を「先頭の区切りの本数」で行う

`classifyRawPath(raw): RawPathShape` を唯一の入口とし、`trim()` した後の
**先頭に連続する区切り (`/` と `\` の両方) の本数**で形を決める。

| 先頭区切り | 形 |
|---|---|
| 0 本 | ドライブレターなら `host`、そうでなければ `other` |
| 1 本 | `posix` |
| 2 本以上 | 実測された 2 綴りを解析できれば `wsl-unc`、できなければ `opaque-unc` |

**2 本以上を「UNC」と呼ばない。** `\\?\C:\dev` / `\\.\C:\dev` は Win32 の
デバイス名前空間接頭辞であってサーバ名も共有名も含まず、FR-042 の対象ではない
(実機で解決することを platform-boundary が確認済み)。
対象外であることと構造が読めることは別なので、**解析できない形は一律で表示値を持たせない**。

### 2. 実測されていない綴りに分岐を作らない

解析するのは `UNC_PREFIX` (`\\wsl.localhost\`) と `UNC_LEGACY_PREFIX` (`\\wsl$\`) だけとする。
research R-02 (ホスト既定 43 件) で観測された綴りはこの 2 つであり、
デバイス名前空間や `GLOBALROOT` 経由の綴りは**誰も観測していない**。

`opaque-unc` を新設し、解析できない UNC 形は
`unknown-location` (**表示値なし**) へ落とす。構造が分からない値から
「安全な残余」を切り出すのは、結局また推測である
— `\\?\UNC\wsl.localhost\Ubuntu\home` に「2 セグメント落とす」規則を当てると
**共有名 `wsl.localhost` が残る**。

### 3. 表示値は判定が見た値と同じものを使う

`RawPathShape` の `posix` / `other` は**自分の表示値を運ぶ**。
呼び出し側は `classifyRawPath` を呼んだ後に生値を参照しない。

参照した結果が S4-001 だった — 空判定にだけ `trim()` を使い、判定には生値を渡していたため、
**先頭の空白 1 つで生の UNC が境界に出た**。形の性質に置き換えたのに、
その性質を評価する位置が 1 文字ずれていた。

加えて、形が分からない (`other`) のに**区切りの連続を含む値には表示値を持たせない**。
落とす文字を数え上げる形にすると、`trim()` にも `hasControlCharacter` にも掛からない
書式文字 (`U+200B` / `U+2066`) でまた破れる。

### 4. ディストロ名の照合は大小を無視し、識別子には検出済みの綴りを使う

**Windows は共有名を大小無視で解決する** (実機で確認)。
完全一致で照合すると、実行中で検出済みのディストロが「未検出の所在」に落ち、
所在が決まらないので登録導線も成立しない (FR-017 / US-1 AC-5)。

`canonicalDistroName(raw, detected)` を `runtime` 側に置き、
**検出済み集合が持っていた綴り**を返す。名前空間識別子はその綴りで組む
— 入力の綴りをそのまま使うと `unc:ubuntu` と `unc:Ubuntu` が別の名前空間になり、
同じディストロが 2 つに割れる。

**`isSameDistro` は変えない。** あちらが比較するのはどちらも検出由来の識別子 2 つであり、
本関数を通せば綴りは揃う。`infra/fs` の入口の判定を緩めずに済むので、
**照合を緩めるのはこの 1 関数の中だけ**に閉じる。

### 5. `undetected-distro` の表示値にディストロ名を含める

FR-042 が禁じているのは **UNC の綴り**であってディストロ名ではない
— `EnumerationOutcomeDTO.location` は既にディストロ名を平文で運んでいる。

`undetected-distro` を `unknown-location` から分けた唯一の意味は
「**どのディストロかは分かるが、そのディストロが今ない**」である。
名前が出ないと利用者は「改名前の名前に戻す」「再導入する」を決められず、
差が訳語だけになる。契約 `contracts/ipc-session-list.md` は当初から
「ディストロ名 + 変換後の POSIX パス」と定めており、本決定で実装がそれに揃った。

### 6. 判定表の正本を 1 箇所にする

正本は `src/domain/session/cwd-origin.ts` の `classifyCwd` docstring の表とする。
`data-model.md §2` とテストの `describe` 名は**参照形**にし、写しを置かない。

Round 1〜4 のあいだ同じ表が 3 箇所にあり、実装が変わるたびに別々にずれた。
Round 4 の時点で行数が 8 / 7 / 7 と食い違い、**同じ「#4」が 3 つの別のものを指していた**。

## Consequences

### 良くなること

- 綴りが増えても判定は破れない。形の性質は綴りに依存しない
- `path-api.ts` の公開面が「形の判定」と「実測綴りの解析」の 2 つに整理された
- テストが綴りのケース表から**組み合わせ生成した全入力に対する性質**になった
  (1,250 通り × 接頭 9 種)。綴りを 1 つ足すのは配列に 1 要素足すことである

### 代償

- **実測されていない綴りは所在を失う。** `\\?\UNC\wsl.localhost\Ubuntu\home` は
  実機で解決するのに `unknown-location` になり、表示値も持たない。
  行は残るので FR-004 / SC-006 は守られるが、その行について作業ディレクトリは何も表示されない
- `\\?\C:\dev` は UNC ではないのに表示値を落とす。安全側だが、塞ぐ必要のない形である

### 申し送り

- [ ] デバイス名前空間の綴り (`\\?\UNC\` / `\\.\UNC\` / `\\?\C:\`) を解析するかを再評価する。
      実機で解決することは確認済みで、判断を保留しているのは**実測で 0 件**だからである。
      持ち主: `docs/roadmap.md` の R-3 行
- [x] `opaque-unc` の行が「値はあるが読めない」という第 3 の状態であることを
      spec の Edge Cases に記録する (PO4-006)。**pr-gate Round 5 で実施** (spec.md Edge Cases / Key Entities)

## Confirmation

判定モデルの変更は「書いた」ことではなく「**変異が発火した**」ことで確認する (AD-027)。
6 つの変異を入れて実行し、すべてが既存のテストを落とすことを確認した。

| 変異 | 発火したテスト |
|---|---|
| A. `classifyRawPath` の `trim()` を外す | 「空白だけの接頭は正しい判定を取り戻す」 |
| B. `other` の区切り連続ガードを外す | 性質テスト 2 件 + 「落とせない書式文字が付いた UNC は表示値を持たない」 |
| C. ディストロ名の照合を完全一致に戻す | 「大小だけが違う綴りは未検出にしない」 |
| D. `undetected-distro` の表示からディストロ名を落とす | 「表示はディストロ名 + POSIX パスである」他 1 件 |
| E. `case 'other'` で `shape.value` でなく生値を出す | 「表示値は判定が見た値と同じである」 |
| F. 名前空間を入力の綴りで組む | 「大小だけが違う綴りは未検出にしない」 |

変異 E は最初**発火しなかった**。生値と表示値が異なる入力がテストに無かったためで、
先頭に空白を付けた相対パスの断言を 1 件足して発火させた。
